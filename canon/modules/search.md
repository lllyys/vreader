# Module — search

## Purpose

In-book full-text search: a SQLite FTS5 index built per book (persisted on disk), queried from a debounced search sheet inside the reader, with every hit resolved to a `Locator` so a tap navigates the reader to the match. The same persisted index also powers library-wide search — but only through the AI agentic tools (`search_current_book` / `search_other_books`, feature #91); the library UI's own search bar (`LibrarySearchBar`, feature #60 WI-9) filters title/author metadata only, never book content. CJK text is searchable via per-ideograph segmentation.

## Key files and types

Services (`vreader/Services/Search/`):
- `SearchService.swift` — `protocol SearchProviding: Sendable` (`indexBook`, `search(query:bookFingerprint:page:pageSize:)`, `removeIndex`, `isIndexed`) and the production `final class SearchService: SearchProviding, @unchecked Sendable` (state behind `OSAllocatedUnfairLock`). Produces `SearchResult` (`id` = `"{fingerprintKey}:{sourceUnitId}:{matchStartOffsetUTF16}"`, snippet, `locator`, `sourceContext`) paged as `SearchResultPage`. `restoreSegmentOffsets` (bug #61) and `markPersistentlyIndexed` (bug #264) reconcile in-memory state with the persisted index. `formatSourceContext` renders `sourceUnitId` → "chapter name" / "Page N" / "Section N" (1-indexed display).
- `SearchIndexStore.swift` — FTS5 wrapper owning the schema: virtual table `search_index` (`tokenize='unicode61 remove_diacritics 2'`), `token_spans` (per-token UTF-16 offsets + `idx_spans_lookup` index), `source_texts` (originals for per-occurrence snippets, bug #28), `search_metadata` (`indexed_at`, `content_hash`, `segment_base_offsets` JSON, `decode_version` — `currentDecodeVersion = "2"`, bug #99 cause #2). `indexBook` deletes-then-inserts in one transaction (ROLLBACK on error); `requiresReindex` flags rows built by an older decode pipeline. `SearchHit` carries `sourceUnitId` + match UTF-16 offsets. `SearchIndexError` covers open/query/index failures.
- `SearchIndexCore.swift` — minimal SQLite3 wrapper (`@unchecked Sendable`, `OSAllocatedUnfairLock`); file-backed init runs `PRAGMA integrity_check(1)` and on corruption deletes the DB plus `-wal`/`-shm`/`-journal` companions and recreates fresh.
- `SearchQueryExecutor.swift` — query build + execution: FTS MATCH `content : <escaped>` filtered by `fingerprint_key`, then all per-unit occurrences via token spans (multi-token queries require ORDERED spans with gaps of at most `maxTokenGap = 50` UTF-16 units between successive query tokens — the spans need not be consecutive; unrelated intervening tokens between two matched query tokens are allowed as long as the gap stays within bound); `extractSnippet` returns `"...before<b>match</b>after..."` with ±40 context chars.
- `SearchTextNormalizer.swift` — `normalize` = NFKC (`precomposedStringWithCompatibilityMapping`, folds full-width→half-width, ﬁ→fi) + `.caseInsensitive` + `.diacriticInsensitive` folding (locale nil); `segmentCJK` space-separates CJK ideographs/kana/Hangul (ranges incl. U+4E00–U+9FFF, Ext A/B+, compatibility, Hangul syllables/jamo, katakana incl. halfwidth, hiragana) so FTS5 unicode61 tokenizes each character — without it "关于编程" is one token and "编程" finds nothing.
- `SearchTokenizer.swift` — `tokenize` emits `IndexedToken` (normalized form + UTF-16 start/end; Character-level iteration handles surrogate pairs; CJK chars become individual tokens); `escapeFTS5Query` double-quotes every whitespace-separated token (`""` escaping) — so boolean operators and quoted phrases are deliberately NOT supported.
- `SearchTextExtractor.swift` — `struct TextUnit { sourceUnitId, text }` + `protocol SearchTextExtractor`. `sourceUnitId` grammar: `"epub:<href>"`, `"pdf:page:<N>"`, `"txt:segment:<N>"`, `"md:segment:<N>"` (echoed — minus the MD case — in `vreader/Models/TokenSpan.swift`).
- Extractors: `EPUBTextExtractor.swift` (spine iteration via `EPUBParserProtocol`, regex `stripHTML` + entity decoding; skips empty/broken spine items; also hosts `stripHTMLPreservingBlocks` for feature #56 bilingual segmentation — a different boundary contract), `PDFTextExtractor.swift` (PDFKit, one unit per page, empty pages kept so page indices align), `TXTTextExtractor.swift` (paragraph segments split on `\n\n`, falling back to `\n` when ≤1 non-empty segment and >500 chars; segment text NOT trimmed to preserve offset alignment; decodes via `TXTService.decodeForDisplayAndSearch` so index offsets match display — bug #99 cause #2; returns `TXTExtractionResult` with `segmentBaseOffsets`), `MDTextExtractor.swift` (`stripMarkdown` then the same segmentation; `MDExtractionResult`).
- `SearchHitToLocatorResolver.swift` — hit → `Locator`: EPUB → `LocatorFactory.epub(href:progression: 0)` (search doesn't know within-chapter position) with `textQuote` from `cleanSnippetForTextQuote` (bug #182 / GH #621: strips the `<b>…</b>`/ellipsis display chrome so `window.find()`/PDFKit `findString` can match; empty `<b></b>` → nil); PDF → `LocatorFactory.pdf(page:)`; TXT/MD → global char range = segment base offset + hit offset (nil if `segmentBaseOffsets` is missing — the hit is dropped by `compactMap`).
- `BackgroundIndexingCoordinator.swift` — `actor` implementing `IndexingCoordinating` (`enqueueIndexing`/`cancelIndexing`/`indexingStatus` with `IndexingStatus` .notIndexed/.indexing/.indexed/.failed); serial in-actor queue drained by a `Task.detached(priority: .background)` with a STRONG `self` capture (bug #187 / GH #653 — weak capture let the actor deallocate before the queue drained, silently killing indexing).
- `PersistentSearchIndex.swift` — the Services-layer source of truth for the on-disk index: `Application Support/SearchIndex/search.sqlite3`; `makeStore()` (in-memory fallback on failure) vs `makeStoreStrict()` (throws — feature #91's agentic tools must hit the SAME persisted index, never a silently-empty in-memory one).

ViewModel + UI:
- `vreader/ViewModels/SearchViewModel.swift` — `@Observable @MainActor`; 300 ms debounce, page size 20, cancels superseded searches, discards results if the query changed mid-flight, `loadMore()` rolls the page back on failure, `retriggerIfNeeded()` re-runs after indexing completes. Every query change posts `.searchHighlightClear`.
- `vreader/Views/Reader/ReaderSearchCoordinator.swift` — `@Observable @MainActor` owner of the pipeline: `prepareEagerly` on reader open (bug #79) with a single-flight `prepareTask`; the cold SQLite open runs on a detached task (`nonisolated` `makePersistentStore`, bug #89 — never stalls reader open); `setup(fingerprint:fileURL:format:)` on first sheet open decides skip-vs-reindex (decode-version force-reindex for TXT; TXT/MD persisted rows with no restorable offsets are stale → dropped + re-indexed, while nil offsets are NORMAL for EPUB/PDF → `markPersistentlyIndexed`, both bug #264) and enqueues extraction via `nonisolated static enqueueBookIndexing` (bug #183 / GH #623 — synchronous file I/O off the MainActor; pre-fix, first search-panel open of a 5MB+ CJK TXT froze the UI). `formatRequiresSegmentOffsets` = txt/md only. `wipeSearchIndex(at:)` backs the DEBUG `vreader-debug://reset` clean slate (bug #264).
- `vreader/Views/Search/` — `SearchView.swift` (feature #63 re-skin; pure `contentState` resolver: loading/noResults/prompt/results, whitespace-only query → prompt; `.accessibilityElement(children: .contain)` + `searchView` id, bug #223 / GH #891), `SearchBar.swift` (custom in-sheet bar, `@FocusState` auto-focus, 44 pt touch targets, bug #224), `SearchResultGrouping.swift` (pure first-encountered-order grouping by `sourceContext`; empty context → "Location"), `SearchResultsGroupedList.swift` ("{N} matches in {M} sections" count line + grouped cards), `SearchResultRow.swift` (serif snippet via `HighlightedSnippet.highlight`), `SearchStateViews.swift` (`SearchNoResultsView` / `SearchPromptView`; full-height fill, bug #319; copy deliberately omits phrase/boolean claims), `SearchViewActions.swift` (testable `onCancel`/`onNavigate` bundle).

Agentic/library lane (`vreader/Services/AI/Tools/`, feature #91): `SearchCurrentBookTool.swift` (`search_current_book`, read-only over `SearchProviding`, page 0 only, byte-clamped output), `SearchOtherBooksTool.swift` (`search_other_books`, whole library minus the open book), `LibraryBookSearchGate.swift` (the pure safety gate: `LibrarySearchExclusion` .notIndexed/.requiresReindex/.staleOffsets — mirrors `ReaderSearchCoordinator.setup`'s guard set so TXT/MD hits never mis-resolve or silently vanish), `LibrarySearchBackendAdapter.swift` (production backend over the `SearchIndexReading`/`IndexedBookSearching` seams; `SearchIndexStore`/`SearchService` conform).

## Data flow

Index: reader open → `prepareEagerly` (store + service + VM, off-main cold open) → first search-sheet open → `setup` → format extractor → `[TextUnit]` (+ `segmentBaseOffsets` for TXT/MD) → `BackgroundIndexingCoordinator.enqueueIndexing` (returns once the job is SCHEDULED on the actor's queue, not once it has run) → `ReaderSearchCoordinator` immediately fires `UPDATE search_metadata SET segment_base_offsets` for TXT/MD — racy, since the detached drain task may not have called `SearchService.indexBook` yet to insert the `search_metadata` row, so the UPDATE can affect zero rows → `SearchService.indexBook` → `SearchIndexStore` (normalize + segmentCJK → FTS5; raw text → `source_texts`; tokens → `token_spans`). Query: typed query → 300 ms debounce → `SearchService.search` (fetches `offset + pageSize + 1` hits for `hasMore`) → `SearchQueryExecutor` → hits → `SearchHitToLocatorResolver` (nil locators dropped) → grouped list. Navigation: result tap → `SearchViewActions.navigate` → `ReaderContainerView+Sheets.swift` `searchSheet.onNavigate` posts `.readerNavigateToLocator` (object = `Locator`) and closes the sheet; format containers navigate and paint a temporary yellow highlight that auto-clears (~3 s, feature #2); `.searchHighlightClear` (posted by `SearchViewModel` on query change) dismisses it. CU-free verification drives all of this via `vreader-debug://search?query=…&index=N` (bug #238, `ReaderContainerView+DebugBridgeSearch.swift`). See [[Module — locator]], [[Architecture — notification bus]], [[Module — debug bridge]], [[Module — AI providers and tools]].

## Concurrency

`SearchIndexCore`/`SearchIndexStore`/`SearchService` are lock-guarded `@unchecked Sendable` classes callable from any thread; `BackgroundIndexingCoordinator` is an actor serializing FTS writes; `SearchViewModel` and `ReaderSearchCoordinator` are `@MainActor`, with the heavy pieces (`makePersistentStore`, `enqueueBookIndexing`) explicitly `nonisolated` so SQLite opens and file I/O never run on the MainActor.

## Edge cases and invariants

- Empty/whitespace query → empty result page / prompt state, no FTS query. `page`/`pageSize` clamped (`max(0,…)`/`max(1,…)`).
- Re-indexing a book replaces its rows atomically. `SearchIndexStore.indexBook` ALWAYS `INSERT OR REPLACE`s a `search_metadata` row, even when `textUnits` is empty; `SearchService.indexBook` compensates by only adding the fingerprint to its in-memory `indexedKeys` set when `textUnits` is non-empty. But on a later reopen, EPUB/PDF `setup` sees that persisted `search_metadata` row (nil segment offsets is the NORMAL EPUB/PDF state, per bug #264) and calls `markPersistentlyIndexed`, treating the empty index as validly persisted — a real bug: it can block a retry despite there being no searchable content.
- `hasMore` is recomputed after locator-resolution filtering (`hasMore && !results.isEmpty`).
- TXT/MD correctness depends on two alignment invariants: index offsets are computed over the SAME decoded string the display renders (`decodeForDisplayAndSearch` + `decode_version` reindex), and segment base offsets must be present — hence the bug #264 stale-row and feature #91 gate handling.
- Surrogate pairs: tokenizer iterates `Character`s and tracks `char.utf16.count`; snippet extraction converts via `String.Index(utf16Offset:in:)`.
- FTS5 injection is neutralized by `escapeFTS5Query` quoting every token; the trade-off (no operators/phrases) is documented in `SearchStateViews.swift` copy.
- Corrupt persistent DB self-heals (integrity check → delete → recreate); a failed file-backed open degrades to in-memory for the reader path only.
