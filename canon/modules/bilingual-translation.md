# Module — bilingual translation

## Purpose

Feature #56 ("bilingual reading", plan `dev-docs/plans/20260519-feature-56-bilingual-reading.md`, WI-1…WI-15): interlinear AI translation rendered beneath each source block across all five reader formats, backed by a persistent per-chapter translation cache, plus a "translate entire book" batch flow and a per-chapter re-translate with provider override.

## Key files and types

- `vreader/ViewModels/BilingualReadingViewModel.swift` + `+Prefetch.swift` — `@Observable @MainActor final class`; per-book state (`isEnabled`, `targetLanguage` default `"Chinese"`, `granularity` default `.paragraph`) persisted via `PerBookSettingsStore` (read-modify-write preserving typography fields); `translationsByUnit: [TranslationUnitID: [String]]` in-memory cache; `unavailableUnits` (offline silent-source-fallback, plan Decision 2); `needsSetupSheet` first-enable flag; `aiConfigured` via `BilingualAIReadiness.resolve()` (bug #301). Prefetch trigger `handlePositionChange(_ locator:)` dedupes by `lastTriggerUnit`, guards interleaving with `triggerRequestSeq`, discards stale results with a monotonic `epoch`, and prefetches current + next unit. `setInFlight(_:)` is the single funnel posting `.readerBilingualPrefetchDidChange` with the FULL in-flight set (feature #77 shimmer). Also `prefetchUnitIfNeeded` (feature #71 WI-7 off-screen sections), `retryUnit` (WI-13 PDF retry), `translateBlocksDirectly` (bug #268 count-divergence fallback), `applyReTranslateResult`.
- `vreader/Models/TranslationUnitID.swift` — `struct { kind: Kind; value: String }`, `storageKey = "<kind>:<value>"`; `Kind`: `epubHref`, `foliateHref`, `txtChapterIndex`, `mdChapterIndex`, `pdfPageRange`. The unit is the format's natural rendering segment, not the TOC chapter (Decision 2.7).
- Text providers (`ChapterTextProviding`, `vreader/Services/Reader/`): `EPUBChapterTextProvider`, `FoliateChapterTextProvider` (an `actor` over the `@MainActor` `FoliateSectionExtracting` facade implemented by `FoliateSpikeView.Coordinator` in `FoliateSpikeView+SectionExtracting.swift`; never caches `[]` — Gate-4 M1), `TXTChapterTextProvider`, `TXTLoaderBackedChapterTextProvider`, `MDChapterTextProvider`, `PDFChapterTextProvider`.
- `vreader/Services/AI/ChapterTranslationPrefetcher.swift` — `struct ChapterTranslationPrefetcher: ChapterPrefetching, Sendable`; disk-cache check BEFORE the provider gate (bug #306: cached chapters render with AI disabled/key-less), then snapshots the active profile and resolves config atomically (no provenance straddle); flags `acceptsCountMismatchedRows` (bug #343, legacy-EPUB/Readium only) and `supportsSentenceGranularity` (bug #344: only TXT/MD — DOM-enumerating formats force `.paragraph` via `effectiveGranularity(requested:supportsSentenceGranularity:)` and dim the Sentence control). Built by `EPUBReaderContainerView.makePrefetcher(bookFingerprintKey:textProvider:acceptsCountMismatchedRows:)`.
- `vreader/Services/AI/ChapterTranslationService.swift` — `actor`; pipeline: cache lookup → segment (`ChapterSegmenter`) → chunk (`ChapterTranslationChunker` + `TranslationChunkContract` strict JSON-array decode) → one `AIService` request per chunk via the `TranslationRequestSending` protocol → per-segment fallback on decode/count mismatch → recombine → cache write. `ChapterTranslationError`: `.offline` (genuine connectivity only — bug #333), `.timedOut`, `.providerFailed(String)`, `.cancelled`.
- `vreader/Services/ChapterTranslationStore.swift` — `actor`, app-scoped `.shared` configured from `VReaderApp.init()`; SwiftData `ChapterTranslation` `@Model` (derived data, excluded from backup); idempotent `upsert` by `lookupKey`; bug #342 lazily migrates old 5-field keys (with provider-profile UUID) to the canonical 4-field key (book|unit|lang|prompt) — profile is provenance, not identity. Prompt version pinned as `bilingualPromptVersion = "bilingual-v1"`.
- Pairing: `vreader/Views/Reader/Bilingual/BilingualPairing.swift` — `translationsByBid(blocks:translatedSegments:)` pairs by position ONLY when `blocks.count == segments.count`; a mismatch returns an empty map → source-only, never a wrong pairing (bugs #266, #334).

## Render lanes (one per engine)

None of `EPUBBilingualJS`, `FoliateBilingualJS`, `ReadiumBilingualCommander`, or `ReadiumBilingualEvalAdapter` conform to `WKScriptMessageHandler` themselves. `EPUBBilingualJS` and `FoliateBilingualJS` are pure JS-string generators (`enum`s of static builders); their output executes through the actual `WKScriptMessageHandler` conformers, `EPUBWebViewBridge.Coordinator` and `FoliateSpikeView.Coordinator` respectively ([[Module — EPUB reader]], [[Module — Foliate AZW3 reader]]). `ReadiumBilingualCommander` and `ReadiumBilingualEvalAdapter` are eval-channel command/adapter objects that run scripts through the Readium navigator's own `evaluateJavaScript` return-value surface — not a registered message handler at all (the navigator exposes no message channel to app code).

- **Legacy EPUB**: `EPUBBilingualOrchestrator` + `EPUBBilingualJS` (712 lines, self-contained IIFE against `document`) + `EPUBBilingualPipeline` (defines `BilingualBlock { bid, text, sectionIndex? }`); per-section block caches added by feature #71 WI-7 for continuous scroll (`EPUBReaderContainerView+ContinuousBilingual.swift`).
- **Readium EPUB**: `ReadiumBilingualCommander` (eval-channel — the navigator has no message channel, so the enumerate IIFE's RETURN value carries `[{bid,text}]`; href normalization to OPF-relative spine entries via `ReadiumDecorationHighlightAdapter.resolveHref`), `ReadiumBilingualEvalAdapter`, `ReadiumBilingualChapterTracker`, `ReadiumEPUBHost+Bilingual.swift`.
- **Foliate (AZW3/MOBI)**: `FoliateBilingualOrchestrator` (`blocksBySection: [Int: [BilingualBlock]]`, `-1` bucket for untagged/legacy payloads; `enumerateJS`/`buildInjectJS`/`clearJS`/`buildLoadingJS`/`clearLoadingJS`, all section-scoped — Gate-4 H2) + `FoliateBilingualJS` (constants `data-vreader-bid`, `data-vreader-decoration`, `vreader-bilingual`, `vreader-bilingual-loading`, `vreader-shimmer-bar` — byte-identical to the EPUB constants) + `FoliateBilingualPipeline` (tolerant parser, wrapped `{requestedSectionIndex, blocks}` + legacy bare-array shapes). Host wiring lives in [[Module — Foliate AZW3 reader]]'s `FoliateBilingualContainerView`; the DOM walk runs in `foliate-host.js` `readerAPI.bilingual*` because Foliate sections live inside iframes/shadow roots. Bug #334 made enumerate and translate-source walk the SAME `bilingualLeafBlockElements` selector so counts match.
- **TXT/MD (native, no JS)**: `BilingualDisplayPipeline` (`@MainActor enum`; off-path returns source + identity map, byte-identical to pre-bilingual) → `BilingualTextRenderer` / `BilingualAttributedStringComposer`; `BilingualOffsetRouter` + `BilingualTXTBridgeDelegateAdapter` keep locator offsets correct ([[Module — TXT reader]], [[Module — text mapping]]).
- **PDF**: `PDFBilingualPanel` / `PDFBilingualPanelState` / `PDFBilingualPanelBodies` — a below-page panel (WI-13) with offline retry CTA.

## Translate-entire-book and re-translate

- `vreader/Services/AI/BookTranslationCoordinator.swift` — `actor`, `.shared`, one job per book (`runningJobs: [String: Task]`); pinned `ResolvedAIProviderConfig` (a mid-run profile swap can't strand the job); monotonic `BookTranslationProgress` snapshots over `AsyncStream` + `.readerBookTranslationProgressDidChange`; `cancelAndPurge` for book delete; feature #98 adds background-task grace + `InterruptedTranslationJobStore` resume, gated through the `BackgroundTaskRequesting` protocol seam (`vreader/Services/BackgroundExecutionToken.swift:31,40`; `UIApplication` conforms in production, tests inject a recorder). UI: `TranslateBookActionRow` (Book Details Actions card, design `vreader-translate-book.jsx`), `TranslateStatusSheet`, `ReaderTranslateBanner`, `TranslateBookConfirmAlert`, `TranslateCancelAlert`. Entry point requires a published provider: hosts post `.readerBookTranslationTextProviderAvailable` (Foliate posts it on every `.foliateSectionLoaded`, idempotent — Gate-4 r2 H2).
- `vreader/ViewModels/ChapterReTranslateViewModel.swift` (+ `ChapterReTranslateBoundaries.swift`) — per-chapter re-translate with provider/model/style override that never mutates the global active profile; atomic swap (bug #341: `bypassCacheRead` + in-place upsert, the old row survives until the new one lands); real N-of-M progress via `onChunkProgress` (bug #311); also depends on the same `BackgroundTaskRequesting` seam for background-survivable re-translate work. UI: `ReTranslatePickerSheet`(+`Parts`), `ReTranslateProgress`, `ReTranslateFlowLayout`; host wiring `ReaderContainerView+ReTranslate.swift` (`ReaderReTranslateObserver` ViewModifier). Result fans out on `.readerBilingualReTranslateApplied` → each host's `vm.applyReTranslateResult(_:for:)`.

## Edge cases and invariants

- Count mismatch → empty inject map → source-only, never mispair (#266/#334); divergence fallback re-translates the enumerate's own block texts 1:1 by construction (#268), restorable cache-only via `cachedSegmentsDirect(for:expectedCount:targetLanguage:)` (#343).
- Cache is consulted before any provider/consent gate (#306) and is profile-agnostic (#342); `.offline` is reserved for genuine connectivity, timeouts are `.timedOut` (#333).
- Epoch + request-token guards make disable/unit-change/interleaved position changes race-free; transient failures clear `lastTriggerUnit` so the same unit retries; granularity change clears the granularity-shaped cache (#344).
- All injected translation text is `FoliateJSEscaper.escapeForJSString`-escaped on JS lanes; injected `<div>`s are `user-select: none` and tagged `data-vreader-decoration`.
- VM is built on book OPEN, not only on first toggle, so persisted `isEnabled == true` repaints the chrome pill on reopen (bug #305 Foliate / #245 TXT).
