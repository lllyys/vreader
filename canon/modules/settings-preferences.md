# Module — settings and preferences

## Purpose

Owns the core reader preferences in vreader: the global reader display settings (theme, typography, pagination, auto page turn, Chinese conversion, custom background), per-book overrides layered on top of the globals, library view/sort preferences, and tap-zone mapping. It also hosts the app-level Settings sheet that fans out to sub-surfaces (WebDAV, AI, book sources, replacement rules, TTS, diagnostics) — but AI provider profiles, WebDAV server profiles, OPDS state, TTS settings, and consent/keychain data are owned by separate stores/modules reached through that navigation, not by this module (see the Dependencies section and [[Module — AI providers and tools]] / [[Module — backup and WebDAV]] / [[Module — TTS]]). Persistence is deliberately split across three mechanisms: UserDefaults for globals, per-book JSON files for overrides, and SwiftData for entity-shaped settings (e.g. replacement rules).

## Key files and types

- `vreader/Services/PreferenceStore.swift` — `protocol PreferenceStoring: Sendable` with `string(forKey:)` / `set(_:forKey:)` / `remove(forKey:)` plus a `setOrRemove` convenience; `UserDefaultsPreferenceStore` (production) and `MockPreferenceStore` (in-memory, with `setRaw` for simulating corrupt data). Injected into `LibraryViewModel` (bug #75) to persist `library.sortOrder` and `library.viewMode`.
- `vreader/Services/ReaderSettingsStore.swift` — `@Observable @MainActor final class ReaderSettingsStore`, the global reader-settings hub. Persists exactly 9 UserDefaults keys, enumerated in `static let allPersistedDefaultsKeys`: `readerTheme`, `readerTypography` (JSON-encoded `TypographySettings`), `readerUseCustomBackground`, `readerBackgroundOpacity`, `readerEPUBLayout`, `readerAutoPageTurn`, `readerAutoPageTurnInterval`, `readerPageTurnAnimation`, `readerChineseConversion`. Each property writes through a `didSet` (or clamping computed setter) guarded by a private `suppressPersistence` flag. Also exposes `let calibrator = FontSizeCalibrator()` (feature #70) and renderer configs `mdRenderConfig` / `txtViewConfig` plus `uiFont` / `uiBackgroundColor` / `uiTextColor` / `lineSpacingPoints` / `cjkLetterSpacing`.
- `vreader/Services/PerBookSettings.swift` — `PerBookSettingsOverride` (all-optional `fontSize` / `fontName` / `lineSpacing` / `letterSpacing` / `themeName`, plus feature #56 `bilingualEnabled` / `bilingualTargetLanguage` / `bilingualGranularity` and feature #101 `metricsReadout`), `ResolvedSettings` (all fields concrete), and the `enum PerBookSettingsStore` namespace: `settings(for:baseURL:)`, `save`, `delete`, `update(for:baseURL:_:)` (the feature #101 read-modify-write seam so a single-field write can't clobber siblings), and `resolve(perBook:global:)`.
- `vreader/Models/TypographySettings.swift` — `fontSize` clamped to `fontSizeRange = 12...64`, `defaultFontSize = 16`, `lineSpacing` clamped `1.0...2.0` (default 1.4), `fontFamily: ReaderFontFamily` (`system` / `serif` / `monospace` / `sourceSerif4` / `inter` — the last two added by feature #60 WI-1), `cjkSpacing: Bool`. Custom `init(from:)` falls back per-field on decode failure.
- `vreader/Models/ReaderThemeV2.swift` — 5-case theme enum (`paper` / `sepia` / `dark` / `oled` / `photo`) with 7 color tokens (`backgroundColor`, `paperColor`, `inkColor`, `subColor`, `ruleColor`, `accentColor`, `chromeColor`), contrast tokens `sliderTrack` / `controlTrack`, and predicates `isDark` / `hasPaperPattern` / `usesBackgroundImage`. Values pinned to `dev-docs/designs/vreader-fidelity-v1/project/vreader-themes.jsx`. Its `Codable` decoder accepts legacy `"light"` → `.paper`.
- `vreader/Models/ReaderTheme+ToV2.swift` — legacy bridge: `ReaderTheme.asV2`, lenient `ReaderThemeV2(legacyOrNew:)` (unknown → `.default` = `.paper`) and strict `ReaderThemeV2(recognized:)` (unknown → nil, used so a corrupt per-book `themeName` never clobbers the live theme).
- `vreader/Models/EPUBLayoutPreference.swift` — `scroll` (default) / `paged`.
- `vreader/Models/FontSizeCalibration.swift` + `vreader/Services/FontSizeCalibrator.swift` — feature #70 unified-font-size calibration. `CalibrationTarget` = `txt` / `md` / `epub` / `foliate` (PDF deliberately absent — PDFKit has no text-size input). Shipped profile `FontSizeCalibrationProfile.standard` = txt 1.0, md 1.0, epub 1.0, foliate 1.06 (bug #280 re-tune from the unverified 1.12). `calibratedSize` re-clamps to 12...64 (text targets) or 8...72 (Foliate, the `FoliateJSEscaper.clampFontSize` band); non-finite input falls back to the band's lower bound. `calibratedFoliateSize` rounds `.toNearestOrAwayFromZero` then clamps to Int 8...72.
- `vreader/Models/TapZoneConfig.swift` — `TapZoneConfig` (left/center/right thirds → `TapAction`: `previousPage` / `nextPage` / `toggleChrome` / `none`) and `TapZoneStore` (`@Observable @MainActor`, JSON under UserDefaults key `readerTapZoneConfig`), deliberately independent of `ReaderSettingsStore`.
- `vreader/Views/Reader/ReaderSettingsPanel.swift` — the in-reader "Display" half-sheet (feature #60 WI-10 `ReaderSheetChrome` re-skin): 5-theme swatch picker, custom background (feature #32), EPUB layout, page-turn animation + auto page turn, font size / line spacing sliders (feature #66 WI-1 `SettingsSliderRow`), font family (`TypefacePillToggle`, WI-2), CJK spacing, Chinese conversion, per-book toggle, live preview.
- `vreader/Views/Settings/SettingsView.swift` — the app Settings sheet (gear icon in the Library nav bar), fixed `.paper` theme, groups: profile card (feature #67 WI-4, `SettingsProfileCard` + `SettingsHeaderViewModel`), Cloud & Sync (`WebDAVSettingsView`, `BookSourceListView`), AI (`AISettingsSection`), Reading (`ReplacementRulesView`, `HTTPTTSSettingsView`), Support (`DiagnosticsLogView`, Help & Feedback, Version from `Bundle.main`). The AI provider and WebDAV profile editor/list surfaces and `HTTPTTSSettingsView` live under this Settings navigation, but their behavior is documented in [[Module — AI providers and tools]], [[Module — backup and WebDAV]], and [[Module — TTS]] respectively, not here.
- `vreader/Views/Settings/KindResetPolicy.swift` — pure, order-insensitive policy for the AI provider editor's kind picker (feature #50 WI-6b audit fix): replace baseURL/model text only when it still equals the OLD kind's default; edit-mode prefill is sticky.
- `vreader/Services/HapticFeedback.swift` — `HapticFeedbackProviding` protocol (`@MainActor`, `triggerLightImpact()`) + `HapticFeedbackProvider` wrapping `UIImpactFeedbackGenerator(.light)`; DI seam for test mocking, coordinates with reader notification handlers.
- `vreader/Services/ThemeBackgroundStore.swift` — per-theme custom background images as JPEG (max dimension 1024, quality 0.8) at Application Support `ThemeBackgrounds/<themeName>.jpg`; `backgroundImageDataURL(for:)` returns an inline `data:` URL for EPUB injection (feature #60 WI-12 / GH #795 — a `file://` URL is refused by the WKWebView's read-access scope).
- `vreader/Services/ReadingModeMigration.swift` — feature #54 one-shot synchronous launch migration: removes the retired `readerReadingMode` UserDefaults key and strips the `readingMode` field from per-book JSON via `JSONSerialization` (not a typed round-trip, which would drop unknown fields). Runs in `VReaderApp.init()` before any `ReaderSettingsStore` construction; idempotent.

## Persistence mechanisms

Three tiers, each with a reason:

1. **UserDefaults** — global reader settings (`ReaderSettingsStore`, 9 keys), library sort/view (`PreferenceStoring`), tap zones (`TapZoneStore`). Enums stored as rawValue strings; structs (`TypographySettings`, `TapZoneConfig`) JSON-encoded into a data key.
2. **Per-book JSON files** — `PerBookSettingsStore` writes `<Application Support>/PerBookSettings/<fingerprintKey with ':' → '_'>.json` (base URL defined at `ReaderContainerView.perBookSettingsBaseURL`). An empty fingerprint key maps to `_empty_key.json`. Files are written with `.atomic`. Unknown JSON keys decode harmlessly (synthesized `Codable`), which is how retired fields age out.
3. **SwiftData** — settings that are entities, e.g. `ReplacementRulesView` uses `@Query(sort: \ContentReplacementRule.order)` directly; AI provider profiles and WebDAV server profiles live in their own stores (see [[Module — AI providers and tools]] and [[Module — backup and WebDAV]]).

## Data flow: global vs per-book

- `ReaderContainerView` owns `@State var settingsStore = ReaderSettingsStore()` (a fresh store per reader open; `ReaderContainerView.swift:52`). A deferred `.task` loads the per-book file and, if present, calls `PerBookSettingsStore.resolve(perBook:global:)` then `settingsStore.applyResolvedSettings(resolved)` (bug #84) — `suppressPersistence` guarantees per-book values never leak into the global UserDefaults.
- `ReaderSettingsPanel`'s "Custom settings for this book" toggle (A05): ON snapshots the store's current fontSize/fontName/lineSpacing/letterSpacing/themeName into the per-book file (`letterSpacing` is derived from the `cjkSpacing` bool as `fontSize * 0.05` or `0`); OFF deletes the file and calls `store.reconcileFromDefaults()` (bug #147) so the live reader immediately reverts to globals. Six `.onChange` observers (fontSize, lineSpacing, fontFamily, cjkSpacing, theme, chineseConversion) re-snapshot the file while the toggle is on. **Two real bugs here, not just doc gaps**: (1) `ReaderSettingsStore.applyResolvedSettings` never applies `ResolvedSettings.letterSpacing` back to `typography.cjkSpacing` — the per-book CJK-spacing override is saved and `PerBookSettingsStore.resolve` returns it, but it is silently dropped on reader reopen; (2) the `chineseConversion` `.onChange` observer re-runs `savePerBookSnapshot()`, which rewrites the per-book file's fontSize/fontName/lineSpacing/letterSpacing/themeName fields, but `PerBookSettingsOverride` has no Chinese-conversion field at all, so the write neither persists nor restores the per-book Chinese-conversion choice.
- Feature #101's bottom-chrome metrics readout (`ReaderMetricsReadout`, pages/time) persists per book through `PerBookSettingsStore.update` from `ReaderBottomChrome`; feature #56's bilingual fields are read/written by `BilingualReadingViewModel` against the same file.
- Renderer fan-out: `txtViewConfig` / `mdRenderConfig` feed the TXT/MD hosts; `EPUBReaderContainerView` and `FoliateSpikeView` read `store.calibrator` directly and build their own CSS; `FoliateStyleMapper` (see [[Module — Foliate AZW3 reader]]) generates sanitized `setStyles()` CSS; the Readium host maps store state to `EPUBPreferences` (see [[Module — EPUB reader]]).
- Notification bus: `.readerMoreToggleAutoTurn` (`ReaderNotifications.swift:136`) flips `ReaderSettingsStore.autoPageTurn` from the More popover; `SettingsView` posts and observes `.openReadingStatsRequested` to present the reading-stats dashboard (see [[Architecture — notification bus]], [[Module — reading stats]]).

## Dependencies and cross-module contracts

- **Backup**: `BackupSettingsKeys.all` (`vreader/Services/Backup/BackupSectionDTOs.swift`) hard-codes the same 9 reader keys (hard-coded because the store is `@MainActor`-isolated and these constants must be reachable from non-isolated contexts); `BackupPerBookSettingsEnvelope` carries `PerBookSettingsOverride` entries verbatim ([[Module — backup and WebDAV]]).
- **Sync**: `NSUKVSBridge.syncedKeys` (`vreader/Services/Sync/NSUKVSBridge.swift`) syncs 5 keys to iCloud KVS, including `"readerTheme"` → `"reader.theme"`. Note: the bridge's local keys `"librarySortOrder"` / `"libraryViewMode"` differ from the keys `LibraryViewModel` actually persists (`library.sortOrder` / `library.viewMode`) ([[Module — sync]]).
- **Debug bridge**: `RealDebugBridgeContext` iterates `ReaderSettingsStore.allPersistedDefaultsKeys` for the `reset` clean-slate (bug #272) and builds a `ReaderSettingsStore(defaults:)` for settings snapshots ([[Module — debug bridge]]).
- **Test seams**: `VReaderApp` honors `--reset-preferences` (`TestSeeder.clearKnownPreferences()`, bug #152 / GH #426) and seeds `ReaderSettingsStore.epubLayoutKey` from a launch arg before any store init (feature #45 WI-4c).

## Edge cases and invariants

- **`@Observable` re-entrancy (bug #222)**: `autoPageTurnInterval` (clamp 1...60) and `backgroundOpacity` (clamp 0...1) are computed get/set over private backing vars — a clamping `didSet` that self-assigns recurses unboundedly under the `@Observable` macro (stack overflow).
- **Key-list drift**: `ReaderSettingsStoreTests.allPersistedDefaultsKeysCoversEveryKey` asserts `allPersistedDefaultsKeys` matches the individual `*Key` constants.
- **Theme decode tolerance**: lenient (`legacyOrNew`, falls back to `.paper`) at UserDefaults load; strict (`recognized`, leaves state untouched) when applying per-book overrides. Legacy `"light"` always maps to `.paper`.
- **Format gating in the panel**: Auto Page Turn renders only when `epubLayout == .paged` AND `formatCapabilities?.contains(.autoPageTurn) ?? true` — a nil `formatCapabilities` deliberately defaults to visible (keeps tests/previews/legacy callers working); capability membership is only checked when a capability set is actually supplied (bug #156 / GH #456 initially gated it to TXT/MD; bug #157 / GH #461 then found TXT's toggle silently no-op'd — no TXT paged renderer observed `pageNavigator.currentPage` — and dropped `.autoPageTurn` from TXT's capability set, so only MD claims it today even though `TXTReaderContainerView` still calls `updateAutoPageTurner` in its now-unreachable branch); Chinese conversion is enabled for TXT/MD, `.formatUnsupported` for PDF, `.nativeMode` for EPUB/AZW3/nil (feature #54; `SimpTradTransform` guarantees 1:1 UTF-16 mappings for BMP CJK so saved offsets stay valid).
- **Calibration safety**: non-finite unified size or multiplier → the target band's lower bound; Foliate values are clamped before `FoliateJSEscaper.clampFontSize` ever sees them.
- **Background image failures surfaced** (bug #134): load/decode/save/remove errors show an alert instead of being swallowed; `customBackgroundRevision` (session-scoped, never persisted) invalidates readers' cached background images when the file bytes change under an unchanged theme (feature #60 WI-12 / #795).
- **Accessibility contrast is designed, not ad hoc**: `subColor` light-family alpha raised 0.55 → 0.68 for WCAG AA 4.5:1 (feature #84 / #1292); `sliderTrack` ink@22% (bug #285 / GH #1273); `controlTrack` ink@30% light / white@16% dark (bug #298 / GH #1329); panel chrome labels routed through theme tokens with a `#c44` destructive color (bug #285 / GH #1265).
