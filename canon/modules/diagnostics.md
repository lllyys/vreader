# Module — diagnostics

## Purpose

Feature #96: in-app runtime diagnostics. vreader logs everywhere via OSLog `Logger` (subsystem `com.vreader.app`, rule 50 §7), but those entries used to be visible only in the system unified log. This module reads the app's OWN current-process entries back via `OSLogStore`, shows them in a Settings-hosted viewer (level/category filters, day grouping, expandable monospace rows), and exports a REDACTED `.txt` a user can attach to bug reports. Capture is always-on (it's just OSLog) — nothing to enable.

## Key files and types

Service layer (`vreader/Services/Diagnostics/`, feature #96 WI-1):
- `DiagnosticsLogEntry.swift` — `enum DiagnosticsLevel: String, Sendable, Equatable, CaseIterable { undefined, debug, info, notice, error, fault }` mirroring `OSLogEntryLog.Level` 1:1 (Gate-2 High: Swift `Logger.warning()` compiles to `.error` in the SDK, so no invented "warning" case); `struct DiagnosticsLogEntry: Sendable, Equatable { date, level, category, message }`.
- `DiagnosticsLogSource.swift` — `protocol DiagnosticsLogSource: Sendable { func recentEntries(since: Date?, limit: Int) async throws -> [DiagnosticsLogEntry] }` — the testable OS seam; ordered oldest→newest.
- `OSLogDiagnosticsSource.swift` — production source. `OSLogStore(scope: .currentProcessIdentifier)` → `position(date:)` → `getEntries(with:at:matching:)` with `NSPredicate("subsystem == %@", "com.vreader.app")` → filtered to `OSLogEntryLog` (`for case let … as OSLogEntryLog`, not a literal `compactMap` despite the source's own header comment). Scope is CURRENT SESSION only (Gate-2 Critical: no prior-launch/pre-crash forensics). Enumeration is synchronous + blocking, so it runs inside `Task.detached(priority: .utility)`; keeps a rolling window of the most recent `limit` entries instead of accumulating the stream (Gate-4 Low); `limit <= 0` returns `[]`.
- `DiagnosticsLogStore.swift` — `@MainActor @Observable final class DiagnosticsLogStore`. `static let captureScopeLabel = "this session"` (single source for export header AND viewer footer — deliberately supersedes the #1597 design mock's "last 24 h"). `load(since:limit:)` clamps the cap to `0…maxEntries` (default 2000; negative limit would trap in `suffix`, Gate-4 Medium) and treats a throwing source as empty. `filtered(level:category:)` is pure; `exportText(entries:)` runs EVERY message through `DiagnosticsRedactor.redact` with ISO8601 timestamps and `[LEVEL]` tags.
- `DiagnosticsRedactor.swift` — `enum DiagnosticsRedactor`, pure regex pipeline, `placeholder = "‹redacted›"`, `pathPlaceholder = "‹path›"`. Threat model: OSLog `.private` interpolations are already `<private>` on read-back (first line); this is the second line for `.public`/untagged content. Rules (in order): `Authorization: Bearer|Basic` values (quoted or unquoted — Gate-4 High), quoted then unquoted keyed secrets (`x-api-key|api[_-]?key|access/refresh token|client secret|token|password|secret`), OpenAI-style `sk-…` keys, JWTs (`eyJ…` three base64url segments), URL credentials (`user:pass@` → pass redacted), `file://` URLs, and filesystem paths under `/private/var/mobile/Containers|/var/mobile|/Users` including internal spaces (Gate-4 Medium: the path tail must not leak). Deliberately context-driven: does NOT blanket-redact long hex/base64 (hashes/ids), and keychain account LABELS are identifiers, not secrets. **Real gap (confirmed 2026-07-11 audit):** the "quoted" keyed-secret rule matches ONLY a double-quoted value (`api_key="…"`); the "unquoted" rule's value class also excludes a leading `'`. A SINGLE-quoted secret — `api_key='secret value'` — matches neither rule and is exported unredacted; the redaction guarantee does not hold for that form.

Viewer (`vreader/Views/Settings/Diagnostics/`, feature #96 WI-2, pinned to `dev-docs/designs/vreader-fidelity-v1/project/vreader-diagnostics.jsx`):
- `DiagnosticsLogViewModel.swift` — `@MainActor @Observable`. Owns the store, `levelFilter: DiagnosticsLevelFilter` + `categoryFilter: String?` (changing either collapses `expandedEntryID`), day sections via `DiagnosticsDayGrouper`, chip counts over ALL loaded entries, `exportText()` built from `filteredEntries` (so the Errors chip's `.fault` rows export — the store's single-level predicate can't express the set), `exportFileName(now:)` = `vreader-log-YYYY-MM-DD.txt` (en_US_POSIX), `footerScope` ("N entries · this session" / "Showing X of N · errors").
- `DiagnosticsLevelStyle.swift` — pure presentation: level→tint mapping (only error family and info are colored, per design), `enum DiagnosticsLevelFilter { all, errors, debug, info }` where `errors` includes `.fault`; `IdentifiedDiagnosticsEntry` (position-based identity, not Equatable-derived, so value-equal entries expand independently); `DiagnosticsDaySection` + `enum DiagnosticsDayGrouper` (now/calendar-injected day bucketing, newest-first).
- `DiagnosticsFilterChips.swift` — `DiagnosticsChip` pill + the two-row `DiagnosticsFilterBar` (level chips with counts; scrollable category chips); active Errors chip takes the error tint.
- `DiagnosticsLogRow.swift` — one row: mono timestamp · colored uppercase level · category pill over a 3-line-clamped monospace message; tap expands in place and reveals "Copy entry" (copies the REDACTED message via `UIPasteboard`). Also defines `Color(diagnosticsHex:)` for the design's hex tints.
- `DiagnosticsLogView.swift` — the pushed screen (Settings → Support → Diagnostics; presented from `vreader/Views/Settings/SettingsView.swift`). States: loading ("Reading log store…" / "OSLogStore · com.vreader.app"), empty, filtered-empty with "Clear filters", list with pinned day headers, footer with green "Capturing" dot. Share uses native `ShareLink` (an embedded `UIActivityViewController` renders blank three presentation levels deep); each filter change spawns a NEW unstructured `Task` calling `prepareExport()`, writing to the SAME deterministic filename (`vreader-log-YYYY-MM-DD.txt`) with no ordering/versioning between tasks — on rapid filter changes an OLDER task's write can finish after a newer one's and silently overwrite both the on-disk file and `exportURL` with a STALE (wrong-filter) export. A write failure does NOT hide the share affordance either: `writeExport` returning `nil` just skips the `exportURL` assignment, so if an earlier export already succeeded the share button stays visible and points at that now-stale file.

## Dependencies

Internal: reads back what every other module writes through `Logger(subsystem: "com.vreader.app", category: …)` — no module calls diagnostics directly; `ReaderThemeV2` theming; Settings navigation ([[Module — settings and preferences]]). External: OSLog (`OSLogStore`, `OSLogEntryLog`), Observation, SwiftUI. No entitlement needed for `.currentProcessIdentifier` scope on iOS 17+.

## Data flow

App code logs via OSLog → unified log ring buffer. Viewer opens → `DiagnosticsLogViewModel.load()` → store → `OSLogDiagnosticsSource.recentEntries` (detached task, subsystem-filtered, bounded window) → `[DiagnosticsLogEntry]` published on main → filters/day-grouping derive in the VM → rows render. Export: `exportText(entries: filteredEntries)` → per-line `DiagnosticsRedactor.redact` → temp `.txt` written off-main → `ShareLink`.

## Edge cases and invariants

- Export leak guard is layered: OS `.private` redaction first, `DiagnosticsRedactor` second; Copy-entry also redacts. Redaction is idempotent; over-redaction (a trailing benign word after a path) is the accepted safe direction.
- A throwing or empty source is a normal runtime outcome — never a crash; empty-vs-unloaded is distinguished by `hasLoaded`.
- Bounded memory everywhere: source keeps a rolling `limit` window; store trims to `maxEntries` (2000); negative limits clamped.
- No "warning" level exists — historical `Logger.warning()` entries read back as `.error` and are shown as such.
- Capture scope is the current process only; cross-launch/pre-crash forensics is explicitly out of scope (WI-1 Gate-2 scope correction).
