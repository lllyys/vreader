# Module — backup and WebDAV

## Purpose

Backs up and restores the user's library over a self-hosted WebDAV server: metadata (annotations, positions, settings, collections, book sources, per-book settings, replacement rules, reading history, AI conversations) travels in a ZIP; book files travel as content-addressed blobs. Feature #46 added the materializing restore (a fresh device downloads and re-imports every book); feature #47 added the selective picker plus lazy-on-tap downloads via a background URLSession; feature #52 added multiple saved server profiles. There is no CloudKit path — `docs/features.md` row 10 ("iCloud backup and restore") is WONT DO in favor of WebDAV.

## Key files and types

Transport and blob store (`vreader/Services/Backup/`):
- `WebDAVClient.swift` — `struct WebDAVClient: Sendable`, URLSession-based; conforms to `protocol WebDAVTransport` (`upload/download/delete/listDirectory/createDirectory/testConnection/move/existsWithSize`). Basic auth via `authorizationHeader`; `buildMKCOLRequest` forces a trailing slash (avoids a 301→method-rewrite auth failure on Apache-class servers); `createDirectory` treats HTTP 405 as "already exists" success; `existsWithSize` is `PROPFIND Depth: 0` (HEAD is unreliable across servers) and returns nil on 404. `WebDAVError` is `LocalizedError` with per-case messages (feature #52 WI-4b Codex fix, incl. a dedicated 405 "not a WebDAV endpoint" string).
- `PROPFINDParser.swift` — Foundation `XMLParser` delegate for multi-status responses; strips D:/d:/no-prefix namespaces; HTTP dates via en_US_POSIX `DateFormatter`.
- `BackupBlobStore.swift` — split protocols `BackupBlobReading` (`existsWithSize`, `download`) / `BackupBlobWriting` (`putBlobAtomically(_:to:expectedByteCount:) -> BlobPutResult` where `BlobPutResult` = `.uploaded | .alreadyExists`); `BackupBlobStoreError` = `.serverCapabilityMissing(String)` / `.sizeAfterPutMismatch(expected:actual:)` / `.underlying(String)`.
- `WebDAVBlobStore.swift` — adapter over any `WebDAVTransport`. Atomic publication: dedupe check (`existsWithSize` == expected → `.alreadyExists`) → MKCOL temp tree → PUT to `VReader/uploads/tmp/<uuid>.part` → PROPFIND size check (only a non-nil size that MISMATCHES throws `sizeAfterPutMismatch`; `uploadedSize == nil` is accepted and `MOVE` proceeds anyway — successful size verification is not actually required before publication) → `MOVE` with `Overwrite: F` to the final path. **412 handling is a real correctness gap, not a safe-by-design dedupe**: every 412 is accepted unconditionally as "concurrent publish converged" → cleanup temp, `.alreadyExists`, with no re-probe of the destination. If the initial `existsWithSize` found a destination with the WRONG size, the code still uploads a correct temp blob, gets 412 (because the bad destination exists), deletes the temp blob, and reports `.alreadyExists` while the MISMATCHED final blob is left in place. 501 = server lacks MOVE → `.serverCapabilityMissing("MOVE")`. Memoizes the temp-dir MKCOL (bug #112: fresh rclone rejects the first PUT with 409); real MKCOL failures propagate so the flag isn't poisoned (bug #117).
- `BlobPath.swift` — `enum BlobPath`: `make(format:sha256:byteCount:)` → `"VReader/books/<format>/<sha256>_<byteCount>.<canonical-ext>"`; `parse(_:)` validates 64-hex SHA. Colons are deliberately absent (fingerprintKey's `:` is unsafe on some WebDAV backends); per-format subdirs bound directory-listing size; original extension travels in the manifest, not the path.

Provider and sections:
- `BackupProvider.swift` — `protocol BackupProvider: Sendable` (`backup/restore/listBackups/deleteBackup`), `BackupMetadata` (id, createdAt, deviceName, appVersion, bookCount, totalSizeBytes), `BackupError` (incl. `.restorePartiallyFailed(String)`).
- `WebDAVProvider.swift` — the conformance. `basePath = "VReader/backups"`; ZIP path `<ISO8601-with-dashes>_<first-8-of-UUID>.vreader.zip`. Also defines `BackupDataCollecting` / `BackupDataRestoring` protocols (with default impls so mocks stay source-compatible) and the #47 entry points `loadManifest(backupId:)` and `restoreSelectively(backupId:selectedKeys:persistence:progress:)`.
- `BackupSectionDTOs.swift` — versioned Codable envelopes. `kBackupCurrentSchemaVersion = 3` (v2 added `reading-history.json`, feature #58; v3 added `ai-conversations.json`, feature #89); `kBackupAcceptedSchemaVersions = [1, 2, 3]` (restorer validates against the SET so old archives restore; v4+ throws `BackupRestoreError.unsupportedSchemaVersion`). `BackupLibraryEntry` (feature #46 WI-2) carries fingerprintKey/format/sha256/byteCount/originalExtension/title/author/addedAt/lastOpenedAt/blobPath + optional `sourceCanonicalKey` (feature #108 converted-Kindle identity, defaulted so no version bump). `BackupSettingsKeys.all` lists the 9 backed-up reader UserDefaults keys.
- `BackupReadingHistory.swift` / `BackupAIConversations.swift` — the v2/v3 section DTOs, split for the 300-line rule.
- `BackupDataCollector.swift` / `BackupDataRestorer.swift` — production impls over `PersistenceActor` + UserDefaults + file-based `PerBookSettingsStore`. Restore is additive upsert (merge, never delete); reading-history and AI-conversation collectors deliberately do NOT `try?`-swallow (an empty section would silently erase history on restore).
- `ZIPWriter.swift` — in-memory ZIP, Stored (method 0) entries, zlib CRC32; also `listEntryNames(in:)` / `extractEntry(named:from:)`.

Materializing restore (feature #46) and selective/lazy (feature #47):
- `BookFileMaterializer.swift` — serial download+verify+import per `BackupLibraryEntry`. Triple verify: byte count → streaming SHA-256 → post-import `ImportResult.fingerprintKey` match. Preflight-rehashes existing sandbox files; SHA-match still routes through `BookImporter` so a deleted row is re-inserted (bug #114); corrupt local file is removed pre-download. `defaultSandboxResolver` mirrors `LibraryBookItem.resolvedFileURL`: Application Support/ImportedBooks/`<fingerprintKey with : → _>.<ext>`.
- `BookFileImportFinalizer.swift` — shared SHA-verify → `importer.importFile(at:source:.restore, titleOverride: entry.title)` → fingerprint-match tail (bug #247: titleOverride keeps the manifest title instead of the `restore_<sha>` temp filename).
- `RemoteBookCatalog.swift` — pure decoder of `library-manifest.json` (`supportedSchemaVersion = 1`); `.iso8601` date decoding (a device-verification catch — unit fixtures had used the default Double dates).
- `SelectiveRestoreCoordinator.swift` — 3 phases weighted 0.10/0.75/0.15: preplant unselected entries as `.remoteOnly` `BookRecord`s (`insertRemoteOnlyBookRecords`), materialize selected, apply metadata via `SelectiveRestoreMetadataSections` — only 7 sections (annotations, positions, settings, collections, book sources, per-book settings, replacement rules). It OMITS `reading-history.json` and `ai-conversations.json` entirely; restore-ALL restores both (see Data flow's "9 metadata sections"), selective does not — a real feature-coverage gap, not just a doc gap. Posts `.bookFileStateDidChange` per landed row even on `PersistenceError.partialBulkInsert` (bug #119). Phase 2.5 re-attaches `sourceCanonicalKey` on materialized rows (#108).
- `LazyDownloadCoordinator.swift` — `@MainActor @Observable`; `progressByKey`/`outcomes`/`terminalKeys` (sticky guard against stale `didWriteData` after a terminal event); `enqueue(...) -> EnqueueResult` (`.started/.deferredWiFi/.notReady/.taskDescriptionEncodeFailed`); `reattachAndReconcile()` at init recovers OS-preserved tasks and flips orphaned `.downloading` rows to `.failed`, first trying `LazyDownloadFinalizer.tryPromoteFromDisk` (bug #118 follow-up: file already at canonical path with right SHA → promote instead of re-download; tries original AND canonical extensions). Declares notifications `.bookFileStateDidChange` (`"vreader.backup.bookFileStateDidChange"`) and `.libraryRowTappedWhileNotLocal` (`"vreader.backup.libraryRowTappedWhileNotLocal"`).
- `LazyDownloadDelegate.swift` — nonisolated `URLSessionDownloadDelegate`; moves the temp file synchronously to Caches/LazyDownloads/`<sha>_<bytes>_<taskID>.<ext>` then hops to MainActor; `urlSessionDidFinishEvents` always invokes the stored `VReaderAppDelegate.takeBackgroundHandler(for:)` handler.
- `LazyDownloadTaskMeta.swift` — Codable payload in `URLSessionTask.taskDescription` (schemaVersion 1; decode validates 64-hex SHA and an alnum ≤8-char extension so a corrupt description can't build a traversing staged path).
- `LazyDownloadFinalizer.swift` — SHA verify → move staged → canonical → `persistence.promoteToLocalClearBlob(fingerprintKey:)` (single atomic save of `fileState=.local` + `blobPath=nil`, bug #118). Bug #115: this wiring was originally deferred and downloads left rows `.remoteOnly` forever.
- `BackgroundDownloadSession.swift` — `protocol BackgroundDownloadSessioning` + `URLSessionBackgroundSession` (`isDiscretionary`, `sessionSendsLaunchEvents`, `allowsCellularAccess = true` — Wi-Fi gating is policy-level because flipping `allowsCellularAccess` mid-flight cancels instead of pausing).
- `WebDAVDownloadRequestBuilder.swift` — authenticated GET for a blobPath, reusing `WebDAVClient` credentials.
- `WebDAVNetworkPolicy.swift` — `@MainActor @Observable` Wi-Fi-only gate over `NWPathMonitor` (seam `NetworkPathMonitoring`); UserDefault `com.vreader.webdav.wifiOnly` default true; `shouldStart()` is false on `.unknown` (don't burn cellular on a guess); wired Ethernet and loopback classify as `.wifi`.

Profiles (feature #52):
- `WebDAVServerProfile.swift` — id/name/serverURL/username; password lives in Keychain at `keychainPasswordAccount(for:)` = `"com.vreader.webdav.profile.<uuid>.password"`; `displayName` falls back to host.
- `WebDAVServerProfileStore.swift` — `actor`, `.shared` singleton; UserDefaults keys `com.vreader.webdav.profiles` / `com.vreader.webdav.activeProfileID`; `loadSnapshot()` atomic pair read; `updateIfExists` avoids the load-then-upsert delete race; every mutation posts `.webdavProfilesDidChange` (`"com.vreader.webdav.profilesDidChange"`).
- `WebDAVProfileMigrator.swift` — one-shot legacy flat-keychain → "Default" profile migration; marker `com.vreader.webdav.profilesMigrated.v1`; stable migrated UUID `00000002-AAAA-4000-8000-000000000001` so a re-run upserts, never duplicates.
- `WebDAVProviderFactory.swift` — builds a wired `WebDAVProvider` (or `WebDAVDownloadRequestBuilder`) from the active profile; throws `missingCredentials` / `invalidServerURL`.

UI: `vreader/Views/Backup/SelectiveRestorePicker.swift` (manifest list, Select All/Clear, "ticked = download now, unticked = lazy-load on tap") and `vreader/Views/Backup/BookDownloadSheet.swift` (per-book progress sheet; Retry re-posts `.libraryRowTappedWhileNotLocal`), both driven by `vreader/ViewModels/BackupViewModel.swift` (`loadBackups/performBackup/performRestore/loadManifest/performSelectiveRestore/deleteBackup`).

Cross-cutting persistence-access note: `WebDAVServerProfileStore` (`vreader/Services/Backup/WebDAVServerProfileStore.swift:44`) is its own actor-isolated durable configuration store (UserDefaults-backed profile list + active-profile selection) — a persistence boundary separate from `PersistenceActor`/SwiftData, not a facade over it.

## Data flow

Backup (`WebDAVProvider.backup`): collect 10 sections (progress 0→0.30) → metadata + ZIP (→0.40) → MKCOL ancestors of `VReader/backups` (→0.45) → publish each manifest blob via `putBlobAtomically` (0.45→0.85; PROPFIND-dedupe makes repeat backups upload only NEW books; a missing local file is logged and skipped; `serverCapabilityMissing` aborts loudly) → PUT the ZIP (→1.0). Restore-all: resolve path from `metadataCache` (refill via `listBackups()`), download ZIP, require `metadata.json`, then Phase A materialize manifest books (0.55→0.75, only when a `bookImporter` was injected — v1 archives skip) and Phase B apply the 9 metadata sections (missing entries silently skipped; per-section errors collected, not aborting). Partial failures from either phase surface as one `BackupError.restorePartiallyFailed`. Lazy download: LibraryView tap on a non-`.local` row → `.libraryRowTappedWhileNotLocal` → `LazyDownloadCoordinator.enqueue` → background URLSession → delegate stages the file → `LazyDownloadFinalizer` promotes → `.bookFileStateDidChange` (see [[Architecture — notification bus]]).

## Round-trip verification harness

`scripts/run-webdav-roundtrip.sh` is the **Android** live round-trip gate (feature #116 WI-6): it stands up a throwaway `rclone serve webdav` on `127.0.0.1:$PORT` (default creds `vreader`/`vreader`, data dir from `mktemp`), waits on the exact port (never a pgrep waiter — rule 49; the 2026-06-23 subshell-pid leak incident shaped this), then runs `com.vreader.app.backup.WebDavRoundTripConnectedTest` on the emulator via `run-android-verify.sh` with the host reachable at `10.0.2.2:$PORT`, printing one `RUN-WEBDAV-ROUNDTRIP RESULT:` line. The iOS side was Gate-5-verified against live rclone WebDAV per the feature #46/#47 rows. Android backup parity is features #113/#114/#116 (see [[Module — Android port]] and [[Module — cross-platform contracts]]).

## Edge cases and invariants

- Blob publication is atomic by construction: final path is present-and-complete or absent; `.part` temp files are the only mid-crash residue.
- Content addressing = idempotency on the happy path: identical bytes converge at one path. But concurrent backups are NOT safe as implemented — `MOVE Overwrite: F` + unconditional 412-as-`.alreadyExists` handling never re-probes the destination, so a destination that already exists with the WRONG size is silently accepted as a dedupe match instead of surfacing the mismatch (see `WebDAVBlobStore.swift` above).
- Selective restore's metadata phase covers only 7 of the 9 backup sections — it does not restore reading history or AI conversations (see `SelectiveRestoreCoordinator.swift` above).
- Restore is a merge — never deletes local data the archive doesn't mention.
- Older/newer archives: missing sections skip (forward compat); envelope version outside {1,2,3} throws; manifest schemaVersion > 1 throws `manifestSchemaVersionTooNew`.
- Corrupted ZIPs in `listBackups()` are skipped, not fatal.
- Fingerprint mismatch after import (`fingerprintMismatchAfterImport`) catches extension/format confusion (AZW3 bytes labelled .epub).
- All hashing is streaming (64 KB chunks) so 13–18 MB books don't spike memory.
- Stale-progress race: `terminalKeys` survives `clearOutcome`; only `prepareToDownload` re-arms a key.
