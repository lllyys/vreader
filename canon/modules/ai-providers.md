# Module — AI providers and tools

## Purpose

The AI assistant subsystem under `vreader/Services/AI/` (78 Swift files, ~10.3k lines incl. `Tools/` and `vreader/Views/AI/`): multi-provider LLM access (OpenAI-compatible + Anthropic-native), a gated request coordinator (`AIService`), reader-context extraction, multi-turn chat with agentic tool-calling (feature #91), and the translation transport that powers bilingual reading (feature #56) and whole-book translation. Users configure saved provider profiles in Settings and switch the active one; every AI call runs behind a feature flag + consent + API-key gate.

## Key files and types

Provider layer:
- `vreader/Services/AI/AIProvider.swift` — `protocol AIProvider: Sendable` with `sendRequest(_ request: AIRequest) async throws -> AIResponse`, `streamRequest(_:) -> AsyncThrowingStream<AIStreamChunk, Error>`, `providerName`, plus feature #91 `supportsToolUse` (default `false`) and `sendToolRequest(_:)` (default throws `AIError.toolUseUnsupported`). Also defines `struct OpenAICompatibleProvider`: POST `<baseURL>/chat/completions`, `Authorization: Bearer`, SSE `data:` lines terminated by `[DONE]`; defaults `https://api.openai.com/v1` / `gpt-4o-mini`.
- `vreader/Services/AI/AnthropicProvider.swift` (+`+Streaming.swift`, `+ToolUse.swift`) — POST `<baseURL>/v1/messages`, `x-api-key` header, `anthropicVersionHeader = "2023-06-01"`, `defaultMaxTokens = 4096` (Anthropic requires `max_tokens`). Streaming dispatches on the JSON `type` field (`content_block_delta` / `message_stop` / `error`); EOF without `message_stop` throws (partial reply never reported as success); non-2xx streaming responses buffer up to 1KB of error body for the excerpt. 429 parses `retry-after` (seconds) into `AIError.rateLimited(retryAfterSeconds:)`; 401 vs 403 get distinct messages (key wrong vs model/workspace access).
- `vreader/Services/AI/ProviderKind.swift` — `enum ProviderKind: String, Codable { case openAICompatible, anthropicNative }` with `defaultBaseURL`, `defaultModel` (`gpt-4o-mini` / `claude-sonnet-4-6`), and `endpointPathHint` (bug #185: users pasting full endpoint URLs got silently doubled paths).
- `vreader/Services/AI/ProviderProfile.swift` — `struct ProviderProfile: Codable, Sendable, Identifiable { id: UUID; name; kind; baseURL; model; temperature; maxTokens }`. The API key is deliberately NOT a stored property.
- `vreader/Services/AI/ProviderProfileStore.swift:31` — `actor`, production singleton `.shared`; profiles persisted as JSON in UserDefaults keys `com.vreader.ai.providerProfiles` / `com.vreader.ai.activeProviderID`; every mutation posts `Notification.Name("com.vreader.ai.providerProfilesDidChange")` so an open in-reader picker resyncs. It's an actor-isolated *durable configuration* store (UserDefaults-backed) — a persistence boundary distinct from the app's SwiftData `PersistenceActor`, worth naming explicitly alongside the module's other actor-isolated stores (see Concurrency below).
- `vreader/Services/AI/KeychainService+ProviderProfile.swift` — per-profile key account `com.vreader.ai.apiKey.<UUID>` via `KeychainService.providerAccount(for:)`; `readAPIKey/saveAPIKey/deleteAPIKey(forProfile:)`.
- `vreader/Services/AI/ProviderProfileMigrator.swift` — idempotent commit-style migration (feature #50 WI-2) from legacy single `AIConfiguration` (UserDefaults key `com.vreader.ai.configuration`) + legacy keychain account `com.vreader.ai.apiKey` into one `.openAICompatible` profile with stable UUID `00000001-AAAA-4000-8000-000000000001`; migration flag `com.vreader.ai.providerProfiles.migrated`; keychain copy verified by read-back before the flag is set. The protocol is synchronous on purpose — an async migrator opens an actor re-entrancy race.

Coordinator and gates:
- `vreader/Services/AI/AIService.swift` — `actor AIService`; gate order: `featureFlags.aiAssistant` → `consentManager.hasConsent` → provider/key resolution → `AIResponseCache` lookup → provider call. `resolveProvider()` takes ONE active-profile snapshot per request; `ResolvedAIProviderConfig` (in `ResolvedAIProviderConfig.swift`: `kind/baseURL/apiKey/model/maxTokens`) pins provider+credential+model for multi-request operations via `resolveActiveProviderConfig()` and `resolveProviderConfig(profileID:modelOverride:)`. `sendRequest(_:using:)` deliberately bypasses `AIResponseCache` (the cache key carries no provider identity). Tool-use: `resolveToolProvider()` and `sendToolTurn(_:using:)` — the latter re-checks the live flag + consent on EVERY agentic turn while reusing the pinned config. Legacy constant `AIService.apiKeyAccount = "com.vreader.ai.apiKey"` is read by the migrator AND by `AIReaderAvailability.hasAPIKey` as a fallback when no active profile exists.
- `vreader/Services/AI/AITypes.swift` — `AIActionType` (summarize/explain/translate/vocabulary/questionAnswer), `AIRequest` (with a SHA256-based deterministic `cacheKey`), `AIResponse`, `AIStreamChunk`.
- `vreader/Services/AI/AIError.swift` — `featureDisabled / consentRequired / apiKeyMissing / providerError / networkError / rateLimited / contextExtractionFailed / invalidResponse / cacheMiss / toolUseUnsupported`, all with `errorDescription`.
- `vreader/Services/AI/AIConsentManager.swift` — UserDefaults keys `com.vreader.ai.consentGranted` / `com.vreader.ai.consentDate`. `AIService.clearCache()` / `AIResponseCache.clearAll()` are documented ("called when consent is revoked") but have no production call site — `AISettingsViewModel.hasConsent`'s setter calls only `consentManager.revokeConsent()`.
- `vreader/Services/AI/AIResponseCache.swift` — actor, in-memory LRU, default 100 entries.
- `vreader/Services/AI/AIReaderAvailability.swift` — the UI gate (flag AND key AND consent; bug #90). `vreader/App/AITestSetup.swift` (DEBUG) makes the `--enable-ai` launch flag set ALL THREE gates (bug #237 had only forced the UI gate, so live requests still threw). `vreader/Services/AI/MockAIProvider.swift` (DEBUG) is a deterministic streaming provider activated by `--mock-ai` for CU-free verification.

## Dependencies

Internal: `KeychainService` (key storage), `PreferenceStoring`/`UserDefaultsPreferenceStore` (profiles, consent, flags), `FeatureFlags` (`aiAssistant` default OFF in every environment, persisted override; `agenticTools` ships dark default OFF), `DocumentFingerprint`/`Locator` (request identity + context), the search subsystem (`SearchService`, `SearchIndexStore`, `PersistentSearchIndex`) for the agentic search tools ([[Module — search]]), `LibraryPersisting` for library tools ([[Module — library]]), `ChapterTranslationStore` (`vreader/Services/ChapterTranslationStore.swift`) for the translation disk cache, `ChapterTextProviding` per-format text providers ([[Module — bilingual translation]]), `EPUBParser`/`TXTService`/PDFKit inside `ClosedBookTextExtractor`. External: Foundation `URLSession` (incl. `bytes(for:)` SSE), `JSONSerialization`, CryptoKit (cache-key hashing), OSLog. No third-party AI SDK — both wire protocols are hand-rolled.

## Data flow

Chat (non-agentic): `AIChatView` → `AIChatViewModel` (@MainActor) → `AIService.streamRequest` (actor hop; snapshot active profile, read Keychain key, build concrete provider) → provider SSE → `AIStreamChunk`s back to the VM. Agentic (flag `agenticTools` ON + `supportsToolUse`): VM resolves once via `resolveToolProvider()`, builds the registry with `AgenticToolRegistryBuilder.buildLive`, maps history via `AIChatHistoryMapper`, then `AgenticChatDriver.run` loops through `AIServiceToolUseAdapter` → `AIService.sendToolTurn` (live gates re-checked per turn) → tools run via `AIToolRegistry.run`; only the final answer surfaces. Bilingual translate: bilingual VM → `ChapterTranslationPrefetcher` (resolve config once) → `ChapterTranslationService.translate` (segment/chunk/decode/cache) → ordered `[String]` segments injected by the reader hosts. Whole book: Book Details UI → `BookTranslationCoordinator.start` → per-unit `translate` → progress snapshots via AsyncStream + `.readerBookTranslationProgressDidChange` userInfo `{fingerprintKey, completed, total, phase}`.

## Concurrency

`AIService`, `ProviderProfileStore`, `AIResponseCache`, `ChapterTranslationService`, `BookTranslationCoordinator`, `WholeBookReducer` are actors; providers are `Sendable` structs constructed per request from a value-type snapshot. The snapshot discipline is the module's core pattern: one `ProviderProfile` snapshot per request (`resolveProvider()`), one `ResolvedAIProviderConfig` per multi-request operation (translation chunks, agentic loop) so a mid-operation profile swap, model change, or Keychain rotation can never straddle an operation — while the agentic path still re-checks flag + consent every turn so a mid-loop disable fails closed.

## Edge cases and invariants

- Keys never leave Keychain except into in-memory Swift values: the ordinary single-request path (`resolveProvider()`) reads the key and stores it directly in a constructed `OpenAICompatibleProvider`/`AnthropicProvider`, never boxing it in a `ResolvedAIProviderConfig` — that DTO exists only to pin provider+credential+model for multi-request operations (translation chunks, agentic loop). Both providers refuse to send a key over non-HTTPS unless the host is `localhost`/`127.0.0.1`.
- Bug #320: user-facing translation errors go through `ChapterTranslationService.sanitizedProviderMessage` — raw provider JSON / enum-case text stays in OSLog only; HTTP error body excerpts truncate at 200 chars (1KB cap on streaming).
- Bug #330: one failed chunk degrades to source-only segments and the run continues; an all-chunks failure throws; a partially-degraded result is never cached (so a re-read retries).
- Bugs #341/#342/#343: an explicit re-translate bypasses the cache READ (write still upserts atomically); the cache lookup key is profile-agnostic (book|unit|language|promptVersion) with the profile id kept as provenance only; the DOM-enumerate divergence fallback caches under the enumerate's count as contract.
- Cached translations render with AI later disabled/unconfigured (bug #306 `cachedTranslation` before the provider gate).
- Tool results and book context are framed as untrusted data; tool executor caps: byte-clamped content, `list_library` announces partial counts, `get_book_content` reports character ranges recomputed AFTER the UTF-8 clamp (so CJK paging never skips text); non-finite `progressFraction` guarded (would trap `Int(_:)`).
- Truncated model turns (`stop_reason=max_tokens` / `finish_reason=length`) throw as retriable rather than acting on a partial `tool_use`.
- `AIRequest.cacheKey` includes `promptVersion`, so prompt changes invalidate stale cache entries; the cache-clear-on-consent-revocation path (`AIService.clearCache()`) is documented but not actually wired to any revocation call site (see AIConsentManager.swift above).
