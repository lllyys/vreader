# Module — Kindle AZW3 and libmobi

## Purpose

Handles Kindle-format books (AZW3/AZW/MOBI/PRC, all normalized to `BookFormat.azw3`) on the import side. Two lanes exist: (1) **convert-on-import** — since feature #42 Phase 2, a newly imported Kindle file is decoded by the vendored libmobi C library and repackaged as a first-class EPUB, so it renders through the default Readium EPUB engine ([[Module — EPUB reader]]); (2) **native import** — when the flag is off or conversion fails semantically, the raw Kindle file is imported as-is, its title/author/cover parsed natively from the PDB/MOBI binary, and rendered by the Foliate-js host ([[Module — Foliate AZW3 reader]]).

## Key files and types

Vendored library (`vreader/Services/Libmobi/`):

- `src/` — vendored libmobi C sources (LGPL-3.0, upstream commit `906274205c11944b628da1c553b255acb1af7c55` per `BUILD-RECIPE.md`): 36 files, 17 `.c` (`buffer.c`, `compression.c`, `debug.c`, `encryption.c`, `index.c`, `memory.c`, `meta.c`, `miniz.c`, `opf.c`, `parse_rawml.c`, `randombytes.c`, `read.c`, `sha1.c`, `structure.c`, `util.c`, `write.c`, `xmlwriter.c`) + headers incl. the public umbrella `mobi.h`.
- `BUILD-RECIPE.md` — iOS build facts: no external zlib (bundled `miniz.c`); libxml2 is the only external dep, gated by `USE_LIBXML2` (define `USE_LIBXML2=1`, include `$(SDKROOT)/usr/include/libxml2`, link `libxml2.tbd`); do NOT define `HAVE_CONFIG_H` (would include a nonexistent configure-generated file); all 17 `.c` compile+archive to a 285 KB `.a` on the iOS Simulator arm64 SDK.
- `README.md` — upstream libmobi's own doc (vendored as-is: features, C API usage sketch, LGPL-3.0-or-later license); not vreader-specific build guidance, which lives in `BUILD-RECIPE.md` above.
- `vreader/SupportingFiles/Libmobi-Bridging-Header.h` — exposes only `mobi.h` to Swift; the `.c` sources compile into the app target via `project.yml`.
- `Libmobi.swift` — `enum Libmobi` namespace. `Libmobi.version` (reads C `mobi_version()`), `contextAllocates()` (WI-1b linkage smoke: `mobi_init`/`mobi_free`).
- `MobiDocument.swift` — the DECODE half (WI-2a). `struct MobiPart { section: .markup/.flow/.resource, uid: Int, fileExtension: String, data: Data }`; `enum MobiDecodeError { initFailed, loadFailed(Int32), parseFailed(Int32), noMarkup, corrupt(String) }`; `struct MobiMetadata { title, author, language: String? }`; `struct MobiBook { parts, metadata }`. `Libmobi.decodeBook(atPath:) throws -> MobiBook` and `decodeParts(atPath:)`; `Libmobi.maxPartsPerSection = 100_000` (cyclic-chain guard); `appendChain(_:section:into:)` is `internal` so synthetic-chain tests can hit the defensive paths.
- `MobiEPUBAssembler.swift` — the ASSEMBLY half (WI-2b). `struct EPUBFile { path, data, isStored }`; `enum MobiEPUBError { noMarkup }`; `MobiEPUBAssembler.assemble(parts:title:author:language:) throws -> [EPUBFile]`. Pure and deterministic — no clock/RNG; package identifier = `"urn:uuid:" + packageUUID(for: parts)`, a SHA-256 over domain-separated part headers + bytes shaped 8-4-4-4-12.
- `MobiEPUBConverter.swift` — end-to-end (WI-2c). `MobiEPUBConverter.version = 2` (v2 = bug #336 reopen: `content.opf` carries the source's real `dc:language` instead of hardcoded `und`); `fallbackTitle = "Untitled"` (fixed string, never the filename, to keep output content-deterministic); `convert(mobiPath:) throws -> Data`; `convertToFile(mobiPath:destinationDir:) throws -> URL` (writes `kindle-converted-<UUID>.epub`, cleans partial file on write failure); `package(files:)` zips via `ZIPWriter` (`vreader/Services/Backup/ZIPWriter.swift`, everything Stored/uncompressed — valid OCF).

Native binary parsing (`vreader/Services/AZW3/`):

- `MOBIMetadataParser.swift` — `extractTitleAndAuthor(from fileURL:) -> (title: String?, author: String?)` from EXTH records 503 (Updated title) + 100 (Author); big-endian PDB/MOBI parsing (78-byte PDB header, 8-byte record entries, `"MOBI"` magic at record-0 offset 16, EXTH flag bit `0x40` at offset 128); decodes payloads UTF-8 first, CP1252 only when the MOBI text-encoding field at record-0 offset 44 declares 1252, and returns nil for other codepages rather than surface mojibake. Never throws; `(nil, nil)` on any parse failure.
- `MOBICoverExtractor.swift` — `extractCover(from fileURL:) -> UIImage?` via EXTH 201 (coverOffset, preferred) / 202 (thumbnailOffset), `0xFFFF_FFFF` = not-set sentinel, image record index = `firstImageRecord` (record-0 offset 108) + relative offset. Nil on any failure (truncated, DRM, corrupt image).

Import wiring: `BookFormat.isKindleConvertible` (`self == .azw3`; `vreader/Models/BookFormat.swift`), `FeatureFlags` case `.kindleConvertOnImport` (`vreader/Services/FeatureFlags.swift` — default ON since the human-gated G2 flip 2026-06-02, persisted user override supported), `AZW3MetadataExtractor` in `vreader/Services/MetadataExtractor.swift` (bug #149/GH #340: uses EXTH title/author, falls back to filename), and Step 3.5 of `BookImporter.importFile` ([[Module — import pipeline]]).

## Dependencies

Internal: `BookImporter` (the only production caller of `MobiEPUBConverter`), `ZIPWriter` (backup module's write-only in-memory ZIP), `ImportProvenance.convertedFromKindleExtension`/`converterVersion` (best-effort observability, non-load-bearing by design decision #5), `Book.sourceCanonicalKey` via `BookPersisting.setSourceCanonicalKey` (feature #108; see [[Module — persistence and data model]] and [[Module — cross-platform contracts]] for `contracts/identity/DECISION.md`). External: the vendored libmobi C API (`mobi_init`, `mobi_load_filename`, `mobi_meta_get_title/author/language`, `mobi_init_rawml`, `mobi_parse_rawml`, `mobi_free`, `mobi_free_rawml`), system libxml2, CryptoKit (deterministic package id).

## Data flow

Convert-on-import (BookImporter Step 3.5, flag ON, `format.isKindleConvertible`):

1. Hash the SOURCE bytes off-main (`ContentHasher`) → `sourceCanonicalKey` = `azw3:{sha256_of_source}:{bytes}` — the cross-platform canonical identity for a converted book (feature #108), matching what Android would compute from the same file.
2. `MobiEPUBConverter.convertToFile` off-main: `Libmobi.decodeBook` runs `mobi_init → mobi_load_filename → mobi_meta_get_* → mobi_init_rawml → mobi_parse_rawml`, then walks the three `MOBIPart` linked lists (`markup` / `flow` / `resources`), copying each node's bytes into Swift `Data` (the C buffers are owned by `MOBIRawml`). Metadata strings from `mobi_meta_get_*` are malloc'd; `copyMetaString` frees them.
3. `MobiEPUBAssembler.assemble`: markup parts become the spine in decode order at `OEBPS/text/part%04d.xhtml`; flow (CSS/SVG) at `OEBPS/styles/`, resources at `OEBPS/resources/`; the FIRST image resource becomes the cover (`properties="cover-image"` + EPUB2 `<meta name="cover">`); generated `content.opf` (EPUB 3.0, `dc:title`/`dc:creator`/`dc:language` from the source's own metadata — "title-neutral", WI-4a), `nav.xhtml`, `META-INF/container.xml`, and `mimetype` first + Stored.
4. `package` → Stored OCF zip → temp `.epub` file; the ENTIRE remaining import pipeline runs over it (`workingFormat = .epub`), so fingerprint, sandbox blob, and display metadata are the EPUB's. The original extension and `MobiEPUBConverter.version` land in `ImportProvenance`.

Fallback: `MobiDecodeError` / `MobiEPUBError` (DRM, corrupt, no markup) are caught and logged — the file imports natively instead (design decision #8: the user never loses the ability to import). Filesystem/`ZIPWriter` failures are NOT caught — they surface as real import errors.

Native lane (flag OFF or fallback): `AZW3MetadataExtractor.extractMetadata` → `MOBIMetadataParser` EXTH 503/100 (filename fallback); `extractCoverImage` → `MOBICoverExtractor`. Rendering dispatches to `FoliateBilingualContainerView` wrapping `FoliateSpikeView` (feature #56 WI-11; see [[Architecture — reader dispatch and format hosts]]).

DEBUG launch overrides in `VReaderApp.swift`: `--enable-kindle-convert` forces the flag ON (verification runs) and `--disable-kindle-convert` forces it OFF (bug #325 verification needed a seeded AZW3 to stay native-Foliate).

## Edge cases and invariants

- **Determinism invariant**: the converted EPUB is a pure function of the source CONTENT — fixed fallback title, no clock/RNG, content-addressed package id — so the same MOBI always yields the same EPUB bytes and thus the same `fingerprintKey`.
- **OCF invariant**: `mimetype` must be first and Stored; `ZIPWriter` stores every entry and preserves order; CI-gated by `MobiEPUBConverterTests.mimetypeRawHeaderIsStored` (reads the raw local-file-header compression field).
- **Corruption guards** (Codex Gate-4 findings): part chains capped at `maxPartsPerSection = 100_000` (cyclic `next` → `.corrupt` instead of OOM); a part with `size > 0` but null `data` → `.corrupt`; zero markup parts rejected in BOTH decode (`.noMarkup`) and assembly (empty spine/TOC `<ol>` is invalid EPUB3); package-id hashing domain-separates section/uid/extension/length so identical bytes in different structures can't collide.
- **EXTH bounds** (Codex Medium fix in `MOBIMetadataParser`): `exthLength` must cover the 12-byte header and fit inside record 0; the per-record loop is bounded by `exthEnd`, not `record0.count`, so a corrupt record count can't parse adjacent bytes as pseudo-records.
- **DRM**: encrypted books typically load but fail `mobi_parse_rawml` → `.parseFailed(code)` → native fallback; neither `MOBIMetadataParser` nor `MOBICoverExtractor` checks DRM/encryption state directly — both parse only the PDB header and EXTH records, which CAN remain readable on a DRM book, so they CAN still return real title/author/cover. A nil result on a DRM book happens only incidentally (e.g. the cover's image record bytes are themselves encrypted and fail to decode as `UIImage`), not as a guaranteed DRM check.
- **Memory**: the conversion pipeline is fully in-memory (~2–3× book size peak for image-heavy books; accepted for the ≤~18 MB fixture range, noted in `MobiEPUBConverter.swift`).
- **Dedupe interplay**: re-importing the source `.azw3` re-runs conversion, hits the SAME converted-EPUB fingerprint, and the dedupe path preserves Kindle-origin provenance (bug #307) and backfills a nil `sourceCanonicalKey` on pre-#108 rows.
- **XML safety**: `xmlEscape` in the assembler escapes `&` first, then `< > " '`, for OPF/nav text.
