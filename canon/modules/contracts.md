# Module — cross-platform contracts

## Purpose

`contracts/` is the canonical, platform-neutral specification of vreader's identity and data-interop surface — how a book is identified (fingerprint), how a reading position is located (Locator), how the translation cache is keyed, and how a backup archive is shaped — plus golden vectors and a dual-platform conformance lane that turns "iOS and Android agree" from a hope into a runnable gate. Decomposed from feature #102 per ADR-0001; the directory IS Spike A (feature #104, VERIFIED 2026-06-17), the ADR's Risk-1 interop gate.

## Key files and types

- `contracts/README.md` — layout, versioning levels, tool-version pinning, the legal rule.
- `contracts/identity/fingerprint.md` — `DocumentFingerprint.canonicalKey = "{format}:{contentSHA256}:{fileByteCount}"`; `format` is a `BookFormat` raw value (`epub`, `pdf`, `txt`, `md`, `azw3` — there is NO `mobi`/`prc` raw value); `contentSHA256` is exactly 64 lowercase hex chars; parse splits on `:` with maxSplits 2. Reference: `vreader/Models/DocumentFingerprint.swift`.
- `contracts/identity/locator.md` — per-field classification of `Locator` + the persisted `VReaderLocator` envelope: **canonical** (`bookFingerprint`, `href`, `progression`, `totalProgression`, `page`, `charOffsetUTF16`, `charRangeStart/EndUTF16`, `textQuote`, `textContextBefore/After`, `legacyLocator`, `schemaVersion`), **platform-local** (`engine` — exactly two persisted cases, `epubWKWebView` and `readium`), **platform-local → lossy-fallback** (`cfi`, `readiumLocatorJSON`). Cross-platform resume rule: resolve by `fingerprintKey` → try the precise anchor → fall back to `progression` + `textQuote`/context, degraded never lost.
- `contracts/identity/cache-key.md` — `ChapterTranslationRecord.lookupKey = [book, unit, lang, prompt].joined("|")`; `providerProfileID` is provenance, NOT identity (iOS bug #342).
- `contracts/identity/backup-format.md` — global `kBackupCurrentSchemaVersion = 3`; every section JSON is a versioned envelope; `library-manifest.json` carries its own schema **1**; `positions` entries hold `locatorJSON` for a **plain `Locator`** (never the `VReaderLocator` envelope); pre-v3 sections are byte-identical across v1/v2/v3 (v2 added `reading-history.json` feature #58; v3 added `ai-conversations.json` feature #89).
- `contracts/identity/DECISION.md` — the Spike-A decision record (see below).
- `contracts/vectors/` — golden vectors, derived data only: `fingerprint.json` (`vectors` + `invalid` arrays), `cache-key.json`, `locator.json` (includes a shared NFD vector), `backup-sections.json` (`schemaVersion` 3, `manifestSchemaVersion` 1, one representative canonical JSON per section — landed with Android feature #113 WI-3).
- `contracts/conformance/run.sh` — drives BOTH platforms against the same vectors and prints one `CONFORMANCE RESULT: PASS|FAIL` line.
- Kotlin implementation (the shared `android/identity` module — the SAME code the Android app consumes, not a standalone reference; feature #106 WI-2 / Gate-2 H1): `Identity.kt` (`Identity.canonicalKey/parseCanonicalKey/isValidSHA256/lookupKey`, `CanonicalLocator.canonicalJson`), `Locator.kt` (`@Serializable data class Locator` with `validate()`, `repairedForCanonicalization()`, `canonicalJson()`), `VReaderLocator.kt` (`ReaderLocatorEngine` enum + the envelope), `DocumentFingerprint.kt` (streams 64KB chunks, tees into the destination sink so the bytes hashed are exactly the bytes stored), `backup/BackupSchema.kt` (`CURRENT_SCHEMA_VERSION = 3`, `ACCEPTED_SCHEMA_VERSIONS = {1,2,3}`, `MANIFEST_SCHEMA_VERSION = 1`, `BackupRestoreError` sealed class), `backup/BackupSections.kt` + `BackupSectionsExtended.kt` + `BackupMetadata.kt` + `BackupDefaultsValue.kt` + `BackupJson.kt` (DTOs).
- Swift conformance: `vreaderTests/IdentityConformanceTests` and `vreaderTests/Contracts/BackupConformanceTests.swift`; Kotlin conformance: `android/identity/src/test/kotlin/vreader/contracts/IdentityConformanceTest.kt` + `backup/BackupConformanceTest.kt` (+ `BackupSectionsTest.kt`, `BackupSectionsExtendedTest.kt`).

## The Spike-A decision (`DECISION.md`, in one line)

Exact-match for native fingerprint + cache-key + the engine-neutral `Locator.canonicalJSON`; **source-bytes (not converted-EPUB) for converted-Kindle (`.azw3`/`.mobi`/`.prc`) cross-platform identity**; CFI is lossy-fallback (resume on progression + text quotes). No global normalization layer — the only platform-local seams are iOS's converted-EPUB fingerprint (a local storage detail under `kindleConvertOnImport`) and CFI, both with defined fallbacks. The planned Android-NDK libmobi byte-identity harness was deliberately NOT built: choosing source-bytes made cross-platform conversion byte-identity moot. The iOS source-bytes implementation gap was tracked as feature #108 (VERIFIED per `docs/features.md`).

## Canonical Locator serialization rules (both platforms MUST apply)

Sorted keys; nil omission; `bookFingerprint` triple inlined with prefix (`bookFingerprint.contentSHA256` etc.); floats POSIX/US-locale `%.6f`; `\r\n`/`\r` → `\n`; RFC-8259 escaping (control chars → `\uXXXX`); **Unicode NFC normalization of every string field** (bug #356 — Swift `precomposedStringWithCanonicalMapping`, Kotlin `java.text.Normalizer.normalize(_, NFC)`; iOS hands back NFD on some text paths). **Non-finite `progression`/`totalProgression` should be rejected before canonicalization** — `Locator.validate()` → `nonFiniteProgression` — but the two canonicalizers diverge when called directly on unvalidated input: Kotlin's `CanonicalLocator.canonicalJson` (`Identity.kt:90-91`) `require(...)`s and throws on a non-finite value, while Swift's `canonicalJSON()` (`Locator.swift:128-136`) does NOT reject — it silently OMITS a non-finite `progression`/`totalProgression` (`if let progression, progression.isFinite`) rather than throwing. Silent omission would let an invalid locator canonicalize identically to a valid missing-progression one, so on iOS `Locator.validate()` is a REQUIRED precondition before calling `canonicalJSON()` directly; Kotlin enforces the same invariant internally instead. This is a known cross-platform gap, not exact non-finite-handling parity — a caller that skips iOS-side validation and one that skips Kotlin-side validation observe different behavior for the same invalid input. iOS additionally repairs at every persistence boundary via `Locator.repairedForCanonicalization()` (feature #109 WI-2) and re-derived 18 persisted profileKey/locatorHash sites via the flag-gated `LocatorKeyBackfillMigration` launch backfill. Validation invariants (do not strengthen): non-negative `page`/offsets, range endpoints paired with `start ≤ end`, progressions finite (NOT required to be 0…1). See [[Module — locator]] for the iOS side.

## Conformance lane data flow

`contracts/conformance/run.sh [both|kotlin|swift]`:
1. Clears stale `contracts/conformance/.out/` FIRST (bug #355 Gate-4 — a suite that fails to re-emit must not false-pass the byte-diff).
2. Kotlin: `cd android && ./gradlew :identity:cleanTest :identity:test --no-daemon` (the `cleanTest` forces a re-run — Gradle's UP-TO-DATE skip would leave `.out/*.txt` unwritten, bug #355). The `:identity` build injects `vreader.vectors.dir` pointing at `contracts/vectors/`; a missing JDK 17 (default `JAVA_HOME=/opt/homebrew/opt/openjdk@17/...`) is a HARD FAIL, not a silent skip (Codex Gate-4 High — fail-open guard).
3. Swift: `scripts/run-tests.sh vreaderTests/IdentityConformanceTests` on the iPhone 17 Pro simulator.
4. Cross-diff: byte-diffs `.out/swift-locator.txt` vs `.out/kotlin-locator.txt` and `swift-cachekey.txt` vs `kotlin-cachekey.txt` — the DIRECT Swift-vs-Kotlin check bug #355 asked for, on top of the transitive both-vs-vector assertions.

Backup conformance is **semantic equality** (decode each vector section into the platform DTO, re-encode, compare PARSED JSON — key order/whitespace/number formatting insignificant); proven identity-bearing details: ISO8601-UTC dates (Swift `.iso8601` / Kotlin `IsoInstantSerializer`), base64 `Data` (`Base64DataSerializer`), omitted nil optionals (Swift `Codable` / Kotlin `explicitNulls=false`), the type-tagged `BackupDefaultsValue` `{type,value}` union, valid-UUID id fields (iOS strict `UUID`, Kotlin `String`).

## Versioning, pinning, legal (binding rules)

- **Contract merge gate is versioned**: a *breaking* change (serialized shape/identity of existing data) requires BOTH platforms green before merge + a migration note; *additive/backward-compatible* merges with ONE platform green + a filed parity obligation + updated vectors. Every contracts-touching PR updates the affected vectors and notes the level; `contracts/` paths route through the Codex audit gate (`.claude/hooks/lib/code-paths.sh`).
- **Tool-version pinning**: vectors that depend on a producing tool record `MobiEPUBConverter.version` / libmobi / Readium versions; a mismatch is a determinism failure ONLY when tool versions match. Converted-Kindle canonical vectors are converter-independent (source bytes) and need no such pin.
- **Legal**: vectors contain derived data only (hashes, serialized locators, key strings, schema shapes) — NEVER Kindle/copyrighted source bytes; the source corpus stays in the gitignored `test-books/`. A `contracts/` PR adding raw book bytes is a defect.
