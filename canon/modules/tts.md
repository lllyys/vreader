# Module — TTS

## Purpose

Read-aloud for books: an on-device `AVSpeechSynthesizer` path and an HTTP cloud-TTS path (Azure or custom REST endpoint) behind one state machine, with per-format text sourcing, sentence highlight + auto-scroll on TXT/MD, a bottom control bar (play/pause/stop/speed), and a deterministic XCUITest mock so verification never needs a real audio session. Feature #26 (base TTS, VERIFIED), #57 (AZW3/MOBI via Foliate extraction, VERIFIED), #72 (cloud provider wiring, VERIFIED).

## Key files and types

- `vreader/Services/TTS/TTSService.swift` (308 lines) — `@MainActor @Observable final class TTSService: NSObject`. The state machine: `enum State { idle, speaking, paused }`, `currentOffsetUTF16`, `rate` (computed get/set over `_rate`, clamped 0.0–1.0 — Bug #226 / GH #910: an `@Observable` `didSet` that self-assigns recurses to stack overflow). `startSpeaking(text:fromOffset:)` trims/validates, sets `AVAudioSession` category `.playback` with `.duckOthers` (bug #96), aligns a UTF-16 offset landing inside a surrogate pair forward, and speaks the substring. `static func extractText(from source: some ReflowableTextSource, startOffset: Int) -> String`. Conforms to `AVSpeechSynthesizerDelegate` (nonisolated callbacks hop to MainActor via `Task { @MainActor in … }`).

Wired from `SettingsView`'s Reading section (`NavigationLink { HTTPTTSSettingsView() }`, a11y id `settingsHTTPTTS`); form fields for endpoint/API key/voice/provider type (`.azure`/`.custom`)/Azure region/custom headers+body template, saved to `UserDefaults` key `httpTTSConfig` and Keychain account `com.vreader.httpTTS.apiKey`.
- `vreader/Services/TTS/HTTPTTSChunkPlayer.swift` (237 lines) — `@MainActor final class HTTPTTSChunkPlayer` (feature #72 WI-2). Sequential audio-chunk queue: one player per chunk behind `@MainActor protocol SpeechAudioPlaying` (prod `AVAudioPlayerBox` wrapping `AVAudioPlayer`); streaming `enqueue(_:)` + `markInputComplete()`; generation token invalidates late finishes; `onFinished` fires only when the queue drains AND input is complete, at most once (`completionDelivered`); unsuccessful chunk finish routes to `onError`, not a silent advance.
- `vreader/Services/TTS/HTTPSpeechSynthesizer.swift` (275 lines) — `final class HTTPSpeechSynthesizer: NSObject, SpeechSynthesizing, @unchecked Sendable` (feature #72 WI-3): the adapter that finally wired the orphaned `HTTPTTSProvider` (Bug #270) into live playback. Chunks the utterance via `HTTPTTSProvider.chunkText`, computes each chunk's `NSRange` in the ORIGINAL text via `static func chunkRanges(in:chunks:)` (forward `range(of:)` scan — trimmed chunks must not drift offsets), synthesizes per chunk in a `synthTask` (generation-guarded), and emulates delegate callbacks (`willSpeakRange` per chunk start, `didFinish` on drain, `didCancel` on stop/failure) against a throwaway `probeSynth` AVSpeechSynthesizer. Pause during the initial network window buffers chunks (`wantsPaused`/`bufferedChunks`). Audio session is owned by `TTSService`, never touched here.
- `vreader/Services/TTS/XCUITestMockSpeechSynthesizer.swift` (257 lines, `#if DEBUG`) — synthetic delegate timeline via a single self-rescheduling `DispatchQueue.main.asyncAfter` tick (0.5 s × up to 60 slices ≈ 30 s), which genuinely suspends while paused; generation counter kills stale ticks.
- `vreader/Services/TTS/TTSHighlightCoordinator.swift` — `@MainActor final class TTSHighlightCoordinator` (features #40/#41): maps `currentOffsetUTF16` to a sentence `NSRange` via `NLTokenizer(unit: .sentence)` (binary search over cached ranges), sets `TextReaderUIState.highlightRange` + `scrollToOffset`. TXT/MD only; lazy `ensureConfigured(text:)` defers the O(n) tokenization to first TTS use.
- `vreader/Views/Reader/TTSControlBar.swift` — bottom bar (`ttsPlayPauseButton`, `ttsStopButton`, speed slider 0.0–1.0), visible only when `ttsService.state != .idle`; mounted in `ReaderContainerView` (bug #97: bottom overlay hides while TTS bar shows).
- `vreader/Views/Reader/TTSTextSource.swift` — `enum TTSTextSource` (feature #57), pure decision logic: `.foliateExtraction` for `.azw3`, `.fileLoad` for `.txt/.md/.pdf/.epub`; `shouldStartExtraction(extractionInFlight:cachedText:)` is the duplicate-walk gate.
- `vreader/Views/Reader/ReaderContainerView+Sheets.swift` — `startTTS()` / `speakLoadedText(ai:)` / `startAZW3TTS(ai:)`: the per-format feeding path.
- `vreader/Views/Reader/ReadiumTTSFollowMapper.swift` (169 lines) — `struct ReadiumTTSFollowMapper: Sendable, Equatable` (feature #42 WI-10b). Pure mapper for the Readium EPUB host: builds a per-spine offset table from the SAME concatenation `TTSService` reads (`EPUBTextExtractor.stripHTML` + trim, skip-empty spines, joined with `"\n\n"`), then `locate(offset:)` maps a flat `currentOffsetUTF16` back to `(spine href, intra-spine fraction)` (clamping out-of-range offsets to the nearest valid position); `shouldFollow` throttles navigation to a spine change or an intra-spine fraction drift past `fractionThreshold`.
- `vreader/Views/Reader/ReadiumEPUBHost+TTSFollow.swift` (162 lines) — wires the mapper into the live Readium EPUB host: while TTS state is `.speaking` and a mapper is built for the open book, observes `currentOffsetUTF16`, resolves the mapper's target through `ReadiumEPUBReaderViewModel.readiumLocator(fromVReader:spineHrefs:)`, and drives `navCommander.navigate(to:)` so the navigator auto-advances to keep the spoken spine on screen — the Readium-EPUB analog of the TXT/MD `TTSHighlightCoordinator.scrollToOffset` and the Foliate AZW3 host's own JS auto-scroll.

## Data flow

0. Settings → Reading → "HTTP TTS" opens `HTTPTTSSettingsView`, which writes endpoint/API key/voice/provider config to `UserDefaults`/Keychain — the config `HTTPTTSConfigStore.loadValidConfig()` reads back at step 4. 1. More-menu "Read aloud" (or DEBUG `.debugBridgeTTSCommand`) → `startTTS()`; toggle-off if not idle. 2. Text source: cached `ai.loadedTextContent` fast path → else `TTSTextSource.source(for:)` routes AZW3 to the Foliate WKWebView walk (three-layer idempotency: playing / in-flight task / cached) and TXT/MD/PDF/EPUB to file load. 3. `TTSService.startSpeaking(text:, fromOffset: ai.currentLocator?.charOffsetUTF16 ?? 0)`. 4. `TTSService.defaultSynthesizer(configStore:)` picks XCUITest mock (DEBUG override) → `HTTPSpeechSynthesizer` (valid `HTTPTTSConfig`) → `SystemSpeechSynthesizer`. 5. Delegate `willSpeakRange` advances `currentOffsetUTF16` (= `baseOffsetUTF16` + location); `TTSHighlightCoordinator.updateHighlight(offset:)` paints the sentence + scrolls (TXT/MD). 5b. For the Readium EPUB host, `ReadiumEPUBHost+TTSFollow` observes the same `currentOffsetUTF16`, maps it via `ReadiumTTSFollowMapper.locate(offset:)` to a (spine href, intra-spine fraction), and throttle-drives `navCommander.navigate(to:)` so the navigator auto-advances to the spoken spine. 6. Selection speaking: `speakSelection: { ttsService.startSpeaking(text: $0, fromOffset: 0) }` in `ReaderContainerView`.

## Concurrency

`TTSService` is `@MainActor`; the `SpeechSynthesizing` protocol is deliberately NOT `@MainActor` — `HTTPSpeechSynthesizer` bridges with `MainActor.assumeIsolated` (its only caller is the `@MainActor` service). Restart cancels are counted, not inferred: `pendingRestartCancels` is armed from `stopSpeaking()`'s Bool result (state lags the backend via Task hops — Gate-4 round-2 H1); a `didCancel` with no pending restart is terminal (external stop OR cloud failure) and returns the machine to idle — feature #72 C5 fixed the bar wedging in `.speaking` with no audio. Generation counters guard: `TTSService.currentGeneration`, `HTTPSpeechSynthesizer.synthGeneration`, `HTTPTTSChunkPlayer.generation`, the mock's `generation`.

## Edge cases and invariants

- Empty/whitespace-only text: no-op, stays idle. Negative offset clamps to 0; offset ≥ UTF-16 length: no-op; offset inside a surrogate pair aligns forward.
- Rate always clamped to 0.0…1.0; `stop()` deactivates the audio session with `.notifyOthersOnDeactivation` (bug #96 audit).
- Cloud path: a fresh `HTTPTTSProvider` per `speak` (`cancel()` is sticky — Gate-2 H4); pause honored during the pre-first-chunk network window (Gate-4 r1 H1); drain ≠ complete for streamed chunks (Gate-4 r1 H2); an unlocatable chunk gets a zero-length range at the previous scan point so highlight never jumps wrong (Gate-2 H3).
- CJK: chunker recognizes fullwidth terminators `。！？`; `NLTokenizer` handles CJK/Latin/mixed sentence boundaries.
- AZW3 extraction: task cancelled in `ReaderContainerView.onDisappear` so a late walk completion can never speak after the reader closed (feature #57); post-await re-checks state/cache/cancellation; extraction result also feeds `ai.refreshChatContext()` (feature #86 WI-1).
