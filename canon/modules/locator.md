# Module — locator

## Purpose

`Locator` is vreader's universal reading-position/range model: one value type that can point into any book format. EPUB positions use `href + progression` (plus an optional CFI), PDF uses a zero-based `page`, and TXT/MD use UTF-16 character offsets (`charOffsetUTF16`, `charRangeStartUTF16`/`charRangeEndUTF16`). Every book-anchored feature — reading-position persistence, bookmarks, highlights, TOC entries, search-result navigation, backup/sync identity — is expressed as a `Locator` bound to a `DocumentFingerprint`. The `vreader/Services/Locator/` directory holds the math around the model: creation with quote/context extraction (`LocatorFactory`), format-independent normalization (`LocatorNormalizer`), and stale-anchor restoration (`LocatorRestorer`, backed by `QuoteRecovery` from `vreader/Utils/`).

## Key files and types

- `vreader/Models/Locator.swift` — `struct Locator: Codable, Hashable, Sendable`. Only `bookFingerprint: DocumentFingerprint` is non-optional; the format decides which of the other fields apply (EPUB: `href`/`progression`/`totalProgression`/`cfi`; PDF: `page`; TXT/MD: the three UTF-16 offset fields; all formats: `textQuote`/`textContextBefore`/`textContextAfter` reflow anchors). `validate() -> LocatorValidationError?` rejects negative pages/offsets, an inverted or half-specified UTF-16 range, and non-finite progressions; `static func validated(...) -> Locator?` is the nil-on-invalid constructor everything else funnels through. `canonicalJSON()` emits deterministic JSON (sorted keys, nil omission, `%.6f` floats in `en_US_POSIX`, `\r\n`/`\r` → `\n`, RFC-8259 escaping incl. `\u%04x` control chars) and `canonicalHash` is its SHA-256 hex — the dedupe/sync key. String fields are NFC-normalized (`precomposedStringWithCanonicalMapping`) before escaping (feature #109 / bug #356) so NFD-vs-NFC input and the Kotlin `CanonicalLocator` reference hash identically. `repairedForCanonicalization()` nulls non-finite progressions so pre-#109 invalid persisted locators are repaired (keep-both policy) during the launch-time key-recompute backfill and backup restore.
- `vreader/Models/DocumentFingerprint.swift` — content identity: SHA-256 (64 lowercase hex, validated) + `fileByteCount` + `BookFormat`; `canonicalKey` = `"{format}:{contentSHA256}:{fileByteCount}"`, parseable back via `init?(canonicalKey:)`.
- `vreader/Services/Locator/LocatorFactory.swift` — stateless `enum LocatorFactory` with per-format factories, all delegating to `Locator.validated`: `epub(fingerprint:href:progression:totalProgression:cfi:...)`, `pdf(fingerprint:page:...)`, `txtPosition(fingerprint:charOffsetUTF16:totalProgression:sourceText:)`, `txtRange(...)`, `txtChapterRange(fingerprint:chapterLocalStart:chapterLocalEnd:chapterText:chapterGlobalStart:)` (translates chapter-local offsets to global via `chapterGlobalStart`), and `mdPosition`/`mdRange` aliases that reuse the TXT logic on rendered text. When `sourceText` is supplied, the TXT factories auto-extract a quote + surrounding context via `extractContext(from:at:length:windowSize:)` — constants `contextWindowSize = 50` and `defaultQuoteLength = 30` UTF-16 code units. Substring math uses `String.Index(utf16Offset:in:)` so extraction is surrogate-pair/boundary safe.
- `vreader/Services/Locator/LocatorNormalizer.swift` — `struct CanonicalPosition: Codable, Sendable, Equatable` wraps a format-independent `progression: Double` (0–1) plus the original `nativeLocator` and quote/context. `LocatorNormalizer.toCanonical(_:format:)` takes `totalProgression` (nil → 0.0) clamped to [0.0, 1.0]; `fromCanonical(_:toFormat:totalLengthUTF16:)` returns `nativeLocator` directly for a lossless round-trip.
- `vreader/Services/Locator/LocatorRestorer.swift` — `enum RestorationStrategy: String` (`cfi`, `hrefProgression`, `quoteRecovery`, `pageIndex`, `utf16Offset`, `failed`) and `struct RestorationResult` (resolved offset/page/href/progression + `QuoteConfidence?`). Fallback chains: `restoreEPUB` tries non-empty CFI pass-through → `href`+`progression` (href must be in `spineHrefs`) → quote recovery; `restorePDF` tries `page` (0-indexed, `< totalPages`) → quote recovery; `restoreTXT` tries `charOffsetUTF16` (0...text length) → the char range → quote recovery.
- `vreader/Utils/QuoteRecovery.swift` — `QuoteRecovery.findQuote(quote:contextBefore:contextAfter:in:)` searches exact → context-disambiguated → case-insensitive → whitespace-normalized, returning `QuoteRecoveryResult` (match range + UTF-16 offset + `QuoteConfidence` `.exact`/`.contextMatch`/`.fuzzy`). Context scoring counts matching chars adjacent to each candidate (`contextBeforeScore`/`contextAfterScore`); whitespace-normalized matches are mapped back to original-text ranges.
- `vreader/Services/Unified/PaginationCache.swift` — the sole file in `Services/Unified/`: an in-memory (never persisted) cache for the Unified TXT-reflow engine's TextKit 2 pagination. `PaginationCacheKey` embeds every layout-affecting parameter (`documentFingerprint`, `fontSize`, `fontName`, `lineSpacing`, `viewportWidth`, `viewportHeight`); values are `[PaginationCachePage]` — lightweight `(pageIndex, charLocation, charLength)` character-range descriptors, no text. `invalidate(documentFingerprint:)` drops all entries for a document regardless of rendering params.

## Dependencies

Internal: `DocumentFingerprint` and `BookFormat` (Models). No UIKit/SwiftUI — the Locator layer is pure Foundation (+ CryptoKit for `canonicalHash`). Consumers reach it directly (no protocol seam): `EPUBReaderViewModel.swift:204` (`LocatorFactory.epub`), `PDFReaderViewModel.swift:237` (`.pdf`), `MDReaderViewModel.swift:267` (`.mdPosition`), `TXTService.swift:391` (`.txtPosition`), `TXTReaderContainerView.swift` (`.txtRange`/`.txtChapterRange` for highlight creation), `TOCBuilder.swift` (TOC-entry locators), and `Services/Search/SearchHitToLocatorResolver.swift` (search-hit → Locator). `QuoteRecovery` is also used by `vreader/Views/Reader/EPUBHighlightJS.swift`. The "what the Unified service unifies" answer: `PaginationCache` is consumed by `UnifiedTextRenderer.swift`/`UnifiedTextRendererViewModel.swift` (roadmap WI-B04/B05, cache added as B13) — the one TextKit 2 renderer that serves both scroll and paged modes for plain and attributed text; `FormatCapabilities.unifiedReflow` gates it per format (MD, simple EPUB, AZW3 — TXT was gated out by bug #158 / GH #468, and `capabilities(for:isComplexEPUB:)` never grants it to PDF).

## Data flow

Selection/position events in a format bridge → the format's ViewModel/container builds a `Locator` via `LocatorFactory` → persisted through `PersistenceActor` (see [[Module — persistence and data model]]; `ReadingPosition`, `Highlight`/`Bookmark` anchors — see [[Module — annotations and highlights]]). Navigation runs the other way: a TOC/bookmark/search-result tap posts `.readerNavigateToLocator` (`Notification.Name("vreader.readerNavigateToLocator")`, object = the `Locator`) and each format container consumes the fields it understands ([[Architecture — notification bus]]); position changes post `.readerPositionDidChange` with the current `Locator`. For the Readium EPUB engine (feature #42), the persisted `VReaderLocator` envelope carries an authoritative `readiumLocatorJSON` plus a lossy legacy `Locator` leg (SchemaV8 `ReadingPosition.vreaderLocatorData`). Cross-platform, `Locator.canonicalJSON()` is the contract the Kotlin `:identity` module's `CanonicalLocator` must reproduce byte-for-byte ([[Module — cross-platform contracts]]).

## Edge cases and invariants

- UTF-16 range endpoints must be both present or both absent, and `start <= end` — enforced by `validate()` (`.invertedUTF16Range`); `LocatorFactory.txtRange` skips context extraction for an inverted range and lets `validated()` reject it.
- `txtChapterRange` returns nil for `chapterLocalStart < 0`, `chapterGlobalStart < 0`, an inverted range, or `chapterLocalEnd > chapterText.utf16.count`.
- `extractContext` clamps offset and window to the text; an at-or-past-end offset with nonzero length yields context-before only; empty strings collapse to nil (`nonEmpty`).
- TXT offsets are UTF-16 code units over the raw decoded source, before display transforms (Locator.swift header) — the alignment contract the search index's decode-version machinery exists to protect.
- `QuoteRecovery.allRanges` deliberately skips overlapping matches (advances by `upperBound`); when multiple exact matches exist, confidence degrades from `.exact` to `.contextMatch` even without context (first-match fallback is not "exact").
- Canonical JSON must never contain NaN/infinity — `validate()` rejects non-finite progressions and `canonicalJSON()` additionally guards `isFinite` before emitting them.
- `LocatorRestorer` and `LocatorNormalizer` currently have no production call sites outside their own files — their consumers are tests (`vreaderTests/Services/Locator/LocatorRestorerTests.swift`, `LocatorNormalizerTests.swift`, `vreaderTests/Integration/LocatorIntegrationTests.swift`, `ModeSwitchPersistenceTests.swift`, `MDIntegrationTests.swift`, `TXTBridgeOffsetTests.swift`). The restoration chains are library code awaiting/backing integration paths, not live reader wiring.
- `TOCProviding` (`vreader/Services/TOCProvider.swift:38`) has no production or test conformers and no existential/generic consumer anywhere in the codebase — `TOCEntry` locators are produced directly by `TOCBuilder.swift`, which does not implement or reference the protocol; only `TOCProviderTests.swift`'s header comment mentions it. It is a dead-code candidate: flag for removal, or document a concrete reason to keep it as reserved-but-unimplemented if one exists.

## History

- Roadmap origins: `Locator` landed with WI-1 (commit `42db959a`, data models/fingerprint/schema baseline); `LocatorFactory` with WI-5 (`6ad33a19`, locator & fingerprint integration spike); the search-to-locator slice was WI-8A (`e2a71332`).
- Feature #109 / bug #356: NFC canonicalization of string fields + the launch-time `LocatorKeyBackfillMigration` (a one-shot key-recompute backfill — the shape-identical SwiftData migration stage never fired, so #109 runs outside the migration plan) and `repairedForCanonicalization()` for cross-platform hash parity with the Kotlin `CanonicalLocator`.
- Bug #182 / GH #621: search snippets fed raw (`...`/`<b>`-bearing) into `textQuote` broke plain-text matchers — fixed in the search resolver (see [[Module — search]]).
- Bug #154 / GH #443 and bug #312 shaped locator *consumption* in `ReaderNotificationHandlers.swift`: `highlightNonce` (re-navigation to the already-current target must still re-paint) and `scrollSnapToTop` (TOC/chapter point jumps pin to top; search-hit ranges keep ~0.25 viewport headroom).
- Bug #158 / GH #468 removed `.unifiedReflow` from TXT (Unified renderer truncated at ~12 lines, dropped bottom chrome, bypassed the chapter detector); the regression guard is `only_md_epub_azw3_supportUnifiedReflow_simpleEPUB`.
