# Module — annotations and highlights

## Purpose

vreader has three per-book annotation record kinds: **highlights** (`HighlightRecord` — an anchored passage with color and optional note), **standalone notes** (`AnnotationRecord` — a note at a locator, no anchored passage), and **bookmarks** (`BookmarkRecord`). This module covers their list view models, the reader's two annotation sheets (feature #62 split the old unified panel into `TOCSheet` = "leave the current page" and `HighlightsSheet` = "revisit reading"), the cross-format highlight-action popover VM (feature #64), delete/edit/copy row affordances (bug #249), and JSON export (feature #35).

## Key files and types

View models (`vreader/ViewModels/`, all `@Observable @MainActor`):

- `HighlightListViewModel.swift` — `highlights: [HighlightRecord]` newest-first; `loadHighlights()`, `addHighlight(locator:selectedText:color:note:)` (upsert — skips insert if the store returned an existing id), `removeHighlight(highlightId:)`, `updateNote`, `updateColor`; out-of-bounds detection: `outOfBoundsHighlightIds` = highlights whose `locator.charRangeEndUTF16 > totalTextLengthUTF16`.
- `AnnotationListViewModel.swift` — `annotations: [AnnotationRecord]`; `loadAnnotations()`, `addAnnotation(locator:content:)` / `updateAnnotation(annotationId:content:)` (both reject empty trimmed content with "Annotation content cannot be empty."), `removeAnnotation(annotationId:)`.
- `BookmarkListViewModel.swift` — `bookmarks: [BookmarkRecord]`; `addBookmark(locator:title:)` (upsert), `removeBookmark`, `updateTitle`, `isBookmarked(at:)`, and `toggleBookmark(locator:title:)` which matches on `profileKey = "\(locator.bookFingerprint.canonicalKey):\(locator.canonicalHash)"` for idempotent add/remove.
- `HighlightPopoverViewModel.swift` — feature #64 WI-1: consumes a `ReaderHighlightTapEvent`, resolves the record via the `HighlightLookup` protocol, publishes `presented: HighlightPopoverContent?` and `presentedInitialMode: HighlightPopoverMode` (`.editing` when the event carried `openInEditMode` — GH #1121, the Bug #249 follow-up). Supersedes feature #55's `NotePreviewViewModel`.

Persistence boundary (`vreader/Services/`): `HighlightPersisting.swift`, `AnnotationPersisting.swift`, `BookmarkPersisting.swift`, `HighlightLookup.swift` (narrow read-only `highlight(withID:forBookWithKey:)`, book-scoped so a lookup cannot leak another book's highlight) — all `Sendable` protocols; production conformer is `PersistenceActor` via `PersistenceActor+Highlights.swift` / `+Annotations.swift` / `+Bookmarks.swift` ([[Module — persistence and data model]]). `HighlightPersisting` has both a legacy `addHighlight(locator:...)` and an anchor-aware `addHighlight(locator:anchor:...)` taking `AnnotationAnchor?`.

Review sheet (`vreader/Views/Reader/Annotations/`):

- `HighlightsSheet.swift` + `HighlightsSheet+Delete.swift` / `+Export.swift` / `+Support.swift` — the All / Highlights / Notes / Bookmarks unified card stream in `ReaderSheetChrome` titled "Annotations", with per-filter count badges and one trailing export button. Its `.task` builds a `PersistenceActor(modelContainer:)` and loads both a `HighlightListViewModel` (with `totalTextLengthUTF16: nil`) and an `AnnotationListViewModel`.
- `AnnotationStreamItem.swift` — `enum AnnotationStreamItem { case highlight(HighlightRecord); case standalone(AnnotationRecord) }`; `id` projects `highlightId`/`annotationId`; `isNote` is true for any standalone and for highlights with a non-empty note (an empty-string note is NOT a note).
- `AnnotationStreamBuilder.swift` — pure `enum`: `stream(highlights:annotations:filter:)` (newest-first by `createdAt`, tie-broken by id then `kindRank` for a total order) and `counts(...)` pinned to the #860 design: `all = h + a`, `notes = a + h.filter{note non-empty}`, `bookmarks = 0` always (the real bookmark surface is `TOCSheet`'s Bookmarks tab).
- `NotesRowState.swift` — bug #249 / GH #1080: the sheet-owned row-interaction state machine. `NotesRowPhase`: `default / menuOpen / confirming / deleting / error / swipeRevealed`. Invariant: at most ONE row is non-default (`activeRowId` + `phase`); a nil row id always pairs with `.default`. The design's `dim-after-delete` transient is deliberately not modelled (the VM removes the record from its array, so the row leaves the stream immediately).
- `NotesDeleteRow.swift` / `NotesActionMenu.swift` (incl. `NotesMoreButton`) / `NotesDeleteConfirm.swift` (incl. `NotesRowError` with Retry + Undo) / `NotesSwipeResolver.swift` — the ⋯ menu, inline confirm strip, swipe drawer chrome.
- `HighlightAnnotationCard.swift` (`HighlightCardV3`) and `StandaloneNoteCard.swift` — the two card renderers; meta line is `chapter · p. N` via `metaLabel(for:)` in `+Support.swift`, backed by `chapterTitle(for:)`: for `charOffsetUTF16` (TXT/MD) or `page` (PDF) it's the last `tocEntries` entry at/before the locator, but for `href` (EPUB) it's exact-equality only (the LAST exact-duplicate entry wins; no nearest-preceding/spine-order fallback) — an EPUB locator with no exact TOC-href match gets no chapter label at all; page shown 1-based.
- `HighlightEditHandoff.swift` — GH #1121 (Bug #249 follow-up) pure routing: a highlight maps to `.requestHighlightEdit(ReaderHighlightEditRequest)` (posted as `.readerHighlightEditRequested`), a standalone note to `.openStandaloneNote` (WI-3, not yet wired).
- `AnnotationsSheetRoute.swift` — `enum AnnotationsSheetRoute { case toc(initialTab: TOCSheetTab); case highlights(initialFilter: HighlightsSheetFilter) }` drives `ReaderContainerView`'s single `.sheet(item:)`; `id` is the full payload so re-presenting the same sheet on a different tab works. Chrome routing: Contents button → `.toc(.contents)`, Notes button → `.highlights(.all)`; More-menu `.presentAnnotationsExport` → `.highlights(.highlights)`.
- `TOCSheet.swift` (+ `TOCSheetRows`, `TOCSheet+Support`, `TOCSheet+Filter`, `TOCFilterField`, `TOCTitleFilter`) — Contents + Bookmarks 2-tab sheet; owns its own `BookmarkListViewModel` in `.task` so the Bookmarks count badge is live on appear; feature #94 adds the Contents title filter; bug #248 restored auto-scroll of the active chapter; bug #313 r2 adds `spineHrefs` fallback matching.
- `AnnotationsEmptyStateView.swift` / `AnnotationsEmptyStateArt.swift` — shared per-filter empty states, gated on load-completed flags so an in-flight load never flashes a false empty state.

Legacy editors (`vreader/Views/Annotations/`): `AddNoteSheet.swift` (bug #49 multi-line note input; Save disabled while trimmed text is empty; used by TXT/MD containers) and `AnnotationEditSheet.swift` (retained un-wired since feature #62 deleted its only caller, `AnnotationListView`).

## Data flow

- **Create**: most per-format reader containers call the anchor-aware `addHighlight` (callers include `EPUBReaderContainerView+Highlights.swift`, `PDFReaderContainerView+Highlights.swift`, `HighlightCoordinator.swift`, `FoliateSpikeView+Selection.swift`); `ReaderNotificationHandlers.swift`'s TXT/MD selection handler still calls the legacy `addHighlight(locator:selectedText:color:note:)` overload (no anchor) — see [[Architecture — reader dispatch and format hosts]].
- **Popover**: reader posts `.readerHighlightTapped`; `HighlightPopoverViewModel.handleTap(_:chapter:)` resolves via `HighlightLookup` and publishes content built by `HighlightPopoverPresenter.content(for:sourceRect:chapter:)`; `refreshPresented(with:)` rebuilds after a recolor/note-save while keeping the anchor rect.
- **Delete** (bug #229 / GH #938): `HighlightListViewModel.removeHighlight` captures the record's `.epub` anchor CFI BEFORE the persistence delete, then posts `.readerHighlightRemoved` (object = UUID string, bug #78 immediate visual clear) and — only for a non-empty `.epub` CFI — `.foliateRequestAnnotationJSDelete` with `["cfi", "fingerprintKey"]`, because AZW3/MOBI highlights are Foliate-js SVG overlays keyed by CFI, not UUID ([[Module — Foliate AZW3 reader]]). All names live in `vreader/Views/Reader/ReaderNotifications.swift` ([[Architecture — notification bus]]).
- **Sheet delete UX**: `confirmDelete(_:)` flips the row to `.deleting`, awaits `performDelete` through the loaded VM, and treats `vm.errorMessage == nil` as success; failure shows `NotesRowError`.
- **Edit handoff**: the menu's Edit dismisses the sheet, calls `onNavigate(record.locator)`, then posts `.readerHighlightEditRequested` so the mounted `HighlightPopoverModifier` auto-opens the card in editing mode (GH #1121, the Bug #249 follow-up; single-flight `token: UUID`).
- **Export** ([[Module — export]]): `exportAnnotations()` fetches highlights + bookmarks + notes (per-kind failures degrade to "Exported with warnings"), builds via `AnnotationExporter.buildPayload` / `.export(payload:format: .json)`, writes `annotations-export.json` to the temp dir, and shares via `ShareActivityView`. **Import is retained but UI-unreachable**: `importAnnotationsFrom(url:)` (which drives `AnnotationImporter` and posts `.readerHighlightsDidImport`) is compiled + tested, but the committed #860 design has no import affordance — tracked as needs-design #963, not a silent drop.

## Concurrency

All VMs are `@MainActor`; persistence hops are `await` on `PersistenceActor`. Two explicit race guards: (1) `HighlightPopoverViewModel.latestTapToken` — a monotonic `UInt64` bumped on every `handleTap` and `dismiss`; a lookup publishes only if its captured token is still latest, so the newest tap always wins and a dismissed-then-resolved lookup cannot resurrect the card; (2) `HighlightsSheet.confirmDelete` re-checks `rowState.activeRowId == id && rowState.phase == .deleting` after the await so a delete finishing late cannot clobber an interaction the user started on another row.

## Edge cases and invariants

- Newest-first ordering everywhere; stream sort is a total order (createdAt → uuidString → kindRank).
- Content mutations trim whitespace and reject empty strings (annotations); highlight upserts avoid duplicate ids.
- Out-of-bounds highlights (book text changed) are detected, not deleted — `hasOutOfBoundsHighlights` flags them.
- Deleted-race on tap (highlight removed between paint and tap) resolves to `nil` and is a no-op.
- The Bookmarks chip in `HighlightsSheet` is hard-zero by design; bookmarks live in `TOCSheet`.
- Cards degrade gracefully: no TOC, or (EPUB only) no exact TOC-href match, → no chapter label; EPUB/TXT locators have no page component ([[Module — locator]]).
- Tap-to-jump is suppressed (`jumpEnabled == false`) whenever a row is in any non-default phase.
- DEBUG-only testing hooks (`loadCountsForTesting`, `deleteHighlightForTesting`, `importForTesting`, etc.) return values instead of mutating `@State`, which is not observable outside a render tree.
