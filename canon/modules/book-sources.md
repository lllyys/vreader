# Module — book sources

## Purpose

Legado-compatible web-novel scraping (feature #24). Users import or hand-edit "book sources" — per-site rule sets describing how to search a novel site, extract book metadata, walk a table of contents, and pull chapter text — then search, browse chapters, and read scraped content inside the app. Entry point: Settings → "Book Sources" (`SettingsView` pushes `BookSourceListView`). There are no built-in sources; everything is user-imported.

## Key files and types

- `vreader/Models/BookSource.swift` — SwiftData `@Model final class BookSource`. `@Attribute(.unique) var sourceURL: String` is the primary key (matches Legado's `bookSourceUrl`). The four rule sets are stored as `Data?` JSON blobs (`ruleSearchData`, `ruleBookInfoData`, `ruleTocData`, `ruleContentData`) with `@Transient` computed accessors (`ruleSearch: BSSearchRule?` etc.) that decode via `try? JSONDecoder` — the same crash-safe pattern as `Highlight.anchorData`. `sourceType: Int` uses Legado's convention (0=text, 1=audio, 2=image, 3=file). `compatibilityLevel: String?` is "Full" / "Limited" / "Unsupported". `static func validateSourceURL(_:) -> Bool` rejects empty/whitespace URLs.
- `vreader/Models/BookSourceRules.swift` — `BSSearchRule`, `BSBookInfoRule`, `BSTocRule`, `BSContentRule` (Codable, Sendable, Equatable; all fields optional; `hasAnyField` helpers).
- `vreader/Models/LegadoBookSourceDTO.swift` — flexible decode DTO for Legado JSON (unknown fields ignored).
- `vreader/Services/BookSource/BookSourcePipeline.swift` — `actor BookSourcePipeline`, the four-stage flow: `search` (replaces `{{key}}` in `searchURL`, applies `ruleSearch.bookList` then per-element sub-rules) → `bookInfo` → `chapters` (follows `nextTocUrl` pagination) → `chapterContent` (follows `nextContentUrl`, applies `replaceRegex` cleanup, checks/fills the chapter cache **only if one was injected**). `maxPaginationDepth` defaults to 50. HTTP is injected as `typealias HTMLFetchProvider = @Sendable (URL, [String: String]?) async throws -> String` (in `PipelineTypes.swift`). The initializer's `chapterCache: ChapterCache? = nil` param **defaults to nil**, and none of the three production call sites (`BookSourceSearchView`, `BookSourceChapterListView`, `BookSourceReaderView`, plus `UpdateChecker`) pass one — see Data flow below.
- `vreader/Services/BookSource/PipelineTypes.swift` — `BookSourceSnapshot` (Sendable value mirror of the non-Sendable `@Model`; `parsedHeaders` decodes the `header` JSON string), `BookSearchResult`, `BookDetail`, `ChapterInfo`, `PipelineStage`, `PipelineError` (`.missingSearchRule`, `.invalidURL(String)`, `.emptyContent`, ...).
- `vreader/Services/BookSource/RuleEngine.swift` — stateless dispatcher: `:regex:` prefix → `RegexRuleEvaluator`; `/` or `//` prefix → XPath, detected but **returns empty** (deferred, "D08" in comments); otherwise CSS. `evaluateRawHTML` returns full element HTML for container rules (bookList/chapterList).
- `vreader/Services/BookSource/LegadoRuleParser.swift` — parses Legado syntax `selector@attribute!index` into `ParsedRule` (`RuleType` css/regex/xpath; `!index` supports negative from-end; `@attribute` must be letters/hyphen/underscore).
- `vreader/Services/BookSource/CSSRuleEvaluator.swift` — regex-based pseudo-CSS evaluator over raw HTML (NSRegularExpression, **no SwiftSoup / no DOM parser**). Supports tag, `.class`, `#id`, `tag.class`, and space-separated descendant selectors; explicitly no `>`, `+`, `~` combinators; special-cases 13 self-closing tags.
- `vreader/Services/BookSource/HTMLHelper.swift` — attribute parsing (double/single/unquoted), `stripHTMLTags`, `decodeHTMLEntities` (7 common entities only), `resolveURL` (only for `href`/`src`/`action`/`data` attributes), `applyIndex` (negative = from end).
- `vreader/Services/BookSource/RegexRuleEvaluator.swift` — `extract` (first capture group per match, else full match), `replace` (used for `replaceRegex` content cleanup).
- `vreader/Services/BookSource/BookSourceHTTPClient.swift` — `actor BookSourceHTTPClient`: headless URLSession fetch (never WKWebView), default 30s timeout, per-client rate limiting via `ContinuousClock`, default User-Agent spoofing iPhone Safari with a `VReader/1.0` token; custom per-source headers may override it. `downloadFile(url:to:)` with 4× timeout.
- `vreader/Services/BookSource/WebPageEncodingDetector.swift` — encoding priority: HTTP Content-Type charset → `<meta charset>` scanned in the first 1024 raw bytes (ASCII-safe, avoids the chicken-and-egg decode) → BOM → UTF-8; maps GB2312/GBK → GB18030, Big5, Shift_JIS, EUC-KR, EUC-JP, Latin-1, CP1252, then CF IANA lookup; last-resort lossy UTF-8 decode.
- `vreader/Services/BookSource/ChapterCache.swift` — `actor ChapterCache`, disk LRU for offline chapters at `<directory>/<sourceHash>/<chapterHash>.txt`; `static func hash(for:)` = first 16 bytes of SHA-256 hex (CryptoKit); default cap 500MB with oldest-first eviction; index lazily rebuilt from disk using file mtimes.
- `vreader/Services/BookSource/LegadoImporter.swift` + `LegadoCompatibility.swift` — Legado JSON import/export (accepts single object or array; dedups by URL, first wins; skips empty URLs). `classifyCompatibility`: any rule containing `<js>` or `{{` → "Unsupported"; `//` prefix → "Limited" (XPath); else "Full".
- `vreader/Services/BookSource/SourceSharingService.swift` — single-source export, QR codes via CoreImage `CIQRCodeGenerator`, and the `vreader://import-source?data=<base64 JSON>` scheme (`generateSharingURL` / `parseImportURL`).
- `vreader/Services/BookSource/UpdateChecker.swift` — `actor UpdateChecker`: re-fetches the TOC via a fresh pipeline and returns `UpdateResult(newChapterCount:)` when remote chapter count exceeds `lastKnownChapterCount`; catches pipeline fetch/parse failures and returns nil for those specifically (graceful degradation); per `source|book` key rate limiting. The public signature is still `async throws -> UpdateResult?` — callers must `try` it; "returns nil on fetch/parse errors" describes today's catch behavior, not a non-throwing contract.
- Views (`vreader/Views/BookSource/`): `BookSourceListView` (`@Query(sort: \BookSource.customOrder)`, enable toggle, swipe delete, `.fileImporter` for Legado JSON, share via temp file + `ShareActivityView`, explicit `try? modelContext.save()` per bug #100), `BookSourceEditorView` (plain-text rule fields, no rule validation — "that's the rule engine's job"), `BookSourceSearchView`, `BookSourceChapterListView` (bookInfo first, `tocUrl` falls back to `bookUrl`), `BookSourceReaderView` (MVP plain `Text` in a `ScrollView`).

## Dependencies

Internal: SwiftData directly via `@Environment(\.modelContext)` / `@Query` in the views — this module does **not** route through `PersistenceActor` (see [[Module — persistence and data model]]); `BookSource` + `ContentReplacementRule` joined the schema in `SchemaV4` (`vreader/Models/Migration/SchemaV4.swift`; see [[Architecture — schema migration history]]). External: Foundation (NSRegularExpression, XMLParser not used here), CryptoKit (cache hashing), CoreImage + UIKit (QR), URLSession. Zero third-party parsing dependencies by design.

## Data flow

`BookSourceSnapshot(from:)` is taken on the main actor, then handed across actor boundaries. Each view operation constructs a fresh `BookSourceHTTPClient` + `BookSourcePipeline` (closure-wired: `fetchHTML: { url, headers in try await httpClient.fetchPage(url: url, headers: headers) }`). Pipeline results return as Sendable value types; views hop back via `await MainActor.run`. `chapterContent` only consults `ChapterCache.get`/`set` when the pipeline was constructed with a non-nil `chapterCache` — and `BookSourceSearchView`, `BookSourceChapterListView`, and `BookSourceReaderView` all construct their `BookSourcePipeline` with the default `chapterCache: nil`. **The production book-source reading flow therefore has no chapter caching and no offline-chapter behavior today**; `ChapterCache` is exercised only by `vreaderTests/Services/BookSource/ChapterCacheTests.swift` and by directly constructing a pipeline with a cache in tests.

## Security posture

- **No JavaScript execution, ever** — sources whose rules contain `<js>` or `{{` are imported but classified "Unsupported"; there is no JS engine in the module. XPath rules are classified "Limited" and evaluate to empty.
- Scraping is headless URLSession with regex extraction; remote HTML is never rendered in a WebView on this path.
- User-imported rules can direct arbitrary GETs with arbitrary custom headers (the `header` JSON field) — the trust boundary is the user's choice to import a source.
- `SourceSharingService.parseImportURL` validates scheme (`vreader`), host (`import-source`), base64, and JSON before constructing models — but as of this writing no production call site dispatches it: `VReaderApp`'s `.onOpenURL` handlers route only `vreader-debug://` (DEBUG) and file URLs (`FileURLImportRouter`), so the deep-link import is exercised only by `vreaderTests/Services/BookSource/SourceSharingServiceTests.swift`.

## Edge cases and invariants

- Pagination (TOC and content) is bounded by `maxPaginationDepth` (50) against circular `next` links; `Task.checkCancellation()` runs per stage and per page.
- Empty/whitespace rules return empty arrays, not errors; a TOC entry with both name and URL empty is skipped, name-only-empty gets "Untitled". `chapterContent` only throws `PipelineError.emptyContent` when the collected **array** of per-page texts is empty (zero pages matched anything); if pages match but yield empty strings, the array is non-empty, so the joined result is returned as an empty (or whitespace-only) string instead of throwing, and there is no re-check after `replaceRegex` strips the joined text down to nothing.
- Cache (when a `ChapterCache` is injected — not the case on any production call site today, see Data flow above): empty content is never cached; non-UTF8 or unreadable cache files are deleted on read and the index entry dropped; writes are `.atomic` and failures silent (best-effort).
- Encoding: CJK novel sites (GB2312/GBK/Big5) are first-class; `decode` falls back requested → UTF-8 → lossy UTF-8.
- Import: duplicate `bookSourceUrl`s dedupe first-wins; `lastUpdateTime` converts Legado ms-epoch ↔ `Date`.
