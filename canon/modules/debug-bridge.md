# Module — debug bridge

## Purpose

DEBUG-only `vreader-debug://` URL scheme (feature #44) that lets a host-side script (an AI agent, cron verification run, or CI test) drive the app from outside via `xcrun simctl openurl` — reset/seed the library, open books at positions, present sheets, fire AI actions, create highlights, and read app state back as JSON files from the app container — so bug reproduction and Gate-5 verification run CU-free (no computer-use, no pixel assertions). The entire subsystem is compiled out of Release builds and its absence is gate-checked by script.

## Key files and types

- `vreader/Services/DebugBridge/DebugBridge.swift` — `@MainActor final class DebugBridge` with `func handle(_ url: URL) async`; pure dispatcher that parses then routes to a `DebugBridgeContext`, records `lastError`, and renders stable error strings via `nonisolated static func stableErrorMessage(for: Error) -> String` (prefixes `parse.*` / `bridge.*` / `unknown`). The `@MainActor protocol DebugBridgeContext` in the same file declares one handler per command (`reset`, `seed(fixture:)`, `open(bookId:position:)`, `theme(mode:fontSize:)`, `settle(token:)`, `snapshot(dest:lastErrorMessage:)`, `txtContent(dest:)`, `eval(bridge:js:)`, `tts(action:)`, `search(query:index:)`, `bilingual(action:)`, `highlight(startUTF16:endUTF16:color:)`, `provider(action:)`, `present(sheet:tab:detent:)`, `aiAction(action:scope:text:)`, `seedReadingSessions(bookFingerprintKey:secondsPerSession:)`, `seekFraction(fraction:)`, `scrollSheet(target:)`, `navigate(spineIndex:fraction:)`, `locate(highlightIndex:)`, `scrollBoundary(spineIndex:near:)`, `pdfHighlight(page:rect:color:)`, `setLayout(layout:)`, `page(direction:)`).
- `vreader/Services/DebugBridge/DebugCommand.swift` (1309 lines) — `enum DebugCommand: Equatable` + `DebugCommand.parse(url)`: the full URL grammar and parameter validation. Grammar is `vreader-debug://<command>[?<params>]`; the host names the command; deeper path segments and duplicate query keys are rejected. Path-safe basenames (`token`/`dest`/`bridge`) must match `[A-Za-z0-9._-]{1,64}` and not be dot-only.
- `vreader/Services/DebugBridge/RealDebugBridgeContext.swift` — the production context. `init(persistence: PersistenceActor, importer: BookImporting, fixtureBundle: Bundle = .main, userDefaults: UserDefaults = .standard, providerStore: ProviderProfileStore = .shared, keychain: KeychainService = KeychainService())`. Per-command handlers split across `RealDebugBridgeContext+{Settle,Snapshot,Eval,Provider,Present,AIAction,SeedSessions,Seek,Navigate,Locate,ScrollBoundary,ScrollSheet,PDFHighlight,SetLayout,Page,TXTContent}.swift` extension files — a HISTORICAL split motivated by feature #44 acceptance criterion (g)'s ~300-line file budget, not present subsystem-wide compliance: `RealDebugBridgeContext.swift` itself is now 473 lines, and `DebugReaderRegistry.swift` (540), `DebugBridgeNotifications.swift` (334), `DebugBridge.swift` (333), and `DebugCommand.swift` (1309, below) all exceed the budget too. `bilingual` stays a method on the main class (no `+Bilingual.swift` extension file exists).
- `vreader/Services/DebugBridge/DebugReaderRegistry.swift` — `@MainActor final class DebugReaderRegistry` (`static let shared`), weak single-slot registry of the active reader probe plus keyed+tokened side-channel slots for the EPUB WKWebView (bug #126), Foliate WKWebView (bug #141), and Readium navigator (`ReadiumNavigatorEvaluating`, feature #42 WI-4). `awaitReader(fingerprintKey:timeout:)` uses UUID-identified waiters so concurrent waiters never resume each other's continuations. `setExpectedReaderToken(_:)` + per-reader UUID tokens close the same-key reopen race where a late `didFinish` from an outgoing webview clobbers the new reader's binding (bug #142). `makeIsolatedForTests()` exists because Swift Testing parallelism corrupted shared singleton state (bug #227).
- `vreader/Services/DebugBridge/DebugReaderProbeAdapter.swift` — default `DebugReaderProbe` conformer registered by `ReaderContainerView` (`.onAppear` register / `.onDisappear` unregister). Pluggable closures: `settleStrategy` (default: 100 ms sleep), `jsEvaluator` (default: throws `evalUnsupported(format:)`), `ttsProbe`, `landingBloomProbe`; pushed fields `livePositionString` (bug #257) and `renderedText` (bug #276, GH #1218).
- `vreader/Services/DebugBridge/DebugSnapshot.swift` — `struct DebugSnapshot: Codable, Equatable`, `static let currentSchemaVersion = 3`. v1 fields (`currentBookId`, `format`, `position`, `theme`, `fontSize`, `selection`, `highlightCount`, `renderPhase`, `lastError`, `partial`); v2 adds `ttsState`/`ttsOffsetUTF16`/`settingsProvenance` (feature #49 WI-1); v3 adds `landingBloomCount`/`landingBloomPeakIntensity` (feature #74). ## Data flow

`xcrun simctl openurl <udid> "vreader-debug://…"` → `VReaderApp.body`'s `.onOpenURL` (vreader/App/VReaderApp.swift; the DEBUG branch checks `url.scheme == DebugCommand.scheme` first, else falls through to `FileURLImportRouter` — feature #59 WI-2; the Release branch routes file URLs only) → `DebugBridge.handle(url)` → `DebugCommand.parse(url)` → `RealDebugBridgeContext` handler. Handlers either mutate state directly (reset/seed/theme/provider/seed-sessions) or post a DEBUG notification the mounted reader host observes: `.debugBridgeOpenBook`, `.debugBridgeLibraryChanged`, `.debugBridgeThemeChanged` (bug #144 live re-theme), `.debugBridgeTTSCommand`, `.debugBridgeSearchCommand`, `.debugBridgeBilingualCommand`, `.debugBridgeHighlightCommand`, `.debugBridgePresentSheet`, `.debugBridgeAIAction`, `.debugBridgeSeekFraction`, `.debugBridgeScrollSheet`, `.debugBridgeNavigateCommand`, `.debugBridgeScrollBoundaryCommand`, `.debugBridgePDFHighlightCommand`, `.debugBridgeSetLayoutCommand` (names namespaced `vreader.debugBridge.*`), plus host→probe pushes `.debugBridgeRenderedTextChanged` and `.debugBridgeLandingBloomChanged` (`vreader.debug.*`). The `provider` command deliberately has NO bridge notification — it reuses `ProviderProfileStore`'s production `.providerProfilesDidChange`. Design invariant across every driver: the observer re-enters the SAME production path the chrome/gesture uses (e.g. `.readerNavigateToLocator` for open/navigate/locate; `settingsStore.epubLayout` for set-layout) — no parallel DEBUG-only logic to drift. Readback files land in the app container at `Library/Caches/DebugBridge/` (`RealDebugBridgeContext.snapshotsDirectory()`): `<dest>` (snapshot, `txt-content`), `ready-<token>.json` (settle), `eval-<bridge>.json` (always written, even on error).

## Concurrency

`DebugBridge.handle` serializes commands through a chained `pendingTask: Task<Void, Never>` — FIFO by construction, because `@MainActor` alone would not prevent interleaving across `await` points from `.onOpenURL`'s independent unstructured tasks. Settle is two-staged (`RealDebugBridgeContext+Settle.swift`): stage 1 races `probe.awaitSettle` against a hard `settleTimeoutSeconds = 30.0` (a hung probe still produces the sentinel); stage 2 waits `webViewWaitSeconds = 5.0` for format-specific WebView registration (bug #250 — distinct error string `"webview not registered"`). `open?position=` awaits the reader (10 s) + settle (10 s) before posting the seek. All registry/probe types are `@MainActor`; the registry holds only weak refs so a forgotten unregister never retains a view.

## Edge cases and invariants

- **No-op posture**: every observer-based command (`tts`, `search`, `highlight`, `present`, `ai`, `seek`, `navigate`, `locate`, `scroll-boundary`, `pdf-highlight`, `set-layout`, `page`) is silently a no-op when no matching reader is presented. `settle` with no reader writes the sentinel with `error: "no active reader"` instead of throwing (bug #125).
- **`scroll-sheet` is NOT a true no-op**: `RealDebugBridgeContext.scrollSheet` always writes the requested target into `DebugBridgeScrollSheetState.shared.pendingTarget` and posts the notification, whether or not a matching sheet is currently presented. The pending target is deliberately replayed when a later `TranslationResultCard` mounts (bug #271 replay guard), so issuing the command with no current observer can still affect a FUTURE UI, not just the present one.
- **Fail-loudly seeks**: EPUB `open?position=` is rejected up front with `bridge.seekUnsupportedForFormat` (its navigate handler resolves spines by `href`, not raw CFI) rather than opening at the wrong place (bug #257 Codex round-1 Medium).
- **reset is the verifier's clean slate**: wipes books, the FTS index (bug #264), all persisted reader-settings keys (bug #272 — a leaked `readerAutoPageTurn=true` polluted position snapshots), and the pending scroll-sheet target (bug #271 replay guard).
- **Stable errors**: assert on `snapshot.lastError`'s `parse.*`/`bridge.*` prefixes (e.g. `bridge.unknownFixture`, `bridge.bookNotFound`, `bridge.openAwaitReaderTimeout`, `bridge.invalidFingerprintKey`); the free-text `error` fields in `ready-*.json`/`eval-*.json` are explicitly not pin-able.
- **Host-driven only**: `simctl openurl` from inside an XCUITest runner fails with NSPOSIX 61 (sandboxed away from CoreSimulatorService — bug #242 (GH #1054), structural); the in-runner workaround is `XCTSkipUnless(bridge.bridgeReachable())` (PR #1053, bugs #240/#242). Verification drivers run host-side bash.
- **iOS scheme approval** (bug #123): a fresh simulator shows an "Open in 'vreader'?" alert that swallows the first URL; `scripts/grant-debug-scheme-approval.sh [udid]` idempotently pre-writes `com.apple.launchservices.schemeapproval.plist` with key `"com.apple.CoreSimulator.CoreSimulatorBridge-->vreader-debug" = com.vreader.app`.
- **Release gating**: all Swift files are `#if DEBUG`; `project.yml` excludes `Resources/DebugFixtures/**` and `SupportingFiles/DebugBridge.plist` from the source phase, a "Copy DebugFixtures (DEBUG only)" preBuildScript rsyncs fixtures into the Debug bundle (bug #111/#124 — hence `Bundle.url(..., subdirectory: "DebugFixtures")`), and a Debug-only postCompileScript merges the CFBundleURLTypes into the BUILT Info.plist (bug #121). `scripts/verify-release-no-debugbridge.sh` runs 6 checks against a Release build (no scheme in Info.plist, no DebugFixtures dir, no fixture filenames, no DebugBridge-named files, no pattern hits in resources or binary strings; pattern `vreader-debug|DebugBridge|DebugCommand|DebugFixture|DebugSnapshot|…`); `scripts/verify-debug-has-debugbridge.sh` is NOT a full inverse of those 6 checks — it verifies only that the `vreader-debug` URL scheme is registered in a Debug build's Info.plist (bug #121 regression net) and, when a simulator is booted, that LaunchServices scheme-approval is pre-granted (bug #123 regression net); it does not check the fixture-directory, fixture-filename, DebugBridge-named-file, or resource/binary-string patterns the Release script gates.

## Companion: idb gesture driver

For real gestures the bridge cannot express, `scripts/sim-tap.sh` drives the booted simulator via Facebook's idb (`brew install facebook/fb/idb-companion` + `pip3 install --user fb-idb`), because the computer-use MCP host cannot target Simulator.app (nested inside Xcode.app, absent from its LaunchServices catalog). Subcommands: `launch <bundle-id>`, `tree` (AX dump as `label<TAB>centerX<TAB>centerY`), `label "<AXLabel>"`, `xy <x> <y>`, `swipe <x1> <y1> <x2> <y2>`, `button HOME|LOCK|SIDE_BUTTON|SIRI|APPLE_PAY`, `shot [out.png]`; `SIM_UDID` overrides the target. Binding preference order: DebugBridge command → XCUITest → idb. Boundaries documented in `docs/subsystems/sim-gesture-driver.md`: WKWebView text is not in the AX tree (use `eval` instead), scroll-vs-paged mode changes which swipe works, and idb checks are ad-hoc, never a Gate-5 regression net. Added v3.41.12 (PR #1305).
