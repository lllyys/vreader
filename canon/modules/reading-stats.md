# Module — reading stats

## Purpose

Captures reading sessions (per book, per device; periodic duration flushing limits data loss on crash, but stale sessions are not auto-recovered on relaunch — `recoverStaleSessions()` exists but has no production call site), maintains a derived per-book `ReadingStats` cache for library sorting, and aggregates raw sessions into the feature #58 reading-time dashboard: seven fixed time windows plus a user-picked custom calendar-day range, a hero total, and a five-column sortable per-book table. Sessions also ride in the WebDAV backup payload.

## Key files and types

Capture side:
- `vreader/Services/ReadingSessionTracker.swift` (323 lines) — `@MainActor final class ReadingSessionTracker`. State machine `enum SessionState { idle, active(sessionId:), pausedGrace(sessionId:pausedAtUptime:) }`. Constants: `minimumDurationSeconds = 5` (shorter sessions discarded), `maximumDurationSeconds = 86400` (24 h cap), `gracePeriodSeconds = 30` (background resume window). Duration via `MonotonicClockProtocol` (`uptime()` = `ProcessInfo.systemUptime`, immune to wall-clock changes); pause time excluded via `accumulatedDuration`/`segmentStartUptime`. `recoverStaleSessions()` closes rows with `endedAt == nil`, clamps duration to 0…86400 and marks `isRecovered`. `recordProgress(locator:)` rejects cross-book locators.
- `vreader/Services/SwiftDataSessionStore.swift` — `@MainActor final class SwiftDataSessionStore: SessionPersisting` (fresh `ModelContext` per op; upsert on `sessionId` unique attribute). `NoOpSessionStore.swift` is the discard-everything stand-in.
- `vreader/Models/ReadingSession.swift` — `@Model final class ReadingSession`: `@Attribute(.unique) sessionId: UUID`, `bookFingerprintKey`, `bookFingerprint: DocumentFingerprint`, `startedAt/endedAt`, private(set) `durationSeconds/pagesRead/wordsRead` mutated via `updateDuration(_:)` etc. (SwiftData `@Model` `didSet` is unreliable, so clamping lives in explicit mutators), `startLocator/endLocator: Locator?`, `deviceId`, `isRecovered`. Init clamps `endedAt < startedAt` to `startedAt`.
- `vreader/Models/ReadingStats.swift` — `@Model final class ReadingStats`: `@Attribute(.unique) bookFingerprintKey` (one row per book); `recompute(from sessions:)` is idempotent, filters to matching key; pages/words accumulate via checked `addingReportingOverflow`, but duration accumulates via unchecked `totalSeconds += Int64(clamped)` — the Int64 running total itself can overflow and trap, and clamping only happens when the final sum converts to `Int`; derives `averagePagesPerHour`/`averageWordsPerMinute`.
- `vreader/Services/PersistenceActor+Stats.swift` — `recomputeStats(bookFingerprintKey:bookFingerprint:)` upsert; `fetchAllReadingSessions() -> [ReadingSessionRecord]` (the #58 WI-5 backup collector read, called from `vreader/Services/Backup/BackupDataCollector.swift`); DEBUG-only `seedSyntheticReadingSessions` for the Bug #263 `vreader-debug://seed-sessions` harness.
- `vreader/ViewModels/ReaderLifecycleHelper.swift` — `@MainActor @Observable final class ReaderLifecycleHelper`, composed by TXT/MD/EPUB/PDF ViewModels (Phase R6) and `FoliateReaderViewModel`; `ReadiumEPUBHost+Body.swift` also constructs one directly (Bug #345) alongside `ReadiumEPUBReaderViewModel` for the Readium EPUB path: `beginSession()` → `startSessionIfNeeded`; periodic flush every `sessionFlushInterval = 60.0` s via `periodicFlush()`; close → `endSessionIfNeeded()` + `recomputeStats`. - `vreader/Services/Stats/ReadingStatsAggregator.swift` (290 lines) — `actor ReadingStatsAggregator: ReadingStatsAggregating`. Internal: SwiftData via `PersistenceActor` (writes) and the aggregator's own `ModelContext` (reads); `DocumentFingerprint`/`Locator` from the persistence layer ([[Module — persistence and data model]], [[Module — locator]]); `PreferenceStoring`; backup collector ([[Module — backup and WebDAV]]) consumes `ReadingSessionRecord`. `ReadingDashboardViewModel` depends on the `ReadingStatsAggregating` protocol seam (`vreader/Services/Stats/ReadingStatsAggregator.swift:26`, stored at `vreader/ViewModels/ReadingDashboardViewModel.swift:59`) rather than the concrete aggregator, so tests substitute a mock; `ReadingStatsAggregator` (`ReadingStatsAggregator.swift:57`) is the production actor conformer. External: Foundation Calendar/DateInterval, SwiftData, OSLog (category "ReadingStats").

## Data flow

Reader opens → format host builds `ReadingSessionTracker` → `ReaderLifecycleHelper.beginSession()` → SwiftData row created immediately (save-first: a failed save leaves state unchanged). Locator updates → `recordProgress`. Every 60 s → `periodicFlush` writes `durationSeconds` (crash trail). Background → `pause()` (30 s grace); close → `finalizeCurrentSession()` (discard <5 s, cap 24 h) → `PersistenceActor.recomputeStats` refreshes the `ReadingStats` cache used by library sort. `recoverStaleSessions()` exists on the tracker to close `endedAt == nil` rows on next use, but no production call site wires it to app launch today (only exercised by `ReadingSessionTrackerTests`) — a crash mid-session leaves the row unclosed until something invokes it. Dashboard: Settings → Stats button → sheet → VM → `aggregator.snapshot(window:sort:now:customRange:)` off-main → immutable `ReadingDashboardSnapshot` rendered.

## Edge cases and invariants

- Sessions bucket by `startedAt` only (not overlap); window end is exclusive so a session at exactly `now` is not counted; `allTime` has no lower bound.
- All durations clamped ≥0 at every layer (model init, mutators, aggregator's `max(0, $1.durationSeconds)`, recompute's Int64 accumulation).
- Duplicate `Book.fingerprintKey` rows: first-wins indexing in the aggregator (mirrors PersistenceActor+Library's integrity guard).
- Snapshot shape is unforgeable: exactly 7 window totals in canonical order, by-construction.
- Monotonic clock means a device clock change mid-session cannot corrupt duration; wall dates (`startedAt/endedAt`) are display/bucketing only.
