# Feature #120 — Android OPDS catalog UI — VERIFIED

Implements the OPDS browse/add/download UI (design `vreader-opds.jsx`, needs-design #1799) on the
shipped #117 backend: a saved-catalog store + add/edit sheet, a source list, a browse screen
(navigation rows + acquisition entries + download states), and the error views — wired through two
ViewModels.

## Observations

`OpdsUiRoundTripConnectedTest` drives the actual user path through the real objects — no stubs:
`OpdsSourcesViewModel` saves the catalog to the DataStore store; `store.clientFor(source)` builds the
real origin-scoped `OpdsClient`; `OpdsBrowseViewModel` fetches + parses the live feed, splits nav vs
acquisition entries, then `download(key)` runs `OpdsAcquisitionService.importEntry` →
`BookImporter` → Room. The test asserts the row reaches `In-Library`, `repo.listBooks()` is non-empty,
the imported artifact exists on disk, and the provenance is `opds://`. The live feed served a **real**
13M EPUB (`The Half Second - Li Xiaolai.epub`), so this exercised a real ZIP magic-bytes validation +
re-fingerprint import, not a synthetic stub.

The 4 reader formats' "no global Settings entry point" gap is shared with the backup (#114/#116) and
AI (#118) features — those reached VERIFIED the same way (connected round-trip + instrumented Compose),
because the app has no Settings hub yet and adding one is an undesigned cross-cutting surface (rule 51).
The OPDS source list is reachable the same way the other settings surfaces are.
