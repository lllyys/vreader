# Feature #123 — Android EPUB highlights & notes — Gate-5b acceptance

In-reader EPUB highlighting: select text → 5-color highlight / note / copy / share
(Readium selection + decorations), persisted to Room, re-rendered on reopen, with
tap-to-edit/remove on an existing highlight. All 4 WIs merged (`android/v0.10.1` →
`v0.11.0`); part of checklist item **B** (EPUB slice — TXT/MD is #124, the review
sheet + bookmark creation ride with item F).

## Observations

- The Readium 3.3.0 selection/decoration API was confirmed against the cached AAR
  via `javap` before building (the plan's WI-3 de-risking step): suspend
  `currentSelection(): Selection?` / `applyDecorations(List, group)`,
  `Decoration.Style.Highlight(tint, isActive)`, `DecorableNavigator.Listener.onDecorationActivated(OnActivatedEvent): Boolean`, `Configuration.selectionActionModeCallback`.
- The selection action mode is kept ALIVE (return true, cleared menu) while
  `currentSelection()` is read, then finished — avoiding the "cancellation clears
  the selection" race a bare `return false` would risk (Gate-4 High).
- **Not headlessly automatable:** the two raw finger gestures — the long-press-drag
  that finalizes a text selection, and the tap that activates a decoration. Their
  entire downstream (currentSelection→popover→create/edit/remove→persist→re-render)
  is verified on-device; the triggers are the documented Readium callbacks. This
  matches the prior Android-feature pattern of verifying substance on-device when a
  raw WebView gesture can't be driven headlessly.
