## Observations

- **Gate-5 caught a real (test-only) defect the compile-gate + JVM suite could not.** WI-10/WI-11/WI-12 landed their connected tests as *compile-green only* (the #132/#134/#135 pattern — connected runs deferred to acceptance). At acceptance the connected run went **5/6 + 1/6 red, deterministically**: the tests did `performTextInput → waitForIdle → immediate assert`, but `waitForIdle()` does not await the ViewModel's real 250 ms wall-clock `debounce()` (the injected `Dispatchers.Main.immediate` runs the collector but does not skip `delay`; no virtual `TestScope`). Root cause was test-authoring, confirmed by the passing non-async icon assertion + the EPUB cases that already polled (`awaitFirstHit`). WI-13 replaced the immediate asserts with bounded `compose.waitUntil(5s)` polls; the gate then went **14/0** (lane + independent orchestrator re-run). Durable lesson: an Android connected-test that only *compiles* during its WI is unverified until an acceptance connected run — treat the acceptance run as load-bearing, budget a test-hardening pass.
- WI-13 also caught a **wrong test assertion** (not a sync issue): `dismissSearch_disposesCursors_vmSurvives` asserted the VM "returns to Idle" on dismiss, but `onDismiss` keeps the query (only bumps the generation + closes EPUB cursors) — verified against the VM + its `dismiss_closesEpubCursors` unit test. The fix re-based the assertion on the real `vmSurvives` contract rather than papering over with a longer timeout.
- The EPUB path runs against the **real** Readium `SearchService` in the connected test (not a fake), so `liveReadiumSearch...` + `tapHit_navigatesViaReadiumLocator_andLands` are genuine end-to-end proof of the `Publication.search → SearchIterator → LocatorCollection → navigator.go` chain.
- **Brittle for next time**: real-book CJK input on the emulator needs an ADBKeyboard IME to drive non-ASCII via adb; without it, real-book CJK-query verification is entry-point-only. A future harness could seed a query via the app's own intent/DebugBridge-equivalent rather than the keyboard.
