## Observations

- **The product behavior was correct on the first Gate-5 pass** (v0.17.1): the live-WebDAV backup→restore→jump round-trip, EPUB/TXT toggle/list/jump, the full two-tab list surface, and real-book per-position presence all passed. The one EPUB flake (live-WebView position hadn't settled) cleared on a clean re-run — a settling flake, not a product failure (rule 52).
- **Gate-5 earned its keep by surfacing 3 connected-test defects/gaps** that compile + JVM gates cannot catch, each fixed in WI-8b and re-run GREEN: (1) the recurring `AndroidComposeTestRule.setContent`-called-twice `IllegalStateException` (the #134 lesson, again — the connected run is the only gate that catches it); (2) an AZW3 toggle test that never seeded the parent `BookEntity`, so the `bookmarks.bookKey→books.fingerprintKey` FK aborted the insert before the assertions (in-memory Room enforces FKs) — masking the AZW3 create/list path; (3) `TxtPdfBookmarkTest` covered only TXT despite its name — PDF had no connected coverage. All three are now genuine, passing coverage.
- The AZW3 render-death test skips when the gitignored real `book.azw3` is absent (worktree runs); it runs in the main checkout where the fixture is present. The FK-fix toggle test needs no book and always runs.
- The `onJumpBookmark` for the PDF host is an inline `setContent` lambda with no `@VisibleForTesting` seam, so the connected test exercises the pure `pdfBookmarkPageTarget` decision (in/out-of-range) rather than driving the host jump directly — a sound test-only boundary (driving it would require a forbidden production change).
