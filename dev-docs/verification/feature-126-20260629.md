# Feature #126 — Android AZW3 / MOBI / KF8 (Kindle) reader — VERIFIED

The Android app now reads Kindle-format books (AZW3/MOBI/KF8) through an Android
`WebView` hosting the security-patched, vendored **foliate-js** bundle (mirroring
iOS `FoliateSpikeView`; no NDK/libmobi). All eight WIs + the go/no-go spike
merged across `android/v0.12.1`→`v0.12.8`; this final pass closes bug #357
(GH #1860), the reading-interaction blocker that held the row at IN PROGRESS,
and flips #126 to VERIFIED at `android/v0.12.9`.

## Observations

- **Root cause of #357 was a Compose↔WebView sizing trap, not foliate or the
  security patch.** The WebView built in the `AndroidView(factory = …)` block
  had default `WRAP_CONTENT` LayoutParams, so it self-measured its content
  height as 0 before content filled. foliate's paginator computes
  `divisor = min(maxColumnCount, ceil(size / maxInlineSize))` from the
  `foliate-view`'s `getBoundingClientRect()`; a 0-height box collapses that to
  1 page, where `next()` is permanently `atEnd` and no-ops with no error.
  `goToFraction` "worked" only because it scrolled within the single giant page
  — which is exactly why resume looked healthy while page-turn was dead.
- **Two-line fix:** explicit `ViewGroup.LayoutParams(MATCH_PARENT, MATCH_PARENT)`
  on the factory WebView + `reader.html` height `100%`→`100vh; 100dvh`. With it,
  the diagnostic logged `VIEWSIZE w=412 h=615` (was `h=0`) and fractions advanced
  `s=0 → s=1 → s=2` on each tap.
- **Lesson (captured):** the WI-0 render spike's GO verdict was too weak — it
  asserted relocates *fired*, not that the *fraction advanced*. A fraction-0
  re-layout gave a false pass. A render/verify spike MUST assert the position
  actually CHANGES, not merely that events arrive. The `@Ignore` on the
  page-turn test has been removed; it is now the standing regression guard.
- The earlier full-class run (`--class=…Azw3ReaderActivityTest`, all 3) hit the
  1200s watchdog — not a wedge (no concurrent emulator driving), just three
  6 MB-book foliate-render tests + build exceeding 20 min. Per-test runs are the
  correct gate here.
