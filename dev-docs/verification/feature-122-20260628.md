# Feature #122 — Android reading-stats — Gate-5b acceptance

Reading-time tracking (Room `daily_reading`) + an in-reader session pill + a
stats dashboard (window bar · hero · 14-day chart · per-book table) for the TXT
reader, per design #1800. All 4 WIs merged on `main` (`android/v0.9.1` →
`v0.10.0`); this run exercises the acceptance criteria end-to-end against the
real stack on the emulator.

## Observations

- The single load-bearing risk in WI-4 was the durable bank running in a
  composition-scoped coroutine that teardown could cancel before the Room write
  committed (Gate-4 Critical). The fix — launching start/stop on the
  process-lifetime `appScope` plus `withContext(NonCancellable)` around the DAO
  writes — is exactly what the `lifecycleHook_…` connected test proves: the
  fire-and-forget launches still complete and bank to Room after `ON_STOP`.
- The "missed initial ON_RESUME" High is a non-issue because `LifecycleRegistry`
  replays lifecycle events to a newly-registered observer up to the current
  state; the connected test registers at `RESUMED` and confirms `start()` fired.
- A 7-min single-jump session was (correctly) treated as an idle gap by the
  tracker (`maxIdleMillis` = 5 min) during test authoring — confirming the
  idle-cap guard works; the test uses a 4-min jump for the continuous case.
