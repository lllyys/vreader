# Feature #155 — Android open-with / system document handler

Gate-5 acceptance pass. All six WIs merged (`android/v0.20.28` → `v0.22.2`).

## The user-visible path (rule 47 Gate 5 — production reachability)

> **Files → Downloads → long-press "The Half Second - Li Xiaolai.epub" → More options (⋮) →
> Open with → VReader**
>
> then: *Library shows "1 books · 0 reading" with "The Half Second - Li Xiaolai"* → **tap the cover**
> → the reader renders page 1.

The only interaction with VReader was **tapping its entry in the system chooser**. The book was
staged the way a user gets one — pushed into `/sdcard/Download/`, then browsed in the shipped Files
app. No DebugBridge command, no `am start` shortcut, no debug-source-set launcher.

Observed at the import step: artifact `epub_71fa5b7d…4a31_1302140` (1,302,140 B — byte-exact with the
source) and `topResumedActivity=com.vreader.app/.MainActivity`; after tapping the cover,
`topResumedActivity=…/.reader.ReaderActivity`.

Step-by-step transcript with commands, screenshots and UI dumps: `.reports/dynamic-reachability-transcript.md`,
`step1..step6-*.png`, `ui-*.xml` (gitignored, local to the verification run).

## Release reachability — both halves, and no install was claimed

`app/build.gradle.kts` declares **no `buildTypes` block and no `signingConfig`**, so
`:app:assembleRelease` produces `app-release-unsigned.apk` (20,352,960 B) which **cannot be
installed**. Claiming "installed the release build" would be exactly the dishonesty rule 47's clause
exists to prevent, so the clause is discharged in two halves:

| Half | Evidence |
|---|---|
| **Static** | Release merged manifest shows `.imports.ImportActivity`, `exported="true"`, 4 intent-filters. `aapt2 dump xmltree` over the **release APK** shows the same in the shipped binary — 219 lines, `exported=true`, 4 `intent-filter` elements, 36 `mimeType` and 54 `pathPattern` data entries. The debug↔release `<activity …ImportActivity>` blocks are **byte-identical**. |
| **Dynamic** | The chooser drive above, on the installed debug build — whose relevant manifest block was just shown identical to release. Plus `cmd package query-activities` from the shell uid against a **real** `ExternalStorageProvider` document URI. |

The static half is sound because `app/src/debug/AndroidManifest.xml` contributes only
`BackupDebugActivity` and a `networkSecurityConfig` — **no intent-filter**.

`cmd package query-activities` results: `VIEW`+`application/epub+zip` resolves to
`com.vreader.app/.imports.ImportActivity` as the **sole** handler; the **typeless** `VIEW` resolves
to it too — proving manifest filter B's `pathPattern` matches a real ESP document id, not just a
synthetic one; `SEND`+`application/epub+zip` lists VReader alongside Messages, Drive, Gmail and
Nearby Share.

## Fixtures — real books first, with the exception stated

| Format | Fixture | Bytes |
|---|---|---|
| EPUB | `test-books/books/epub/The Half Second - Li Xiaolai.epub` | 1,302,140 |
| TXT | `test-books/books/txt/黑暗血时代.txt` — staged under a CJK display name, doubling as the 14 MB+ case | 14,059,220 |
| AZW3 | `test-books/books/azw3/Bei Tao Yan De Yong Qi - Zi Wo.azw3` | 6,288,371 |
| large file | `test-books/books/epub/道诡异仙 - 狐尾的笔.epub` — artifact digest asserted byte-for-byte | 19,381,838 |
| PDF | committed androidTest asset `sample-3page.pdf` | — |
| MD | the repo's own `docs/architecture.md` | — |

**Exception stated explicitly**: PDF and MD use non-book fixtures under the AGENTS.md exception *"the
format has no real book"* — `test-books/books/` contains `azw3/`, `epub/` and `txt/` **only**. For MD
the lane went beyond synthetic and pushed the **real** `docs/architecture.md` (a real repo document,
simply not a *book*). Its identity check is necessarily weaker than the books' exact-byte pin —
size floor + title line + three section anchors — because it is a **living file**; a pinned digest
would break the matrix on every unrelated docs commit. Named follow-up: have the runner hand each
pushed fixture's SHA-256 to the test so even a living document can be bound cryptographically.

Malformed cases are synthetic by necessity — no real book is zero-byte or truncated.

**Fixtures are re-pushed before every run.** Confirmed empirically that the connected task wipes
`/sdcard/Android/data/com.vreader.app/` at run **end**.

## The RED that proves the fixture policy

The class was run with **no fixtures pushed**: 7 real-fixture tests failed loudly with the `adb push`
instruction and **0 fell back to a synthetic stand-in** (`.reports/red-no-fixtures.txt`). Green after
the push. That is the difference between a matrix that tests five formats and one that reports five.

## What the gates caught that the tests would not have

- **Gate-4 round 1**: the first draft asserted byte **count** but not byte **identity**, and treated
  *"a new row appeared"* as attribution — a previous test's still-queued import could satisfy it.
  Now every source is hashed and the exact canonical key, sha, provenance URI and stored-artifact
  digest are pinned; `awaitBook(staged, format)` requires the exact key **and** the exact staged URI.
- **Gate-4 round 3** (3 Mediums, fixed, then independently confirmed **clean** in an
  orchestrator-run round): a self-contradicting KDoc; a `finishAll()` throw that could skip teardown
  cleanup; and a pre-existing-key exclusion that would have left a stranger's row mutated — now a
  loud refusal before anything dispatches. That guard **caught itself** during development.

## Surprises recorded

**An app cannot tell whether the system will interpose the "Open with" chooser.** Android 11+ package
visibility filters `queryIntentActivities` to the app itself, so the first run concluded "VReader is
the sole handler" for `text/plain` and `application/pdf`, started implicitly, the real system
resolver appeared (`ResolverListAdapter` in logcat), and the run **parked until the 120 s timeout**.
Intents are now started **package-scoped** — which keeps the manifest filters load-bearing, since a
filter that stopped matching throws `ActivityNotFoundException` — and the chooser leg is proven by
the **manual drive**, not claimed by the class.

**A zero-byte `.epub` imports as a zero-byte library row.** The import layer is content-agnostic by
design: extension decides format, bytes decide identity. The test pins that the exported entry point
**survives** it rather than endorsing it; whether the library should refuse an empty book is a
product decision for a tracker row, not this WI.

The app is uninstalled by AGP after every `connectedAndroidTest`, so the dynamic drive needed an
explicit `:app:installDebug` first.

## Not claimed by this pass

The best-effort **copy**-stall case — a real provider cannot be made to stall from here. Covered by
WI-5's connected `aStalledResolutionNeverHoldsAnInFlightSlot` and WI-4's JVM liveness test.
