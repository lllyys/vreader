# Feature #127 — Android library collections — VERIFIED

The Android app now has **library collections** (parity-checklist item **C**, the *collections*
half; *search* is split to #128). Users create collections, assign books, filter the grid by a
collection chip, rename/create from a manage sheet, and — the cross-platform-binding part — their
collections + membership survive the WebDAV backup/restore round-trip byte-compatibly with the iOS
`BackupCollection` contract. All 7 WIs merged across `android/v0.11.x`→`v0.13.7`; this pass flips
#127 to VERIFIED.

## Observations

- The live round-trip ran a **selective** restore (`selection = setOf(theBook)`) on purpose — so the
  pass also confirms the WI-6 Gate-4 High fix: a single-book restore re-creates only the collection the
  restored book belongs to (not unrelated collections), and adds only the selected book's membership.
- The connected instrumentation lane was flaky early in the session (stale hung `adb shell getprop`
  processes from repeated boot probes congested adbd → two `ManageSheetUiTest` TIMEOUTs at the
  instrumentation stage). Clearing those shells + `adb kill-server/start-server` made every subsequent
  connected run land cleanly (rule 52 contention class). The emulator was started **detached**
  (`nohup … & disown`) so no background task owned it.
- Delete UI is the only deferred surface (needs-design #1875); the delete *capability* is repo/VM-tested.
  Library *search* is a separate feature (#128) per the Gate-2 split.
