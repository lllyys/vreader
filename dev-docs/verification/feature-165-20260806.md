# Feature #165 — Android annotations export / import

Gate-5b acceptance for the **import half**. Seven WIs merged (`android/v0.23.3` → `v0.30.0`).

**This does not take the row to `VERIFIED`.** The export row and its result surface are WI-8, blocked
on `needs-design` **#2085**, so A-10b and A-1/A-2's end-to-end leg are undischarged and the row is
capped at `DONE` per rule 47 Gate 5.

## The user-visible path (rule 47 Gate 5 — production reachability)

> **Open the app → the Library grid → tap the book → the reader opens → tap the top bar's `⋯` More →
> tap Details → tap "Import annotations…" → the system document picker opens → pick a file → the
> designed preview sheet shows the counts and "Import N items" → tap it → the merged
> highlights/notes/bookmarks are in the book's Notes sheet.**

Every file on that path lives in `android/app/src/main` — `MainActivity` → `LibraryScreen` → the four
reader activities → `ReaderChromeScaffold` / `EpubReaderSheets` → `BookDetailsSheet` →
`AnnotationImportEntry`. **Nothing comes from `src/debug`.**

**Stated deviation, same as #139's and #140's**: the module declares no `buildTypes` block, so there
is no instrumentable release variant — `connectedAndroidTest` runs debug. The gap is closed on the
other axis (nothing debug-only is on the path), which is supporting evidence, not an equivalent.

## The round-trip: locators, not just counts

Real `The Half Second - Li Xiaolai.epub`, digest-pinned. Seeded **7 rows** — 3 highlights (3 colours,
one with a note, one with an engine anchor), 2 standalone notes, 2 bookmarks — exported through the
**shipped** `AnnotationsExportWriter`, wiped to 0, then imported back **through the production path**
with the picked `Uri` arriving via the app's own SAF launcher as a real `content://` FileProvider
document. **All 7 returned.**

**Locator equality is asserted kind by kind, as sets, BEFORE any whole-row compare** — so a failure
names the position rather than reporting a generic mismatch. A count-only assertion would pass with
every annotation landing in the wrong place, which is precisely the failure mode feature #173
documents on the iOS side.

Two normalisations, both **observed on device, not assumed**:

1. **`anchor` is null after import** — the backup wire has no anchor field. Asserted separately on the
   anchored probe row, **whose locator is untouched**.
2. **Timestamps truncate to the second** — `BackupJson` emits ISO-8601 UTC at second precision for
   Swift `Codable` parity, so milliseconds cannot survive the versioned wire (the same holds on
   WebDAV restore). Asserted as the **exact transform**, plus a check that the seeded rows really
   carried milliseconds — so a zeroed or re-minted timestamp still goes **RED**.

**Idempotency asserted at the surface**: re-importing the same file offers "Import 0 items" with a
**disabled** primary and changes nothing.

**CJK leg** on the real 14 MB `黑暗血时代.txt`: a 20-ideograph run taken from the real book survives
UTF-8 encode → SAF write → SAF read → decode → Room **byte-for-byte**, plus a CJK note, plus a
byte-level check that the exported file carries the characters as **UTF-8 rather than escapes**.

## A-9 measured on target — and the plan was wrong

§8.2 claimed `MAX_IMPORT_JSON_BYTES = 2 MiB` ≈ "10 000 richly-annotated rows with headroom".

**Measured: the byte cap binds first, so `MAX_IMPORT_ROWS = 10 000` is unreachable.** The largest
importable file is **4 000 rows / 1 973 880 bytes** — the estimate was off by ≈2.5×. At that real
ceiling: preview **717–807 ms**, apply **695–729 ms** across three runs, both inside the stated
2 s / 1 s budgets. The plan is corrected with an erratum.

## What is NOT covered — stated plainly

1. **A-1/A-2's end-to-end leg and A-10b are NOT discharged.** The designed "Export annotations…" row
   does not exist and stays blocked on **#2085**; the export **writer** is exercised in-process only,
   which is exactly the reach the export half has in this pass.
2. **A-12's hostile-provider suite is WI-4b's JVM coverage**, re-run here as regression — not
   re-proved on device, since the emulator cannot reach the parked path.
3. **The teardown test is better-instrumented, not deterministic.** It now fails **loudly as
   inconclusive** if the merge finished before `DESTROYED`, so it cannot false-green — but a
   genuinely fast device makes it red rather than green.
4. **No test exercises the session guards through the composable** (the open Low). Round 4 judged
   shipping with it acceptable for the import half given four-host reachability plus real round-trip
   coverage; closing it needs a fake-controller composable test with latched A/B previews.
5. **Rotation specifically was not exercised** — `finish()` was the teardown used.
6. **Release-variant behaviour is unverified** (no instrumentable release variant exists).
