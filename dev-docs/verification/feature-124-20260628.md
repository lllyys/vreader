# Feature #124 — Android TXT highlights & notes — Gate-5b acceptance

Custom Compose long-press-drag selection in the TXT reader → 5-color highlight /
note / copy / share (reusing #123's annotation domain), washes via
`drawBehind`+`getPathForRange`, persisted + re-rendered, with tap-to-edit/remove.
All 4 WIs merged (`android/v0.11.1` → `v0.12.0`); part of checklist item **B**
(EPUB #123 + **TXT #124** + MD #125 + the review-sheet/bookmark entry via item F).

## Observations

- The Android TXT selection gesture **is automatable via the Compose test harness**
  (`performTouchInput { longClick() }` / `click(percentOffset(...))`) — unlike #123's
  EPUB WebView gesture. The full select → create → edit → remove flow is exercised by
  real synthetic gestures on the emulator, not just a substance-level proxy.
- Real bugs caught + fixed during testing: two conflicting `pointerInput` detectors
  (replaced with one `awaitEachGesture`); a stale-closure capture in the stable
  `pointerInput` (fixed with `rememberUpdatedState`); a node-center tap landing past the
  left-aligned text (test taps the actual text); shared on-disk Room across test methods
  (clear-first). Gate-4 caught the cancellation-vs-tap + nearest-chunk-fallback hazards.
