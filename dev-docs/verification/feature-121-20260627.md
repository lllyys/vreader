# Feature #121 — Android TTS read-aloud — VERIFIED

Implements the TTS read-aloud design (`vreader-tts.jsx`, needs-design #1797) on Android's on-device
`android.speech.tts.TextToSpeech`: a sentence chunker, a `TextToSpeech` engine wrapper, the transport
state machine, the designed control bar + voice/speed sheets, and the TXT-reader integration
(spoken-sentence highlight + auto-scroll). 5 WIs.

## Acceptance criteria

| # | Criterion | Observed | Result |
|---|---|---|---|
| 1 | Read-aloud starts + speaks sentences in order (or surfaces a typed no-voice-data error) | WI-5 `TxtTtsConnectedTest` drives the REAL chunker→VM→`TextToSpeech` on the emulator → reaches `speaking` (advancing sentence index) OR the typed error — both valid; audible output not asserted (headless, as on iOS). WI-3 13 VM tests pin Started-advance/pause/resume/next/prev | ✅ pass |
| 2 | The spoken sentence is highlighted + auto-scrolled into view (TXT) | WI-5 `TtsHighlight` (5 JVM) maps the spoken raw-text span → chunk-local span; `TxtBody` washes that span; auto-scroll fires when the spoken chunk is off-screen | ✅ pass |
| 3 | Control bar: play/pause · sentence prev/next · speed (0.5–2.0×) · voice/engine selection | WI-4 `TtsControlBarTest` (4) + `TtsSheetsTest` (3) instrumented — transport callbacks, speed pick, voice select + not-installed→install | ✅ pass |
| 4 | Error state (no installed voice) offers Install-voice-data + System-TTS | WI-4 control bar error layout test (install/system CTAs fire); WI-5 `launchTtsIntent` fires the guarded system intents | ✅ pass |
| 5 | On-device only — no credentials/network for embedded voices | `AndroidTtsEngine` over `TextToSpeech`; `TtsVoiceFilter` filters/labels network voices and never auto-selects one (WI-2, 6 JVM tests) | ✅ pass |

## Observations

`TxtTtsConnectedTest` exercises the actual user pipeline through the real objects — no stubs: a
multi-sentence prose string → `TtsChunker.chunk(text, TextToSpeech.getMaxSpeechInputLength())` →
`TtsViewModel.start` → `AndroidTtsEngine` (real `android.speech.tts.TextToSpeech`). It reaches a
terminal phase (speaking with an advancing index, or the typed error on a voice-less emulator) and the
spoken span maps onto a valid highlight chunk. Audible output is the only unverifiable part (headless,
the same limitation iOS TTS verification has).

Test tally: 30+ JVM (chunker 10, models 2, voice-filter 6, viewmodel 13, highlight 5) + 11 instrumented
(engine init/double-init 3, control bar 4, sheets 3, live pipeline 1). Across 5 WIs, Gate-4 Codex audits
caught + fixed real concurrency bugs (engine single-flight init / type-aware flows, VM start-token +
terminal-failure handling, integration lazy-chunk + lifecycle).

Per the plan §OUT-of-scope, MD/EPUB/PDF read-aloud + their offset maps, in-app voice-data download, and
background `MediaSession` playback are documented #110 follow-ons; the engine + bar + VM are
format-agnostic so they wire in incrementally.
