# Feature #137 — Android reader layout (scroll/paged) toggle + Compose paged text renderer (TXT/MD)

Gate-5b final acceptance for feature #137, the box-**E** remaining half of the #110
Android capability-parity driver. All 11 WIs merged (`android/v0.19.1` → `android/v0.20.6`);
this evidence flips the row `IN PROGRESS` → `VERIFIED`.

The feature delivers a designed **Layout (Paged/Scroll)** segmented control across the
EPUB/TXT/MD readers: EPUB reuses Readium native pagination (a 2-site `EpubPreferences(scroll)`
flip), and TXT/MD gain a **new Compose paged text renderer** (measured-line pagination +
span-preserving page-offset map + `HorizontalPager` + 30/40/30 tap-zones) with every existing
TXT/MD feature (selection, highlights, bookmarks, TTS, find, display settings) re-integrated in
paged mode. Default layout = **Scroll** (iOS parity); bilingual-on routes to scroll (v1 scope cut).
PDF is exempt.

## Observations

- **Memory posture holds under the two-phase design.** Even on a 30,695-page CJK book, phase-1 retains
  only the page-start `IntArray` (peak used-heap delta 24 MB / peak PSS 296 MB) — the composed
  `PageOffsetMap` + rendered pages are lazily windowed and evicted. The R2-High memory-blow-up risk did
  not materialize.
- **Phase-1 latency is the real cost, and it is high: ~96 s median to paginate a 14 MB CJK book.** This
  is a genuine UX concern, BUT it is bounded in blast radius: **Paged is opt-in** (default = Scroll,
  which uses the pre-existing chunked lazy renderer and is unaffected), so only a user who explicitly
  switches a very large CJK book to Paged hits it. The #137 plan pre-authorized this as a
  windowed-measurement follow-up rather than a #137 blocker. **Filed as feature #138** (Android paged
  phase-1: windowed / incremental pagination for very large docs) so it is tracked and planned before
  implementation. This evidence is intentionally explicit about the number so it is not lost.
- **Connected-run defects that compile/JVM could not catch** were surfaced and fixed during Gate-5
  (per the recurring Android lesson): (a) a resume-to-forward-position acceptance test waited for the
  off-screen `Line 001` — fixed to wait on the always-present read-aloud chrome tag; (b) the gesture
  classifier had to fold selection + tap-zones + pager-swipe into one `awaitEachGesture` (WI-7a R1
  Critical) or tap double-fire snapped the pager back; (c) the perf benchmark's connected lifecycle
  uninstalls the app at run-end, wiping the pushed book — the test has an exact-14059220-byte identity
  check + a deterministic synthetic ~14 MB CJK fallback so a bare re-run still measures (and logs which
  it used).
- **EPUB paged acceptance opens FRESH in Paged** (not a mid-read scroll→paged reflow): a mid-read reflow
  does not reliably relayout the offscreen instrumentation WebView columns, whereas a fresh Paged open
  does (WI-3 discovery).
