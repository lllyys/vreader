## 1. Problem

#132's reader top bar (`ReaderTopChrome`) has an `onMore: (() -> Unit)?` button slot that is **omitted (null) until #134** (the #129 "no dead controls" rule). Each row emits either `onAction(id)` (`tts`/`configure-ai`/`details`/`share`/`export`) or `onToggle(id)` (`autoTurn`/`bilingual`) — the design already separates the tap-action rows from the stateful-toggle rows (verified `vreader-more.jsx:80-114`). `vreader-book-details.jsx` `BookDetailsSheet` depicts a metadata sheet (cover + title/author·year + tag chips + a `Format/Size/Pages/Fingerprint/Location` `MetaList` + copy-fingerprint mini-action + an `ActionList`: replace/add cover · share · export) with two layouts (stacked/split) and four states (default/long-title/missing-cover/remote-only). ### §details-source — the details data model (round-1 HIGH: `Book` can't supply year/tags/coverPath)
Verified: Android `Book` = `{ fingerprintKey, title, originalFormat, contentSHA256, fileByteCount, localFilePath?, sourceUri?, addedAt, lastOpenedAt? }` — **no `author`, no `year`, no `tags`, no `pageCount`, no `coverPath`.** iOS `BookDetailsViewModel` maps `author`/`totalPageCount`/`collectionNames`/`coverImagePath`/`fileByteCount` off `LibraryBookItem` (verified) — and notably iOS ALSO has no `year` (the design's `· year` is unmapped even on iOS). So:
- **`author`** — comes from **#128's `books.author`** (a nullable String). Degrade to null when #128 hasn't merged or the book has none → the author line is **omitted** (matches iOS "Unknown Author" being a display fallback; #134 chooses to OMIT the line when null rather than show a placeholder, since the design shows author inline with a `·` separator that reads wrong without a value).
- **`tags`** — the design's tag chips = **collection names** (verified iOS `tags = book.collectionNames`). Sourced via the NEW `collectionNamesForBook(bookKey): Flow<List<String>>` join query. Empty list → the tag-chip row is omitted.
- **`pageCount`** — host-supplied, PDF-only (§page-count).
- **Intentionally ALWAYS-absent on Android (no data source → the row is OMITTED, never invented):** **year** (no field anywhere; even iOS doesn't map it) — no Year row; **cover art** (no `coverPath`; every book would hit the interactive missing-cover placeholder) — no cover until Design-gate #1 clears.
- `BookDetailsSource(book, author, collectionNames, pageCount, cover?=null)` bundles the assembled inputs; the details ViewModel/factory observes `collectionNamesForBook` so the chips update live.

### §fingerprint — copy the FULL canonical key (round-1 HIGH: mapping was wrong)
The v1 plan said "fingerprint from `contentSHA256` truncated" — WRONG. The design AND iOS display+truncate the **canonical `fingerprintKey`** (`format:sha256:bytes`) and **copy the FULL key**, not the bare SHA. Verified: `vreader-book-details.jsx:20` renders `${format}:8a4f…2c1b` (the canonical shape); iOS `BookDetailsViewModel` sets `fingerprintFull = book.fingerprintKey` (copied to the pasteboard, `BookDetailsSheet+Actions.swift:64`) and `fingerprintDisplay = truncateFingerprint(book.fingerprintKey)` (`prefix(14)…suffix(8)`). #134 mirrors this exactly:
- `fingerprintFull = book.fingerprintKey` — the **copy-button payload** (the whole `format:sha256:bytes`).
- `fingerprintDisplay = middleTruncate(book.fingerprintKey)` — `if (key.length <= 28) key else key.take(14) + "…" + key.takeLast(8)` (same thresholds as iOS).

### §size-formatting — the byte-format contract (MEDIUM)
Mirror iOS `FileSizeFormatter` (verified: `ByteCountFormatter` `.file` count style, and the ViewModel maps `byteCount <= 0` → **"Unknown"**). Android contract:
- Use the platform file-style byte formatter — `android.text.format.Formatter.formatShortFileSize(context, bytes)` (SI/decimal divisors, matching `.file` count style; locale-aware, RTL-safe).
- **Rounding/units** follow the platform formatter (no hand-rolled math). **Zero or negative → "Unknown"** (the iOS ViewModel override, NOT the formatter's "Zero KB"). **`Long.MAX_VALUE`** → the formatter's top-unit output (no overflow; tested it doesn't throw). Pin these exact outputs in `BookDetailsMapperTest`: `0 → "Unknown"`, `-1 → "Unknown"`, a small/KB/MB boundary sample, `Long.MAX_VALUE → non-empty, no crash`.

### §page-count — PDF-only pages row (MEDIUM)
Verified: only PDF exposes a real page count (`PdfDocument.pageCount`, captured from `renderer.pageCount`). EPUB's `readingOrderCount` (`BookOpener.BookMetadata.readingOrderCount = publication.readingOrder.size`) is a **spine-item count, NOT pages** → must NOT be shown as "Pages." TXT/MD/AZW3 have no page count. So: `pagesLabel` is non-null **only** on the PDF host; the **Pages row is OMITTED on every other host** (never label chapters/spine-items/chunks as pages).

### §location — a truthful Location label (MEDIUM)
`Book.localFilePath` is an internal app-private path (`/data/user/0/…/files/books/epub_…`). Showing that raw is a leak/noise (MEDIUM). Mirror iOS, which shows a relative label `"ImportedBooks/\(lastPathComponent)"` (verified `BookDetailsViewModel.swift:50`). (Not a dead control — it's a plain label, not a button.)

### §share-missing-file — no invented error UI (round-1 HIGH, rule 51)
Neither `MorePopover` nor `BookDetailsSheet` JSX depicts a "disabled Share with reason/toast" state — the v1 plan's "Share row disabled with a reason" was **invented UI**. **Resolution (recommended autonomous path — chosen, NO design gate):** constrain the flow so the sheet + its Share action are only reachable for a book whose `localFilePath` points at a readable, existing local file. The book being *open in the reader* already implies a materialized local file (the reader opened it), so on the happy path the file exists. For the **residual deletion race** (the file is deleted between opening the reader and tapping Share), handle it **non-visually**: `shareBookFileIntent` is called after a final `file.exists() && file.canRead()` check; if that check fails (or the subsequent `startActivity` throws `ActivityNotFoundException`), the tap is a **silent no-op** (logged, no crash, no invented toast/dialog) — the popover simply dismisses. No new visible error surface is created (rule 51). **This is the chosen path; no `needs-design` gate is filed for the share-error case** (recorded in the Design-gate list for completeness).

### §share-hardening — the share intent contract (MEDIUM)
`shareBookFileIntent` must: (a) put the `FileProvider.getUriForFile(context, "${applicationId}.fileprovider", file)` URI on `EXTRA_STREAM`; (b) set `FLAG_GRANT_READ_URI_PERMISSION` AND attach a matching `ClipData` (belt-and-suspenders on Android where the flag alone can miss on some receivers); (c) set a **per-format MIME** (`epub`→`application/epub+zip`, `pdf`→`application/pdf`, `txt`→`text/plain`, `md`→`text/markdown`, `azw3`→`application/vnd.amazon.ebook`, unknown → `application/octet-stream`); (d) wrap in `Intent.createChooser`; (e) survive **no receiver** (`resolveActivity == null` → silent no-op) and **`ActivityNotFoundException`** (caught → no-op). Existing precedent: the app already builds `ACTION_SEND` + `text/plain` + `EXTRA_TEXT` choosers for selection-share (verified `ReaderActivity.kt:250`, `TxtReaderActivity.kt:527`) — but has **no `EXTRA_STREAM`/FileProvider file share**; #134 adds that path.

### §display-name — safe DISPLAY_NAME without renaming the file (round-1 HIGH)
Imported files have no extension and an ugly sanitized-key name (verified). The receiver of a shared URI reads `OpenableColumns.DISPLAY_NAME` to name the attachment. Override the provider's `query(...)` so `DISPLAY_NAME` = a sanitized `"$title.$ext"` (title from `Book.title` with illegal filename chars `[\\/:*?"<>| ]` replaced by `_` and length-capped; ext from `originalFormat`), the canonical file on disk **unchanged**. Tests: Unicode/CJK title (preserved, not mangled), title with illegal chars (sanitized), a title that is only illegal chars (falls back to a safe stem), and every format's extension mapping.

**OUT of scope:** annotation-export subsystem (separate follow-up feature); interactive cover replace/add (scoped out + missing-cover fallback gated); split layout + remote-only state; the More menu's TTS/Auto-turn/Bilingual **behavior** (owned per §more-row-ownership — #134 leaves omitted slots, no dead rows); the Location `reveal` mini-action; `search/*`, `nav/*` (#132/#133).

## 3. Prior art / project precedent / rejected alternatives

Android: `Book` carries `originalFormat`/`fileByteCount`/`contentSHA256`/`localFilePath`/`title`/`fingerprintKey` (verified); `author` arrives via #128; #132's `ReaderTopChrome`/`ReaderChromeScaffold`/`ReaderChromeState`/`ReaderChromeStateSaver` provide the More anchor + route state; #127's `SheetRoute`/`SheetRouteSaver` is the Saver precedent #132's state uses (and #134's `Details` route rides). `CollectionDao` already has the `book_collection`⋈`collections` tables + an `observeCollectionsWithCount` join precedent (verified) → the new `collectionNamesForBook` join follows it. The app's existing `ACTION_SEND`+`text/plain` selection-share (verified) is the intent precedent; #134 adds the FileProvider `EXTRA_STREAM` path. `AppContainer` `by lazy` constructor injection (verified `VReaderApp.kt`).

**Rejected alternatives:**
1. *Build annotation export now* — no Android export subsystem; a large format-serialization concern (Markdown/JSON/VReader-JSON mirroring iOS `AnnotationExporter` + `BackupSections`) worthy of its own feature. Omit the Export row; file the follow-up.
2. *Ship the depicted interactive missing-cover placeholder ("Tap to add cover"/pencil)* — Android has no cover store, so it's a dead control on EVERY book (rule 51 + #129 no-dead-control). Gate a NON-interactive fallback (Design-gate #1); ship no cover art until then.
3. *Disabled "Share (file missing)" row with a toast* — invented UI (neither JSX depicts it). Constrain Share to a validated local file; handle the deletion race silently (§share-missing-file). No gate needed.
4. *Show the raw `contentSHA256` as the fingerprint / copy the SHA* — wrong; the design + iOS display+copy the full canonical `fingerprintKey` (§fingerprint).
5. *Assemble tags from a separate collections read + membership read* — a transient mismatch window (MEDIUM). Use ONE `collectionNamesForBook` join query.
6. *Show `readingOrderCount` as "Pages" on EPUB* — spine items ≠ pages. PDF-only Pages row (§page-count).
7. *Show the raw `/data/user/0/…` path as Location* — internal-path leak/noise. A truthful relative `"Books/<name>"` label, read-only (§location).
8. *Make the More popup a durable `ReaderSheet` route* — a popover isn't a bottom sheet; re-showing it on process death is surprising. Only the `Details` sheet is a durable route; the popup is a transient boolean (§chrome-coordination, §state-ownership).
9. *One uniform `ReaderChromeScaffold` wiring for all five hosts* — EPUB is a View/Fragment host with separate `ComposeView` overlays; its More/Details wiring is distinct (§host-wiring).
10. *Rename the on-disk book file to `title.ext` so the shared filename is nice* — breaks the canonical fingerprint-key filename (idempotent re-import, backup references). Override `DISPLAY_NAME` instead (§display-name).

## 6. Risks + mitigations

1. **Hard dependency on #132's unmerged chrome API (round-1 HIGH).** `ReaderTopChrome`/`ReaderChromeScaffold`/`ReaderChromeState` are #132's and don't exist yet. Mitigation: `Deps:[feat:#132]`; #134's UI WIs (WI-3..WI-5) start only on #132's merged baseline and **re-audit** there; the two coordinated extensions (`moreMenuSlot` on `ReaderTopChrome`; the `Details` case on `ReaderSheet`/`ReaderChromeStateSaver`) are landed WITH #132's owner or as additive nullable-safe changes on its baseline (§chrome-coordination). Foundational WI-1/WI-2 (models + share plumbing) are chrome-free and may proceed earlier.
2. **FileProvider did not exist + no-extension sanitized filenames (round-1 HIGH).** Add the provider + paths unconditionally; reject out-of-`books` paths; override `DISPLAY_NAME` to `title.ext` without renaming the canonical file (§display-name, §share-hardening). Tested incl. CJK/illegal titles.
3. **`Book` lacks year/tags/coverPath/pageCount (round-1 HIGH).** `BookDetailsSource` + the mapper source year/cover as always-absent (omit rows), tags via the new join query, author via #128 (nullable), pageCount host-supplied PDF-only (§details-source, §page-count). No invented rows.
4. **Fingerprint mapping (round-1 HIGH).** Display+copy the full canonical `fingerprintKey`, NOT `contentSHA256` (§fingerprint) — tested against `book.fingerprintKey`.
5. **Missing-cover + missing-file invented UI (round-1 HIGH, rule 51).** Missing-cover interactive placeholder → gated (Design-gate #1), no cover art until then. Missing-file share → validated-file flow + silent race handling, no invented error UI, no gate (§share-missing-file).
6. **EPUB host is the outlier (round-1 HIGH).** Its More/Details wiring goes through the `ComposeView` overlay + `ReaderChromeModel` StateFlow #132 introduces, not the plain scaffold call (§host-wiring). Serialize/rebase after #132's WI-7-EPUB.
7. **More-row ownership drift (round-1 HIGH).** #134 owns only Details+Share; unsupplied optional slots are OMITTED (§more-row-ownership) — tested by absence. TTS/Auto-turn/Bilingual behavior is assigned elsewhere; #134 leaves no dead rows.
8. **Popup vs sheet state (MEDIUM).** Rapid taps, popup→sheet, rotation, mutually-exclusive routes → §state-ownership: the More popup is a transient boolean (dismissed on rotation, NOT restored); opening Details **dismisses the popup first**, then sets `ReaderSheet.Details`; the Details route is keyed by the open book and survives process death via #132's Saver; only one sheet route is active at a time (#132's `ReaderChromeState` invariant).

### §more-row-ownership — who owns each More row (round-1 HIGH)
| Row | Owner | #134 behavior |
|---|---|---|
| **Book details** | **#134** | builds the `Action(DETAILS)` row + routes to `BookDetailsSheet` |
| **Share book** | **#134** | builds the `Action(SHARE)` row + `shareBookFileIntent` |
| **Read aloud (TTS)** | **#121** (TXT/MD read-aloud, VERIFIED) | #121 (or its host) supplies a `Toggle`/`Action(TTS)` row on the TXT/MD hosts where TTS exists; #134 renders it if supplied, else OMITS. #121 owns `on`/`onTap`. **#134 does not wire TTS.** |
| **Auto-turn pages** | **no current owner → a real follow-up feature** (round-1 HIGH) | There is no Auto-turn feature on Android today. #134 assigns Auto-turn to a **named follow-up** (`feature: Android reader Auto-turn pages`) and **OMITS the row** until that feature supplies it. No dead slot. |
| **Bilingual mode** | **#131** (bilingual TXT/MD UI) | #131 owns the bilingual toggle + its `disabled` "Configure AI provider first" state; it supplies the row on the hosts where bilingual exists; #134 renders if supplied, else OMITS. **#131 does not own More-menu integration or Auto-turn** — it owns the bilingual toggle STATE that a supplied row binds to. #134 does not wire bilingual. |

**Rule:** an optional slot with NO owner is a permanent gap → **OMITTED** (never a dead/disabled row). Only rows whose owning feature supplies a `MoreRow` appear. #134 ships Details+Share always; the rest appear only when their owner hands #134 a row.

### §state-ownership — popup/sheet transitions (MEDIUM)
- The More popup is a **transient boolean** (`moreMenuVisible`), NOT a `ReaderSheet` route: a popover is not process-death durable, and restoring it on recreation is surprising. On rotation the popup is **dismissed, not restored**.
- The **`Details` sheet IS a `ReaderSheet` route** (#132's state), keyed by the currently-open book; it survives process death via #132's `ReaderChromeStateSaver` (the added token round-trips; unknown tokens → `None`).
- **Opening Details from the popup dismisses the popup FIRST**, then sets `sheet = ReaderSheet.Details` (never both visible). Routes are **mutually exclusive** (#132's single-`sheet` invariant): opening Details while Notes/Toc is open replaces it.
- **Share** sets no durable state — it dismisses the popup and fires the chooser Intent.
- Rapid taps: the popup toggle + the route set are idempotent (a second "open Details" while Details is already the route is a no-op); tested.

## 7. Backward compat

- **No DB migration** — the new `collectionNamesForBook` is a `@Query` over existing `book_collection`⋈`collections` tables (verified), not a schema change. #134 adds no `@Entity`/migration.
- **No backup-contract change** — details/share read the existing `Book`; no `contracts/` edit → no ADR-0001 single-writer gate.
- **FileProvider addition is additive** — a new `<provider>` + `file_paths.xml`; no existing import/backup provider to conflict with (verified none exists). `exported=false` + per-request read-grant only.
- **#132 chrome extensions are additive/nullable-safe** — `moreMenuSlot` is a nullable slot on `ReaderTopChrome` (null for #132's own callers → back-compat); the `Details` `ReaderSheet` case + its Saver token are additive (unknown tokens already fall back to `None` in #132's Saver contract). No #132 caller breaks.
- **Annotation export explicitly deferred** — no regression; a future export feature adds the row + the details Actions entry.
- **Author line degrades to null** when #128 hasn't merged — the sheet omits the author line; #134 does not hard-depend on #128.
