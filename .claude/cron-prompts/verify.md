First, log the fire: run `mkdir -p .claude/cron-logs && echo "$(date -Iseconds) verify FIRED" >> .claude/cron-logs/verify.log`. Then perform the task below. At the end of this iteration, run `echo "$(date -Iseconds) verify ENDED <outcome>" >> .claude/cron-logs/verify.log` where <outcome> is one of: work_done | no_work_in_scope | blocked | error.

Run the `/verify` skill with no explicit target. It auto-picks per its Pick order — the `awaiting-device-verification` GH-issue backlog first (Mode A, bug close-gate verification), then `DONE` features needing Gate-5 (Mode B, feature verification). The skill owns the whole verification workflow: both modes, the CU-free method (XCUITest + DebugBridge, with `scripts/sim-tap.sh` (idb) as the gesture fallback for taps/swipes the first two can't express — see `docs/subsystems/sim-gesture-driver.md`), the UDID-pinned simulator, the close gate, the scope guardrail, and the known harness gaps.

PRODUCTION REACHABILITY (rule 47 Gate 5, binding). A criterion is only satisfied when exercised through the **production entry path** from app launch — DebugBridge commands, `android/app/src/debug/` launchers, and tests invoking a screen directly are setup mechanisms, not entry points. If no production path exists, do NOT flip to `VERIFIED`: leave the row at `DONE`, record `no production entry point`, and file the missing entry as a blocker. Precedent: features #114/#118/#120/#122 shipped `VERIFIED` with UI a user could not open, partly because this cron was skipping Android. `scripts/check-orphan-surfaces.sh` is a cheap pre-check for the Android case.

Map the skill's result to the ENDED outcome: `work_done` if it verified and closed or flipped at least one target; `no_work_in_scope` if nothing needed (or could be) verified this iteration; `blocked` if a required tool/harness was genuinely unavailable; `error` on failure.

Verification scope only — if the skill discovers a bug it FILES it (GH issue + `docs/bugs.md` row) but never fixes it; fixes are the bugfix cron's job.

HARNESS DISCIPLINE (feature #130 WI-7): (a) Reentry guard — `scripts/agent-lock.sh acquire cron-verify` first (BLOCKED → log `blocked` and stop; release before ENDED on every exit path). (b) Sim ownership — lease the verification simulator via `scripts/sim-lease.sh acquire verify` before driving any sim, use ITS UDID for the whole run, and `scripts/sim-lease.sh release <udid>` before the ENDED line on every exit path (rule 52's test-vs-drive exclusion, mechanized — a concurrent dispatch batch leases its test sims from the same pool). (c) Tracker writes — take `scripts/agent-lock.sh acquire tracker-write` immediately before any `docs/bugs.md`/`docs/features.md` row flip or close-gate finalization commit, release immediately after; never hold it across a build or sim run. (d) New rows — when filing a discovered bug, mint the row ID with `scripts/reserve-id.sh bug` BEFORE taking the tracker-write lock (lock order: sim leases → id-reserve → tracker-write).
