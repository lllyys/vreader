First, log the fire: run `mkdir -p .claude/cron-logs && echo "$(date -Iseconds) bugfix FIRED" >> .claude/cron-logs/bugfix.log`. Then perform the task below. At the end of this iteration, run `echo "$(date -Iseconds) bugfix ENDED <outcome> <mode>" >> .claude/cron-logs/bugfix.log`. `<outcome>` is EXACTLY ONE token from: work_done | no_work_in_scope | blocked | error — never modified or suffixed. `<mode>` is EXACTLY ONE token from: dispatch-mode (at least one true lane spawned — worktree + HANDOFF — via /dispatch) | dispatch-inline-mode (/dispatch ran but its N=1 degrade executed the item inline under the dispatch lock; no lane spawned) | inline-mode (kill-switch fallback — /dispatch never invoked) | no-dispatch (iteration ended before reaching /dispatch: reentry-blocked, dispatch busy, or nothing eligible). Optional free-text detail goes in a trailing parenthetical AFTER the mode token, e.g. `blocked no-dispatch (dispatch busy)`. The feature cron's self-gate counts `ENDED work_done dispatch-mode` lines, so tagging an inline degrade as dispatch-mode would falsely feed that gate — the mode distinction is load-bearing.

DISPATCH CUTOVER (feature #130 WI-7 — owner go-ahead recorded in the WI-7 PR): this cron now drives bug fixes through the parallel lane harness (`.claude/rules/55-lane-dispatch.md`), not inline /fix-issue.

1. **Reentry guard**: run `scripts/agent-lock.sh acquire cron-bugfix`. If it prints BLOCKED (exit 2), a previous bugfix iteration is still live — log `blocked no-dispatch (reentry)` and stop. Do NOT steal; the lock lib self-heals dead owners and `sweep-ghosts.sh` is the reaper. Release this lock (`scripts/agent-lock.sh release cron-bugfix`) before the ENDED line on EVERY exit path.

2. **Kill switch**: if `.claude/state/dispatch-kill` exists, the harness is disabled by the operator. FALL BACK to the legacy inline path — but the inline fix edits the same shared surfaces the harness serializes, so FIRST acquire the global lock: `scripts/agent-lock.sh acquire dispatch` (BLOCKED → log `blocked no-dispatch (dispatch busy)` and stop; release before ENDED on every exit path). Then pick ONE eligible issue (rules below) and run /fix-issue #N on it; tag the ENDED line `inline-mode`. Never delete or ignore the kill file.

3. **Pick work**: `gh issue list --label bug --state open --json number,labels,title`. Prefer severity:high, then severity:medium, then others. Skip issues whose body or comments indicate they are blocked (waiting on fixture, multi-iteration scope, harness gap, `blocked on #106 app shell`) — leave a one-line skip note in the issue and pick the next. Select up to 2 eligible, mutually independent issues (disjoint write-sets, no Deps edge between them — `scripts/deps-check.sh` decides; when in doubt, take 1). If nothing is eligible, log `no_work_in_scope no-dispatch` and stop.

4. **Dispatch**: run `/dispatch` on the selected issue(s). The skill takes the global `dispatch` lock ITSELF — never pre-acquire it here (lock order, rule 55). If /dispatch reports the dispatch lock is BLOCKED (another session is orchestrating), log `blocked no-dispatch (dispatch busy)` and stop — do NOT fall back to inline while another dispatch runs; a parallel inline fix would race the same shared surfaces the lock exists to serialize. Mode for the ENDED line: `dispatch-mode` only if at least one lane actually spawned; `dispatch-inline-mode` if the skill's N=1 degrade ran the item inline under its lock.

5. Map the result: `work_done` if at least one item's PR merged; `no_work_in_scope` if nothing eligible; `blocked` per steps 1/2/4 or genuinely missing tooling; `error` on unrecoverable failure. /dispatch owns lane cleanup — before ENDED, confirm `scripts/agent-lock.sh status` and `scripts/sim-lease.sh status` show nothing held by this session.
